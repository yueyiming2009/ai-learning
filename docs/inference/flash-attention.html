FlashAttention — IO-Aware Exact Attention

Standard attention materializes an \(N \times N\) score matrix in HBM — \(O(N^2)\) memory traffic that dominates runtime for long sequences. FlashAttention avoids writing it at all: IO-aware tiling keeps Q, K, V tiles in SRAM and accumulates the output via an online softmax recurrence, reducing HBM access from \(O(N^2)\) to \(O(Nd)\).

The attention operation is the single most memory-bandwidth-intensive part of a transformer at long context. Most of the cost is not arithmetic — it is the cost of writing and reading back the intermediate \(N \times N\) score matrix. FlashAttention's contribution is entirely algorithmic: the same exact output, computed without ever materializing that matrix, by fusing the three attention steps (QK^T, softmax, and PV) into a single kernel that operates in tiles small enough to live in SRAM.

1 · Standard attention — the HBM bottleneck

The standard scaled dot-product attention for a sequence of \(N\) tokens with head dimension \(d\) (derived forward and backward on the Self-Attention page):

Standard attention
\[ S = QK^\top \in \mathbb{R}^{N \times N}, \quad P = \text{softmax}(S / \sqrt{d}), \quad O = PV \in \mathbb{R}^{N \times d} \]
\(Q, K, V \in \mathbb{R}^{N \times d}\) live in HBM. \(S\) and \(P\) are \(N \times N\) intermediates that must also be written to and read back from HBM.

The HBM traffic breakdown for a PyTorch-style fused or unfused implementation:

Standard attention HBM reads and writes
  • Read Q, K: \(2Nd\) elements to compute \(QK^\top\).
  • Write \(S\): \(N^2\) elements to HBM (the full score matrix).
  • Read \(S\), write \(P\): \(2N^2\) elements (read scores, write normalized probabilities).
  • Read \(P\) and \(V\), write \(O\): \(N^2 + 2Nd\) elements.
  • Total HBM I/O: \(\approx 4N^2 + 4Nd\) elements — dominated by \(N^2\) for long sequences.

Concretely, for a single attention head with \(N = 8192\) and \(d = 128\):

8 ms

At \(N = 8192\), the attention operation is ~270× more memory-bound than compute-bound. Faster arithmetic changes nothing — only reducing HBM traffic matters.

2 · The tiling insight

An GPU has two distinct memory tiers used during a kernel: HBM (high bandwidth, large, ~80 GB on H100) and SRAM (on-chip scratchpad, fast, ~20 MB across all SMs). Any value in SRAM can be read/written without touching HBM. The goal: keep all intermediate values in SRAM and only write the final output \(O\) back to HBM.

The tiling strategy

Partition \(Q\) into row tiles of size \(B_r\) and \(K, V\) into column tiles of size \(B_c\), where \(B_r \times B_c + B_r \times d + B_c \times d \leq M\) (everything for one tile fits in SRAM). Process all \((i, j)\) tile pairs in order: for each Q tile \(Q_i\), load \(K_j\) and \(V_j\), compute the partial attention scores \(S_{ij} = Q_i K_j^\top\), and accumulate into the output tile \(O_i\).

The challenge: softmax over row \(i\) of \(S\) requires knowing all values in that row before normalizing. When we process tile \((i, 0)\), we have not seen tiles \((i, 1), (i, 2), \ldots\) yet. The online softmax trick resolves this.

3 · Online softmax — the key recurrence

Standard softmax requires two passes: one to find the row maximum for numerical stability, one to compute the normalized probabilities. Processing one tile at a time forces a one-pass, streaming algorithm. The recurrence maintains three running statistics per row:

Running statistics: m (max), ℓ (normalizer), O (partial output)

Initialize: \(m^{(0)} = -\infty\), \(\ell^{(0)} = 0\), \(O^{(0)} = \mathbf{0}\).

Upon processing tile \(K_j, V_j\) for query row \(i\), compute partial scores \(\tilde{S}_{ij} = Q_i K_j^\top / \sqrt{d}\). Then update:

  • \(m^{(j)} = \max(m^{(j-1)},\; \max_k \tilde{S}_{ij,k})\) — running maximum across all seen positions.
  • \(\ell^{(j)} = e^{m^{(j-1)} - m^{(j)}} \cdot \ell^{(j-1)} + \sum_k e^{\tilde{S}_{ij,k} - m^{(j)}}\) — running sum of softmax numerators, rescaled.
  • \(O^{(j)} = \frac{e^{m^{(j-1)} - m^{(j)}} \cdot \ell^{(j-1)}}{\ell^{(j)}} \cdot O^{(j-1)} + \frac{1}{\ell^{(j)}} \sum_k e^{\tilde{S}_{ij,k} - m^{(j)}} V_{j,k}\) — partial weighted sum of \(V\), updated as each tile arrives.

After the last tile \(j = N/B_c\): \(O^{(N/B_c)}\) equals the exact softmax attention output for row \(i\). No approximation — the final normalization is baked into each update step.

Key property
The online recurrence produces exactly the same result as standard softmax, computed one tile at a time, with all intermediate values (\(m, \ell, O\)) held in SRAM. The \(N \times N\) score matrix \(S\) is never written to HBM.

4 · IO complexity — the reduction

With tiling, the HBM traffic is:

HBM I/O comparison
AlgorithmHBM readsHBM writesTotal HBM I/O
Standard attention \(Q + K + V + S + P\,\,\approx 4N^2 + 4Nd\) \(S + P + O \approx 2N^2 + Nd\) \(O(N^2)\)
FlashAttention \(Q + K + V \approx 3Nd\) (tiled, each loaded \(N/B_c\) times) \(O \approx Nd\) \(O(Nd)\)

The reduction factor is \(N / d\). For typical values (\(N = 4096\), \(d = 128\)): FlashAttention uses 32× less HBM bandwidth for the attention operation. At \(N = 32768\): 256× less.

FlashAttention does not reduce FLOPs — it computes exactly the same arithmetic as standard attention. All gains come from eliminating HBM reads and writes of the \(N \times N\) intermediate. This is the definition of an IO-aware algorithm: the bottleneck is memory traffic, not compute, so the optimization target is memory traffic.

An equivalent view through the roofline: standard attention at long context is deep in the memory-bound regime (\(I \approx 1\) for the softmax + PV operations). FlashAttention shifts the kernel to the compute-bound regime by fusing everything into one pass, raising arithmetic intensity by the tile size factor.

5 · FlashAttention-2 and FlashAttention-3

FlashAttention-2 (2023)

The original FlashAttention had suboptimal parallelism: different thread blocks were assigned to different rows of \(Q\), but the inner loop over \(K, V\) tiles was sequential within each block. FA-2 makes three improvements:

  • Reduced non-matmul FLOPs: the online softmax rescaling involves element-wise multiplies and additions (not matmuls). FA-2 restructures the update to minimize these, since non-matmul ops are ~4–8× slower than Tensor Core matmuls.
  • Parallelism over the sequence dimension: instead of only parallelizing over batch and head, FA-2 also partitions \(K, V\) across thread blocks — multiple blocks cooperate on a single query tile, then merge outputs with a second pass. This is especially beneficial when the number of heads is small (e.g., MQA/GQA with few KV heads).
  • Better register utilization within a warp: threads within a warp hold a slice of the \(O\) accumulator in registers, avoiding shared-memory round-trips for the partial sum.

FA-2 achieves ~2× speedup over FA-1 on A100 for typical model shapes.

FlashAttention-3 (2024, H100-specific)

H100 introduces asynchronous execution capabilities that FA-2 does not exploit. FA-3 targets:

  • Warp specialization: different warps within an SM are assigned producer and consumer roles — producers load tiles asynchronously via the Tensor Memory Accelerator (TMA), consumers compute attention on the already-loaded tiles. Overlap of data movement and compute.
  • Ping-pong scheduling: while one warp group performs the Tensor Core matmul for tile \(j\), the other prefetches tiles for \(j+1\) — hides TMA latency completely.
  • FP8 support: FA-3 supports FP8 E4M3/E5M2 for the score computation, halving the HBM bandwidth requirement for Q, K, V and the compute cost.

FA-3 achieves 75% of the H100 FP16 theoretical peak for attention (vs. ~35% for FA-2), and up to 1.5 PFLOP/s for FP8 attention.

6 · FlashAttention-4 — when softmax becomes the bottleneck

FA-1 through FA-3 all rest on one assumption: the tensor cores are the scarce resource, and everything else can be hidden behind them. Tiling hides HBM traffic; warp specialization hides TMA latency; the online-softmax exponentials and rescaling multiplies were assumed to fit in the shadow of the matmuls. On Blackwell (B200/GB200) that assumption breaks — not because the algorithm changed, but because the hardware scaled asymmetrically: the tensor cores doubled and nothing else did.

Asymmetric scaling, H100 → B200 (per SM, per clock)

Exponentials (MUFU.EX2 on the SFU)16161×
Shared-memory bandwidth——1×

Aggregate BF16 throughput rises from ~1 to 2.25 PFLOP/s, but the special-function unit that evaluates \(2^x\) retires the same 16 values per SM per clock it did on Hopper — a 512:1 ratio between matmul and exponential throughput.

The roofline flips at \(d = 128\)

Count the work per element of the score matrix. Each score participates in two matmuls — \(QK^\top\) and \(PV\) — contributing \(2d\) FLOPs each, so \(4d\) FLOPs total; and it needs exactly one exponential. So for one \(128 \times 128\) score tile:

Cycles per 128×128 score tile
\[ t_{\rm mma} = \frac{4 \cdot 128^2 \cdot d}{\text{FLOPs/clk}}, \qquad t_{\rm exp} = \frac{128^2}{16} = 1024 \ \text{cycles} \]
The exponential cost is independent of \(d\); only the matmul cost grows with head dimension. The two are balanced when \(4d = \text{FLOPs/clk} / 16\) — i.e. \(d = 64\) on Hopper, \(d = 128\) on Blackwell.
Matmul, H100 (4096 FLOP/clk/SM) Matmul, B200 (8192 FLOP/clk/SM) Exponentials (16/clk/SM, both)

Blackwell doubled the matmul rate and moved the crossover from \(d=64\) to \(d=128\). Wherever the matmul line sits above the flat exponential line, softmax hides completely behind the tensor cores — the situation FA-2 and FA-3 were designed for, comfortably true on H100 at the standard \(d = 128\) (2048 vs. 1024 cycles). On B200 the same point lands exactly on the exponential line: 1024 cycles of matmul, 1024 cycles of exp. There is no slack left to hide softmax in, and once the rescaling multiplies and other element-wise work are added, the non-matmul path exceeds MMA time by 25–60%.

So FA-4 is not another memory-traffic optimization — the \(O(Nd)\) IO result of §4 still stands untouched. It is an attack on the two resources that Blackwell did not scale: exponentials in the forward pass and shared-memory bandwidth in the backward pass.

Software-emulated exponential

If the SFU can only produce 16 exponentials per clock, produce the rest somewhere else. FA-4 splits \(2^x\) across two independent pipes: the hardware MUFU.EX2 unit, and the ordinary FMA pipe (which is idle, since the FLOPs are all going through the tensor cores). The FMA path is a classic three-step float emulation:

  1. Cody–Waite range reduction: split \(x = n + f\) with \(n\) integer and \(f \in [0,1)\), so \(2^x = 2^n \cdot 2^f\).
  2. Degree-3 polynomial in Horner form: \(2^f \approx p_0 + f(p_1 + f(p_2 + f p_3))\) with \(p_0 = 1.0,\ p_1 \approx 0.6951,\ p_2 \approx 0.2276,\ p_3 \approx 0.0771\) — coefficients fitted with Sollya to minimize relative error on \([0,1)\). Three FFMA instructions.
  3. Bit-shift recombination: apply the \(2^n\) factor by adding \(n\) directly into the exponent field.

Accuracy: max relative error \(8.77 \times 10^{-5}\) in FP32, and after rounding to BF16 it matches the hardware instruction to within 1 ULP on 99% of inputs — well inside the noise floor of BF16 attention. FA-4 also explicitly staggers its two softmax warpgroups so they never issue to the MUFU at the same instant, removing SFU contention.

Conditional softmax rescaling

The online recurrence of §3 rescales the output accumulator by \(e^{m^{(j-1)} - m^{(j)}}\) every time the running max grows — a full \(B_r \times d\) element-wise multiply per tile, all of it non-matmul work on the critical path. FA-4 observes that \(m\) does not have to be the true running max; it only has to keep \(e^{\tilde S - m}\) inside float range. So it leaves \(m\) alone unless the new tile's max exceeds it by more than a threshold \(\tau\):

Conditional rescale
\[ \text{if } m_j - m_{j-1} \leq \tau: \ \text{keep } m_{j-1}, \text{ skip the accumulator rescale} \]
With \(\tau = \log_2 256 = 8\), the un-normalized numerators may run up to 256× above unity — harmless in FP32 — and the final division by \(\ell\) restores the exact answer. Most tiles now skip the rescale entirely.

A dedicated correction warpgroup handles the rescales that do happen, off the critical path of the softmax and MMA warpgroups.

Pipeline redesign for fully asynchronous tensor cores

Blackwell's fifth-generation tcgen05.mma instructions are issued by a single thread and write their accumulator into Tensor Memory (TMEM) — 256 KB per SM of scratchpad wired directly into the tensor cores, rather than into registers. The largest single-CTA tile grows to \(128 \times 256 \times 16\), roughly double Hopper's WGMMA. (The full sm_100 programming model — TMEM allocation, the single-thread MMA warp, CTA pairs, block-scaled MMA — is covered on the Blackwell kernel model page.) Two consequences FA-4 exploits:

  • Deeper warp specialization without register spilling. Accumulators live in TMEM, freeing the register budget that on Hopper capped how many roles a kernel could run. FA-4 carries two query tiles per CTA in a ping-pong: while one tile's matmuls occupy the tensor cores, the other tile's softmax runs on the SFU and FMA pipes.
  • 2-CTA MMA mode. A pair of CTAs issues one UMMA cooperatively over shared TMEM, reaching a \(256 \times 256 \times 16\) tile and halving the shared-memory traffic for the shared operand — the decisive win in the backward pass.

The backward pass — a shared-memory problem

Backward attention runs five matmuls (\(dV, dP, dS, dQ, dK\)) plus element-wise work, and on B200 it is bound by shared-memory bandwidth rather than by the tensor cores. FA-4 partitions the output accumulators across a CTA pair (\(M = 256,\ N = K = 128\)), halving operand-B shared-memory traffic, and resolves the resulting reduction-axis mismatch by exchanging \(dS\) through distributed shared memory so each CTA ends up owning \(M/2\) rows with the full \(2N\) reduction dimension. A side benefit: the global atomic adds for \(dQ\) are halved. A deterministic mode, which serializes those \(dQ\) reductions with semaphore-style locking, still runs at 85–90% of the non-deterministic throughput.

Scheduling and implementation

Causal masking and variable-length batches leave work tiles wildly unequal, so FA-4 adds grid swizzling (reverse \(m\)-block traversal within a batch-head section), longest-processing-time-first scheduling to shrink the tail, and an optional preprocessing kernel that sorts batches by per-tile cost. The whole kernel is written in CuTe-DSL, CUTLASS's Python kernel DSL that lowers to PTX — which compiles 20–30× faster than the equivalent C++ template metaprogramming, the practical reason a kernel this specialized is maintainable at all.

7 · Inference vs. training — where FlashAttention matters most

FlashAttention applies to both training and inference, but its relative impact differs between the two phases:

Impact by phase
PhaseSequence shapeS matrix shapeFA benefit
Training / Prefill \([B, T_p, d]\) — all prompt tokens in parallel \(T_p \times T_p\) — can be large Very large — \(T_p^2\) HBM traffic eliminated
Decode (new token) \([B, 1, d]\) — one token per step \(1 \times T\) — only one row Moderate — no \(N^2\), but KV cache I/O still significant

During decode, the new query attends over \(T\) cached keys — producing a \(1 \times T\) score vector, not an \(N \times N\) matrix. There is no \(N^2\) blowup. However, the attention kernel still reads \(T \times h_{\rm kv} \times d\) bytes of KV cache from HBM, which grows with context length and contributes to the TPOT bandwidth cost. FA-3's TMA prefetching and FP8 support help here.

For training: FlashAttention is essentially mandatory at any non-trivial sequence length. Prefill for long-context inference (RAG, document QA, long code) benefits equally — a 32K prefill without FlashAttention would need ~16 GB of HBM just for the score matrices across 32 layers and 32 heads.

FlashAttention is also critical for the backward pass during training: it uses a recomputation strategy (recompute the softmax from \(Q, K\) during backward rather than storing \(P\)) that reduces the activation memory from \(O(N^2)\) to \(O(N)\). This is independent of the IO benefit. The combination is why FlashAttention is now standard in all serious training frameworks.

8 · Summary

The problem

Standard attention writes the \(N \times N\) score matrix to HBM twice (write S, read it for softmax, write P, read P for PV). At N=8K, this is ~4 GB per head per layer.

The insight

Process Q, K, V in SRAM tiles. Accumulate the output using an online softmax recurrence that maintains running max, sum, and partial output — exact result, no HBM writes for S or P.

IO reduction

HBM I/O drops from \(O(N^2)\) to \(O(Nd)\). Reduction factor = \(N/d\): 32× at N=4K, d=128; 256× at N=32K.

Exact output

No approximation — FlashAttention computes mathematically identical results to standard attention. Same FLOPs; all wins are from reduced memory traffic.

FA-2 / FA-3

FA-2: better warp-level parallelism (~2× vs FA-1 on A100). FA-3: H100 warp specialization + TMA overlap + FP8 — reaches 75% of H100 theoretical attention throughput.

FA-4

Blackwell doubled tensor-core throughput but not the exp unit or SMEM bandwidth, so softmax became the bottleneck. FA-4 emulates \(2^x\) on the idle FMA pipe, rescales only when the max drifts past \(\tau\), and uses TMEM + 2-CTA MMA — 1613 TFLOP/s, 71% of peak.

Inference impact

Critical for prefill (eliminates \(T_p^2\) HBM traffic). Moderate for decode (no N² matrix, but helps with KV cache read efficiency at long context).
