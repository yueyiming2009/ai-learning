Cross Entropy

Forward and backward pass for the softmax + cross-entropy loss used in language model next-token prediction and multi-class classification.

Notation

SymbolDescription
\(\mathbf{z} \in \mathbb{R}^V\)Logits (raw pre-softmax scores); \(V\) is the vocabulary or class count
\(\mathbf{p} \in \mathbb{R}^V\)Softmax probabilities: \(p_i = e^{z_i} / \sum_j e^{z_j}\)
\(S = \sum_j e^{z_j}\)Partition function (normalization denominator)
\(k\)Index of the true class
\(\mathbf{y} \in \{0,1\}^V\)One-hot target: \(y_i = \mathbf{1}[i = k]\)
\(L\)Scalar cross-entropy loss
\(d\mathbf{z}\)Gradient \(\partial L / \partial \mathbf{z}\)

1. Forward Pass

Step 1 — Softmax

Convert logits to a probability distribution over all \(V\) classes:

\[ p_i = \frac{e^{z_i}}{S}, \qquad S = \sum_{j=1}^{V} e^{z_j} \]

By construction \(p_i > 0\) and \(\sum_i p_i = 1\), so \(\mathbf{p}\) is a valid probability distribution.

The binary case — softmax is the sigmoid

When there are only two classes \((V = 2)\), softmax collapses to the logistic sigmoid applied to the difference of the two logits. Take the probability of class 1 and divide top and bottom by \(e^{z_1}\):

\[ p_1 = \frac{e^{z_1}}{e^{z_1} + e^{z_2}} = \frac{1}{1 + e^{z_2 - z_1}} = \frac{1}{1 + e^{-(z_1 - z_2)}} = \sigma(z_1 - z_2) \]

The two separate logits cancel, leaving only their gap \(z_1 - z_2\). That is expected: with two classes the probabilities must sum to 1, so there is just one free quantity — how much class 1 outscores class 2 — and \(\sigma\) is the natural function of it. Sanity checks: \(z_1 = z_2 \Rightarrow \sigma(0) = \tfrac12\) (a toss-up); \(z_1 \gg z_2 \Rightarrow \sigma \to 1\).

This is why binary logistic regression is the two-class special case of softmax classification — and why multi-class cross entropy generalizes the binary log-loss. The same identity turns the two-way reward comparison in DPO / RLHF into \(\sigma\big(r(x,y_w) - r(x,y_l)\big)\).

Step 2 — Cross-entropy loss

Measure the log-loss against the one-hot target:

\[ L = -\sum_{i=1}^{V} y_i \log p_i = -\log p_k \]

Because only the true-class term survives the sum, the loss reduces to the negative log-probability assigned to the correct class.

This is exactly the negative log-likelihood of the categorical distribution — cross entropy is NLL with a softmax output. See the NLL page for the general maximum-likelihood principle that also yields MSE, the LM token loss, and the DPO loss.

Expanding \(-\log p_k\) using the definition of softmax:

\[ L = -\log p_k = -\log \frac{e^{z_k}}{S} = -\log e^{z_k} + \log S = -z_k + \log \sum_{j=1}^{V} e^{z_j} \]
Forward pass
\[ L = -z_k + \log \sum_{j=1}^{V} e^{z_j} \]
This form avoids any division and gives a clear interpretation: the loss equals how much the log-partition function \(\log S\) exceeds the true-class logit \(z_k\). A perfect model pushes \(z_k \to \infty\) relative to all others, driving \(L \to 0\). The same \(z_k - \log S\), read at the token the model sampled rather than the target, is the per-token \(\log\pi\) of RL — see log-probabilities from logits.

2. Numerical Stability

Computing \(e^{z_i}\) directly overflows for large logits. The standard fix subtracts the maximum logit before exponentiating. Let \(m = \max_j z_j\):

\[ p_i = \frac{e^{z_i - m}}{\sum_j e^{z_j - m}} \]

This is mathematically identical to the original (the \(e^{-m}\) factors cancel), but the largest exponent is now \(0\), keeping all values in \((0,\, 1]\).

PyTorch's F.cross_entropy and JAX's optax.softmax_cross_entropy both apply this shift internally. You rarely need to implement it by hand, but understanding it is important for writing numerically stable custom kernels.

3. Backward Pass

We want \(\partial L / \partial z_i\) for each logit. The derivation goes through the Jacobian of softmax.

Step A — Softmax Jacobian

Apply the quotient rule to \(p_k = e^{z_k}/S\), where \(S = \sum_j e^{z_j}\).

Case \(i = k\) — both numerator and \(S\) depend on \(z_k\), so the quotient rule gives \((e^{z_k} \cdot S - e^{z_k} \cdot e^{z_k})/S^2\):

\[ \begin{aligned} \frac{\partial p_k}{\partial z_k} &= \frac{e^{z_k} \cdot S - e^{z_k} \cdot e^{z_k}}{S^2} \\[8pt] &= \frac{e^{z_k}}{S} - \left(\frac{e^{z_k}}{S}\right)^{\!2} = p_k - p_k^2 = p_k(1 - p_k) \end{aligned} \]

Case \(i \ne k\) — the numerator \(e^{z_k}\) does not depend on \(z_i\), so its derivative is zero:

\[ \frac{\partial p_k}{\partial z_i} = \frac{0 \cdot S - e^{z_k} \cdot \dfrac{\partial S}{\partial z_i}}{S^2} = \frac{-e^{z_k} \cdot e^{z_i}}{S^2} = -\frac{e^{z_k}}{S} \cdot \frac{e^{z_i}}{S} = -p_k\, p_i \]
Step B — Chain rule through the log

Since \(L = -\log p_k\), the chain rule gives \(\partial L/\partial z_i = (-1/p_k)\cdot(\partial p_k/\partial z_i)\).

Case \(i = k\) — substitute the result from Step A:

\[ \frac{\partial L}{\partial z_k} = -\frac{1}{p_k} \cdot p_k(1-p_k) = -(1-p_k) = p_k - 1 \]

Case \(i \ne k\) — the two negatives cancel:

\[ \frac{\partial L}{\partial z_i} = -\frac{1}{p_k} \cdot (-p_k\, p_i) = p_i \]

Combining both cases using the one-hot label \(y_i\):

Key result — gradient of the combined loss
\[ \frac{\partial L}{\partial z_i} = p_i - y_i \] \[ d\mathbf{z} = \mathbf{p} - \mathbf{y} \]

This remarkably clean formula is one of the most important in deep learning. The gradient at each logit is simply how much probability the model assigned minus what it should have assigned. No intermediate Jacobian matrices or division by \(p_k\) remain in the final expression.

This simplicity is not a coincidence. Cross entropy is the natural loss for softmax because they are conjugate in the exponential family — the log in the loss exactly cancels the exp in the softmax, leaving a linear residual.

In code, both passes collapse to a line each — the stable forward is a single library call, and the gradient is just the softmax with \(1\) subtracted at the true class:

import torch.nn.functional as F

loss = F.cross_entropy(logits, targets)   # stable -z_k + logsumexp(z), averaged over N

# gradient dL/dz is the p - y residual:
grad = F.softmax(logits, dim=-1)          # p
grad[range(N), targets] -= 1              # subtract y (one-hot) at the true class
grad /= N                                 # average, matching the loss

4. Batch Formulation

In practice, loss is averaged over a mini-batch of \(N\) examples. Let \(Z \in \mathbb{R}^{N \times V}\) be the logit matrix and \(k_1, \ldots, k_N\) the true class indices.

\[ L = -\frac{1}{N}\sum_{n=1}^{N} \log p_{n,k_n} \]

Softmax is applied row-wise to produce \(P \in \mathbb{R}^{N \times V}\). The gradient follows immediately:

\[ \frac{\partial L}{\partial Z} = \frac{1}{N}(P - Y) \]

where \(Y \in \mathbb{R}^{N \times V}\) is the batch of one-hot labels. The \(1/N\) factor comes from averaging the loss — it simply scales every gradient row uniformly.

In language modelling the sequence dimension is typically folded into the batch, so the effective \(N\) is \(\text{batch} \times \text{sequence length}\). The same formula applies without modification.

5. Reference Implementation

Everything above collapses into a few lines of NumPy — no framework, so each step maps directly onto the math. The forward uses the stable \(-z_k + \log\sum_j e^{z_j}\) form from §1–§2, and the backward is the \((P - Y)/N\) residual from §3–§4. Shapes: Z is \((N, V)\) logits and k is the length-\(N\) vector of true-class indices.

import numpy as np

def softmax(Z):
    # subtract row-max before exp — §2: identical result, no overflow
    Z = Z - Z.max(axis=1, keepdims=True)
    E = np.exp(Z)
    return E / E.sum(axis=1, keepdims=True)          # P, shape (N, V)

def cross_entropy(Z, k):
    # forward — §1: L = mean(-z_k + logSumExp(z)), computed the stable way
    N = Z.shape[0]
    m = Z.max(axis=1, keepdims=True)                 # stability shift
    logsumexp = m[:, 0] + np.log(np.exp(Z - m).sum(axis=1))
    z_k = Z[np.arange(N), k]                         # true-class logits
    return np.mean(logsumexp - z_k)                  # scalar loss

def cross_entropy_grad(Z, k):
    # backward — §3–§4: dZ = (P - Y) / N
    N = Z.shape[0]
    P = softmax(Z)
    P[np.arange(N), k] -= 1                          # subtract one-hot Y at true class
    return P / N                                     # shape (N, V)
The gradient needs no autograd and no Jacobian: run softmax, subtract 1 at each true class, divide by \(N\). A finite-difference check against cross_entropy agrees to ~1e-10 — the analytic \(\mathbf{p} - \mathbf{y}\) is exact, not an approximation. (PyTorch's one-line equivalent, F.cross_entropy, is in §3.)

6. Practical Extensions

Production implementations — PyTorch's F.cross_entropy, JAX / T5X, and fused kernels like Liger — layer three options on top of the textbook loss above. Each is a small, local modification of the same forward and backward machinery.

Class weighting — weight

A per-class vector \(\mathbf{w} \in \mathbb{R}^V\) rescales each example's loss by the weight of its own true class \(k_n\). Rare classes can be up-weighted and frequent ones down-weighted to counter class imbalance:

\[ L_n = -\,w_{k_n} \log p_{n,k_n} \]

The subtlety is the mean reduction: PyTorch does not divide by the example count \(N\). It divides by the sum of the applied weights, giving a weighted mean:

\[ L = \frac{\sum_{n} w_{k_n}\,\big(-\log p_{n,k_n}\big)}{\sum_{n} w_{k_n}} \]

The gradient inherits the same per-row scale — row \(n\) of the \((P - Y)\) residual is multiplied by \(w_{k_n}\), then normalized by \(\sum_m w_{k_m}\) in place of \(N\):

\[ \frac{\partial L}{\partial \mathbf{z}_n} = \frac{w_{k_n}}{\sum_m w_{k_m}}\,(\mathbf{p}_n - \mathbf{y}_n) \]
Distinct from ignore_index, which removes a position entirely — it counts toward neither the numerator nor the denominator. Weighting keeps the position but rescales how much it pulls on the gradient.

Label smoothing

Instead of the hard one-hot target \(\mathbf{y}\), regress against a softened target that keeps a little probability mass on every class. With smoothing strength \(\varepsilon\), the target is a blend of the one-hot label and the uniform distribution over all \(V\) classes:

\[ q_i = (1-\varepsilon)\,y_i + \frac{\varepsilon}{V} \quad\Longrightarrow\quad q_k = (1-\varepsilon) + \tfrac{\varepsilon}{V},\;\; q_{i\neq k} = \tfrac{\varepsilon}{V} \]

The loss then splits into the ordinary hard-label term plus a uniform term that spreads probability toward all classes:

\[ L = -\sum_i q_i \log p_i = (1-\varepsilon)\underbrace{(-\log p_k)}_{\text{hard}} + \varepsilon\underbrace{\Big(\tfrac1V\textstyle\sum_i -\log p_i\Big)}_{\text{uniform}} \]

The payoff: the gradient keeps the exact same \(\mathbf{p} - (\text{target})\) shape from §3 — just against the soft target \(\mathbf{q}\) instead of the one-hot \(\mathbf{y}\):

Gradient with label smoothing
\[ d\mathbf{z} = \mathbf{p} - \mathbf{q}, \qquad dz_i = p_i - \tfrac{\varepsilon}{V} - (1-\varepsilon)\,y_i \]

Because \(q_k < 1\), the model can no longer minimize the loss by driving \(z_k \to \infty\); it settles for a finite margin. This regularizes overconfidence, improves calibration, and is standard in Transformer and Inception training (\(\varepsilon = 0.1\) is typical).

This is the label_smoothing argument of PyTorch and Liger, and it composes with everything else here: weight rescales both the hard and uniform terms per class, and the \(\mathbf{p} - \mathbf{q}\) residual still picks up the z-loss and reduction adjustments below.

Z-loss — logit-scale regularization

Cross entropy depends only on logit differences (§1: \(L = -z_k + \log S\)), so nothing stops the absolute scale of the logits from drifting arbitrarily large during training. Z-loss adds a penalty on the log-partition function \(\log S\) to pin it near zero:

\[ L_{\text{total}} = \underbrace{-z_k + \log S}_{\text{cross entropy}} \;+\; \lambda\,(\log S)^2 \]

with a small coefficient \(\lambda\) (T5X and PaLM use \(10^{-4}\)). Driving \(\log S \to 0\) means \(S \to 1\), which keeps the exponentials in a safe range for bf16 / fp16 and damps the loss spikes that runaway logit inflation causes in large-model pretraining.

It is nearly free because its gradient reuses the softmax. Since \(\partial(\log S)/\partial z_i = e^{z_i}/S = p_i\), the extra term is just the probability vector scaled by \(2\lambda \log S\):

Gradient with z-loss
\[ d\mathbf{z} = (\mathbf{p} - \mathbf{y}) \;+\; 2\lambda\,(\log S)\,\mathbf{p} \]
Both \(\log S\) (the logsumexp from §2) and \(\mathbf{p}\) are already computed for the loss, so a fused kernel folds z-loss in with no extra passes over the logits. In pretraining this is a standard stability knob; in Liger it is the lse_square_scale argument.

Logit soft-capping — softcap

Where z-loss softly discourages large logits with a penalty, soft-capping hard-bounds them with a smooth squashing transform applied to every logit before the softmax. With threshold \(\tau\):

\[ \tilde{z}_i = \tau \tanh\!\big(z_i / \tau\big) \;\in\; (-\tau,\, \tau) \]

Near zero \(\tanh\) is almost the identity, so small logits pass through untouched; only large ones saturate toward \(\pm\tau\). No single logit can run away, which stabilizes training — this is the final-logit and attention-logit cap used in Gemma 2 and Grok.

Because the cap sits in front of the softmax, the backward pass just prepends one chain-rule factor. Using \(\frac{d}{dz}\big[\tau\tanh(z/\tau)\big] = 1 - \tanh^2(z/\tau)\), every gradient computed on the capped logits \(\tilde{\mathbf{z}}\) is rescaled by it:

Gradient through soft-capping
\[ \frac{\partial L}{\partial z_i} = \underbrace{\big(\tilde p_i - q_i\big)}_{\text{residual on }\tilde{\mathbf z}} \cdot \Big(1 - \tanh^2(z_i/\tau)\Big) \]

The factor \(1 - \tanh^2 \to 0\) exactly where a logit saturates, so soft-capping also damps the gradient on the most extreme logits — a self-limiting effect the raw loss lacks.

softcap is not an F.cross_entropy argument — it is a model-architecture choice applied to the logits beforehand (\(\tau \approx 30\) for Gemma 2's final logits). Liger fuses it into the same kernel: it caps inside the online-softmax pass and applies the \(1-\tanh^2\) factor during the gradient write-back, so no separate tanh pass over the \((N, V)\) logits is needed.

Token accuracy

A diagnostic metric — the fraction of positions whose top-1 prediction matches the target, excluding masked positions:

\[ \text{acc} = \frac{\#\{\,n : \arg\max_i z_{n,i} = k_n\,\}}{\#\{\,n : k_n \neq \texttt{ignore\_index}\,\}} \]

Unlike the loss, it depends only on the argmax, not the full distribution: the model can drive the loss down by growing more confident on already-correct tokens with accuracy unchanged, and vice versa. It is non-differentiable (a hard \(=\) test), so it is only ever a reported side metric, never an optimization target.

Under teacher forcing this is next-token accuracy given the ground-truth prefix, so it reads far higher than free-running generation quality — a training monitor, not an eval. A fused kernel returns it almost free: it already reduces over the vocabulary to find the max logit for the §2 shift, so tracking which index attained that max and comparing it to \(k_n\) costs one comparison and saves a separate pass over the \((N, V)\) logits.

Putting it together — in code

Class weighting, label smoothing, and ignore_index are native arguments of F.cross_entropy. Soft-capping, z-loss, and token accuracy are not — soft-capping is applied to the logits beforehand, while z-loss and token accuracy ride alongside, reusing the logsumexp and argmax the loss already needs:

import torch, torch.nn.functional as F

# --- softcap (model-specific, e.g. Gemma-2): bound logits before the loss ---
logits = softcap * torch.tanh(logits / softcap)   # τ·tanh(z/τ) ∈ (−τ, τ)

# --- native F.cross_entropy options ---
loss = F.cross_entropy(
    logits, targets,          # (N, V) logits, (N,) target class indices
    weight=class_weights,     # (V,) per-class rescale — mean ÷ Σ weights, not N
    label_smoothing=0.1,      # ε: soft target (1-ε)·one-hot + ε/V uniform
    ignore_index=-100,        # positions dropped from loss AND denominator
    reduction="mean",
)

# --- z-loss + token accuracy: computed alongside (not native args) ---
logZ   = torch.logsumexp(logits, dim=-1)          # log S per row (§2)
z_loss = lse_square_scale * (logZ ** 2).mean()    # λ·(log S)²
loss   = loss + z_loss                            # fold into the objective

mask      = targets != -100                       # non-ignored positions
correct   = (logits.argmax(dim=-1) == targets) & mask
token_acc = correct.sum() / mask.sum()            # diagnostic only, no grad
A fused kernel (Liger's liger_cross_entropy) does all of this in one pass over the \((N, V)\) logits — softcap, weight, label_smoothing, and lse_square_scale are folded into the same \(d\mathbf{z}\) write-back derived above, instead of the several separate passes this reference code makes.

\(L = -\log p_k = -z_k + \log S\)

Subtract \(m = \max_j z_j\) before exp

Log and exp cancel; cross entropy is the natural loss for softmax
