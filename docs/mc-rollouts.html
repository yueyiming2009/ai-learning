Monte Carlo Rollouts

Run the policy to the end of an episode, observe the actual return, and use it as an estimate. Unbiased — but variance is the price, and every LLM RL method is a response to that problem.

🎓
David Silver's Reinforcement Learning Course (DeepMind/UCL)

Covers MC prediction and REINFORCE from Lectures 4–5 (model-free prediction and model-free control).

The value functions page showed that \(V^\pi(s)\) exists and satisfies the Bellman equations — but computing it exactly requires summing over all states and transitions, which is intractable for any real problem. Monte Carlo is the simplest approximation strategy: skip the math, run the policy, and use whatever actually happens as your estimate.

1. What is a Rollout?

A rollout is one complete run of the policy through an episode — from an initial state to termination. At each step the policy samples an action, the environment returns a reward and a new state, and the process repeats until the episode ends:

Algorithm — Rollout generation
Require: policy π, environment env

s ← s₀,  τ ← []
for t = 0, 1, 2, … do
    aₜ       ← π(sₜ)               ▷ sample action from policy
    rₜ, sₜ₊₁ ← env.step(sₜ, aₜ)   ▷ observe reward and next state
    τ ← τ ∥ (sₜ, aₜ, rₜ)
    if sₜ₊₁ is terminal then break end if
    sₜ ← sₜ₊₁
end for
return τ = (s₀, a₀, r₀, s₁, a₁, r₁, …, sT)

Once the rollout is complete, compute returns by walking backwards through the trajectory — this handles the telescoping sum in a single pass:

Algorithm — Computing returns (backward pass)
Require: trajectory τ = (s₀,a₀,r₀,…,sT), discount factor γ

G ← 0
for t = T−1 downto 0 do
    G  ← rₜ + γ · G   ▷ Gₜ = rₜ + γ Gₜ₊₁
    Gₜ ← G
end for
return (G₀, G₁, …, G_{T−1})

The result is a list of \((s_t, a_t, G_t)\) tuples — one per step. These are the raw material for both value estimation and policy gradient updates.

2. Monte Carlo Value Estimation

The definition \(V^\pi(s) = \mathbb{E}_\pi[G_t \mid s_t = s]\) immediately suggests an estimator: collect many rollouts, record \(G_t\) every time you visit state \(s\), and average them. The law of large numbers guarantees convergence.

Monte Carlo estimate of V
\[ \hat V^\pi(s) = \frac{1}{N(s)} \sum_{i=1}^{N(s)} G_t^{(i)} \]

where the sum is over all visits to state \(s\) across episodes, and \(G_t^{(i)}\) is the return observed on visit \(i\).

There are two variants depending on how you count visits within a single episode:

VariantWhich visits countTrade-off
First-visit MC Only the first time \(s\) is visited in each episode Unbiased; simpler convergence proof
Every-visit MC Every time \(s\) is visited in each episode More data per episode; also converges, but with slightly correlated samples
In LLM RL the context grows monotonically — each state (prompt + tokens so far) is visited at most once per episode, so first-visit and every-visit MC are identical. The distinction matters in environments where the agent can return to previously-visited states (mazes, board games).

3. Why Monte Carlo is Unbiased

The estimate \(\hat V^\pi(s)\) is unbiased: its expected value equals the true \(V^\pi(s)\). The proof is a direct appeal to the definition:

\[ \mathbb{E}\!\left[ G_t \mid s_t = s \right] = \mathbb{E}_\pi\!\left[ \sum_{l \ge 0} \gamma^l r_{t+l} \;\middle|\; s_t = s \right] = V^\pi(s) \]

Because \(G_t\) is computed from real rewards collected by running the actual policy — no model assumptions, no bootstrapped estimates, no approximation errors — averaging it is a consistent estimator of the true expectation. This is the key property that distinguishes MC from TD methods.

What "unbiased" means in practice

If you ran infinitely many rollouts from state \(s\) and averaged the returns, you would get exactly \(V^\pi(s)\). With a finite number of rollouts you get a noisy estimate — but the noise averages to zero. The systematic error ("bias") is zero; only the random error ("variance") remains.

4. The Variance Problem

Unbiasedness is great in theory. In practice, Monte Carlo returns can have enormous variance — especially in long episodes with sparse rewards.

Consider a token-by-token LLM response of length \(T\). The reward is entirely sparse: \(r_t = 0\) for all \(t < T\), and \(r_T\) is the reward model score at the final token. Then for every step \(t\):

\[ G_t = \gamma^{T-t} r_T \]

All tokens in the same response get the same (discounted) return — the full episode reward, just differently scaled. If two responses to the same prompt get scores of \(+1\) and \(-1\), every token in the first episode gets \(G_t \approx +1\) and every token in the second gets \(G_t \approx -1\). The return swings between \(+1\) and \(-1\) across episodes not because of what individual tokens did, but because of the global quality of the response.

Where the variance comes from

For a non-sparse setting, \(G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots\). Each \(r_{t+l}\) is a random variable. The variance of a sum of \(T\) random variables grows roughly linearly in \(T\) (assuming some independence). Long episodes accumulate variance from every future step — the further from the end, the more noisy the estimate.

TD learning's core idea is to stop the sum early and substitute a learned value estimate \(V(s')\) for the tail, trading a small amount of bias for a large reduction in variance.

High variance means the gradient estimator is noisy: the policy receives contradictory signals across batches and converges slowly. Reducing variance — through baselines, advantage normalisation, or bootstrapping — is the central engineering problem in practical RL.

5. REINFORCE — The MC Policy Gradient

The policy gradient theorem (derived in full on the Policy Gradient page — log-derivative trick, trajectory factorisation, and why only the policy terms survive) gives the exact gradient of the expected return with respect to policy parameters:

\[ \nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\!\left[ \sum_t G_t \, \nabla_\theta \log \pi_\theta(a_t \mid s_t) \right] \]

This is an expectation over trajectories — so we can estimate it by Monte Carlo: sample a trajectory, compute \(G_t\) at each step, and treat the sum as a gradient estimate. That is exactly REINFORCE (Williams, 1992):

Algorithm — REINFORCE (Williams, 1992)
Require: policy π_θ, learning rate α, discount factor γ

repeat
    τ ← GenerateRollout(π_θ)          ▷ sample one episode
    (G₀, …, G_{T−1}) ← BackwardPass(τ)
    for t = 0 to T−1 do
        θ ← θ + α · Gₜ · ∇_θ log π_θ(aₜ | sₜ)
    end for
until convergence

The update rule has a clean intuition: if \(G_t\) was high (the episode went well from step \(t\)), increase the log-probability of the action taken — make it more likely next time. If \(G_t\) was low, decrease it. The magnitude of the push is proportional to how good the return was.

6. Adding a Baseline

REINFORCE works but is notoriously high-variance. The fix is to subtract a baseline \(b(s_t)\) from the return. The baseline can be any function of the state — it does not change the expected gradient (the bias remains zero) but can dramatically reduce variance:

\[ \nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\!\left[ \sum_t \big(G_t - b(s_t)\big) \, \nabla_\theta \log \pi_\theta(a_t \mid s_t) \right] \]

Why is subtracting a baseline safe? Because \(\mathbb{E}_{a \sim \pi}[b(s) \nabla_\theta \log \pi(a|s)] = b(s) \mathbb{E}_{a \sim \pi}[\nabla_\theta \log \pi(a|s)] = 0\) — the expected gradient of log-probabilities under their own distribution is always zero.

The optimal baseline is the value function

Setting \(b(s_t) = V^\pi(s_t)\) gives:

\[ G_t - V^\pi(s_t) \approx A^\pi(s_t, a_t) \]

This is the advantage function. It strips out the "this state was just generically good/bad" component of \(G_t\), leaving only the signal about the specific action taken. The update now pushes up actions that were better than average and pushes down actions that were worse — a much cleaner signal than raw return.

The practical problem: \(V^\pi(s_t)\) is unknown and must itself be estimated (by the critic in PPO, or by group averaging in GRPO).

7. Monte Carlo in LLM RL

Every LLM RL method is built on MC rollouts at its core — the model generates a complete response (one rollout), a reward is computed at the end, and the policy is updated from the result.

MethodHow it uses MC rolloutsHow it handles variance
REINFORCE One rollout per prompt; raw \(G_t\) as gradient signal Optional baseline; typically high variance
PPO Batch of rollouts; \(G_t\) used to train critic and compute advantages via GAE Learned critic \(V_\psi\) provides baseline; GAE trades off MC vs TD
GRPO \(G\) rollouts per prompt; each rollout's terminal reward is the return Group mean reward as implicit \(V(s_0)\) baseline; no critic needed

GRPO as group-average MC

GRPO samples \(G\) complete responses to the same prompt and computes each response's reward \(r^{(i)}\). The group mean \(\bar r = \frac{1}{G}\sum_i r^{(i)}\) is a Monte Carlo estimate of \(V^\pi(s_0)\) — the expected return from the starting state under the current policy. Subtracting it gives a zero-centred advantage:

\[ \hat A^{(i)} = \frac{r^{(i)} - \bar r}{\sigma_r} \]

This is pure MC: no critic, no bootstrapping, no Bellman equations. The cost is that you need \(G\) rollouts per prompt instead of one, and you only get a baseline for the start of the episode — per-token advantages are approximated by assigning the same \(\hat A^{(i)}\) to every token in response \(i\). See the GRPO page for the full derivation.

The credit assignment problem

In LLM RL with sparse terminal rewards, every token in a response gets the same return \(G_t \approx r_T\). The model has no way to know which specific tokens made the response good or bad — a grammatically clunky token early in a brilliant response and a crucial insight token both receive the same gradient signal. This is the credit assignment problem, and it is why:

  • A learned critic \(V_\psi(s_t)\) that predicts token-level value is worth the cost — it lets the advantage vary across tokens within a response.
  • Process reward models (PRMs) — which score intermediate steps rather than just the final output — are an active area of research.
  • Dense per-token KL penalties in RLHF act as a partial substitute for per-token reward signal.
