Alignment

DeepSeek-R1

A fully disclosed recipe for training a reasoning model: start from a base LLM, apply GRPO with verifiable rewards, and get spontaneous chain-of-thought — no human-annotated reasoning traces required.

OpenAI's o1 demonstrated that scaling test-time compute produces qualitatively better reasoning, but its training recipe remained opaque. DeepSeek-R1 (January 2025) disclosed the full procedure: what data goes in, what rewards are used, how the pipeline is staged, and how reasoning ability transfers to smaller models via distillation. This page traces that recipe step by step and connects it to the RL foundations built across this series.

1. Two Models, One Paper

The paper introduces two distinct models with the same name family:

R1-Zero

RL from scratch

  • Base model → GRPO with verifiable rewards
  • No supervised CoT data at all
  • Reasoning emerges spontaneously
  • But: language mixing, poor formatting, hard to deploy

The scientific result: proof that chain-of-thought is a latent capability that RL can unlock without demonstrations.

R1

Full 4-stage pipeline

  • Cold-start SFT → Reasoning RL → Rejection-sampling SFT → Final RL
  • Small amount of CoT bootstrap data to fix format/language
  • Stronger performance, deployable output
  • Distilled into smaller models (7B–70B)

The engineering result: a production-quality reasoning model with a fully reproducible procedure.

2. R1-Zero — What Happens When You Just Apply GRPO

R1-Zero starts from DeepSeek-V3-Base (a pretrained LLM with no instruction fine-tuning) and applies GRPO with two simple verifiable reward signals — accuracy and format — and nothing else. No human-labelled reasoning traces, no reward model, no PRM.

The prompt template

Every training prompt is wrapped in a fixed system message instructing the model to reason step-by-step inside <think>…</think> tags before giving its final answer inside <answer>…</answer> tags. The model is not given examples of how to use these tags — it must learn their purpose from the reward signal alone.

The reward function is purely outcome-based. For math: is the final boxed answer correct? For code: do the unit tests pass? No credit for any particular reasoning style, no bonus for longer thinking, no penalty for repetition. The model receives a binary \(\{0, 1\}\) signal per response.

Despite this sparse feedback, training converges on measurably better reasoning — and produces behaviors that were never in the training objective.

3. Emergent Behaviors

The most striking finding of R1-Zero is that complex reasoning behaviors emerge from a simple binary correctness signal, without being explicitly trained:

📈
Thinking length scales

Average response length grows monotonically across training. The model spontaneously learns to think longer on hard problems.

🔄
Self-correction

The model learns to backtrack and revise reasoning mid-response when it detects an inconsistency — without being told to.

✅
Self-verification

The model checks its own answer before committing to it — substituting back into equations, running edge-case checks.

💡
"Aha moments"

During training (not just inference), checkpoint outputs show abrupt transitions: the model discovers a new reasoning strategy and begins applying it consistently.

A representative thinking trace after training:

<think> Let me solve 3x + 7 = 22 step by step. Subtract 7 from both sides: 3x = 15. Divide by 3: x = 5. Let me verify: 3(5) + 7 = 15 + 7 = 22. ✓ Wait, I should check if I handled this correctly from the start. The equation is 3x + 7 = 22, so 3x = 22 - 7 = 15, giving x = 5. Yes, that's correct. </think> <answer>x = 5</answer>

The self-verification and backtracking are not in the prompt, not in any training example. They emerge because they are instrumentally useful for getting the binary reward — the model found, by RL, that checking its work increases accuracy.

The AlphaZero parallel

This is precisely the AlphaZero phenomenon applied to language. AlphaZero learned to sacrifice pieces, plan openings, and evaluate endgames — all without being taught chess strategy — because those behaviors led to more wins. R1-Zero learned to self-verify, backtrack, and think longer because those behaviors led to more correct answers. In both cases: give the model a verifiable signal, give it an optimization algorithm, and it finds strategies humans never encoded. The difference is that chess has a perfect simulator; R1 relies on math/code verifiers as its ground-truth oracle.

The limitations of R1-Zero

R1-Zero has three practical failure modes that prevent direct deployment:

  • Language mixing — the model sometimes switches between English and Chinese mid-reasoning, especially when trained on a multilingual base.
  • Poor formatting — the <think>/<answer> structure is learned imperfectly; occasional malformed outputs that downstream applications can't parse.
  • Readability — thinking traces can be repetitive or circuitous in ways a human wouldn't write, making them hard to verify.

The full R1 pipeline addresses all three with a small amount of cold-start data before RL begins.

4. The Full R1 Pipeline

R1 is a four-stage pipeline. Each stage produces the model that feeds the next:

Stage 1
Cold-Start SFT
Fine-tune the base model on a small set of long-form CoT examples with correct <think> / <answer> formatting. Fixes language mixing and format before RL begins.
SFT · ~thousands of examples
Stage 2
Reasoning RL
GRPO on math and code tasks with verifiable outcome rewards + format reward. Model learns to reason deeply. This is where thinking length, self-correction, and verification emerge.
GRPO · no PRM · binary rewards
Stage 3
Rejection-Sampling SFT
Sample many responses from Stage 2 model, keep only correct ones. Mix in general-domain supervised data (QA, writing, etc.). Fine-tune on this combined dataset.
RS · 800K examples · SFT
Stage 4
Final RL
Another round of GRPO, now on the full task mixture — reasoning tasks with verifiable rewards + general tasks with a reward model. Balances reasoning and general helpfulness.
GRPO · mixed rewards

Stages 1 and 3 are standard SFT — the core learning happens in stages 2 and 4. The alternation of RL and SFT is deliberate: RL discovers new reasoning behaviors; SFT (on verified outputs from RL) stabilizes and generalizes them.

The cold-start SFT in Stage 1 is tiny — a few thousand examples, all human-written or carefully selected from strong models. Its only job is to give the model a consistent format template and a language anchor before the RL signal kicks in. It is not trying to teach the model how to reason.

5. Reward Design

One of the key engineering decisions in R1 is what not to include in the reward signal:

Accuracy reward
Is the answer correct?

Math: final boxed answer matches ground truth exactly. Code: all unit tests pass in a sandboxed executor. Binary \(\{0, 1\}\) — no partial credit.

Format reward
Is the structure correct?

Checks that <think>…</think> and <answer>…</answer> tags are present and correctly ordered. Small reward, prevents malformed outputs.

Not used
Process reward model

No per-step scoring. Every token in a response gets the same advantage signal, derived from the final outcome. A PRM is expensive to train and can be gamed.

Not used
Length penalty / bonus

No explicit reward for thinking length. Length grows naturally because longer thinking produces more correct answers. Adding a length bonus would be Goodhart's law bait.

Not used
Cosine / style rewards

No reward for readability, coherence, or writing style on reasoning tasks. Style rewards add noise and are hard to calibrate without a learned reward model.

Not used (Stage 2)
Learned reward model

Stages 1–3 use only rule-based verifiers. A learned reward model is added only in Stage 4 for general-domain tasks where no verifier exists.

Why binary rewards work

Binary rewards seem like they provide a weak learning signal — either you get it or you don't. But combined with GRPO's group sampling, binary rewards are surprisingly effective. With a group of \(G=8\) samples per prompt, the group-relative advantage \(\hat A_i = (r_i - \bar r)/\sigma_r\) varies continuously even when individual rewards are \(\{0,1\}\) — a prompt where 4/8 responses are correct has \(\hat A = \pm 0.5\) for each response, while a prompt where 7/8 are correct has \(\hat A = -2.65\) for the wrong one and \(+0.38\) for the correct ones. The difficulty gradient is implicit in the group statistics.

6. Rejection Sampling — The Bridge Between RL and SFT

After Stage 2 the model reasons well but unevenly — it can solve hard problems it couldn't before, but also produces low-quality outputs that mix reasoning with repetition. Rejection sampling converts the RL model's best outputs into clean SFT training data:

  1. Sample — for each prompt in a large reasoning dataset, generate \(G\) responses from the Stage 2 model (typically \(G \in [4, 64]\) depending on task difficulty).
  2. Filter — keep only responses where the final answer is verifiably correct. Optionally apply readability filters (no language mixing, well-formed tags).
  3. Mix — combine the filtered reasoning data with supervised data for general capabilities: QA, summarization, creative writing, safety. The mix prevents catastrophic forgetting of general language ability.
  4. Fine-tune — standard SFT on the combined dataset.

This produces a model that is both a strong reasoner (from the RL phase's training signal) and a coherent, formatted responder (from the SFT phase's stabilisation). Stage 4 RL then further improves both dimensions together.

Connection to AlphaZero's self-play loop

Rejection sampling + SFT is the LLM equivalent of AlphaZero's self-play training loop: use the current best model to generate training data (stage 2 model generates responses), filter to only high-quality examples (keep correct answers), train the next model on those examples (SFT), repeat. The key difference: AlphaZero generates data via MCTS (expensive search), while R1 generates data via sampling + outcome verification (much cheaper at LLM inference scale).

7. Distillation — Reasoning Without RL

The full R1 model (671B MoE) is large. To make reasoning accessible in smaller models, DeepSeek distills R1's capabilities directly via SFT — no RL training required for the student models.

StepWhat happens
Generate Sample 800K (prompt, response) pairs from the full R1 model across math, code, and reasoning tasks
Filter Keep only correct responses (same rejection-sampling filter as Stage 3)
Fine-tune SFT a smaller base model (Qwen-7B, Qwen-14B, Llama-8B, Llama-70B, etc.) on these 800K examples
Result Small model that can produce long reasoning traces, self-corrects, and solves problems far beyond its untuned capability

The distilled models outperform previous open-source models at the same parameter count by a large margin on math and code benchmarks — without any RL training. This finding has significant implications:

Why distillation is so effective here

Standard knowledge distillation transfers a teacher's output distribution to a student. What makes R1 distillation unusually effective is the nature of the teacher outputs: long, explicit reasoning traces. The student doesn't have to guess how to solve the problem — the teacher shows its work, step by step, verified to be correct. The student SFT is essentially supervised training on a very high-quality, reasoning-dense dataset that couldn't be produced cheaply by humans. This is the same dynamic as process supervision (PRMs) — but the process labels come from the RL-trained model rather than human annotators.

RL from scratch is harder and less efficient than distillation for small models. A 7B model trained with GRPO from scratch (R1-Zero style) substantially underperforms a 7B model distilled from the full R1 teacher on the same compute budget. Distillation leverages the teacher's search — the 671B model found the reasoning paths through RL; the 7B model just has to learn to produce similar paths via SFT.

8. What R1 Tells Us About Reasoning in LLMs

Reasoning is a latent capability, not a trained behavior

R1-Zero demonstrates that a pretrained LLM already has the underlying representations needed for multi-step reasoning — it just doesn't use them unless rewarded to. The base model was trained on vast amounts of text that contains mathematical reasoning; R1-Zero's RL unlocks this latent capability. This reframes alignment: we're not teaching the model how to reason, we're selecting for the behaviors that demonstrate it.

Verifiable tasks are the key constraint

Everything in R1 depends on having a ground-truth verifier — something that unambiguously tells you whether the model's answer is correct. Math and code are ideal: answers are exact-match, test cases are mechanical. Open-ended tasks (helpfulness, style, nuance, safety) don't have this property, which is why Stage 4 needs a learned reward model for general tasks. The hard problem of alignment is that most of what we care about in LLM behavior can't be verified automatically.

Summary

Base LLM + GRPO + binary verifier → spontaneous chain-of-thought. No CoT demonstrations needed.

Cold start

Tiny SFT on well-formatted CoT fixes language/format before RL, without teaching reasoning.

Reasoning RL

GRPO with accuracy + format rewards. Thinking length, self-correction, verification emerge from the binary signal.

Rejection sampling
