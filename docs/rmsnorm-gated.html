Gated RMSNorm

RMSNorm followed by a SiLU output gate — the norm-then-gate module Qwen3-Next applies to every linear-attention head, and why the gate deliberately comes after the norm.

The Basic Idea

Qwen3-Next mixes two token mixers: standard softmax attention in a minority of layers, and Gated DeltaNet — a linear-attention layer that replaces the softmax with a fast recurrent state update — in the rest. Each Gated DeltaNet layer ends with Qwen3NextRMSNormGated, which does two jobs in one module:

  1. Normalize. The layer's raw output is a readout from a recurrent memory state. Unlike softmax attention — whose output is a convex combination of value vectors and therefore scale-bounded — nothing bounds the scale of this readout. A per-head RMSNorm brings every head back to unit scale before the output projection.
  2. Gate. The normalized readout is multiplied element-wise by \(\mathrm{silu}(\mathbf{z})\), where the gate pre-activation \(\mathbf{z}\) is computed directly from the layer's input hidden state. The current token decides, channel by channel, how much of the memory readout to let through — including "none at all."

The ordering is the design decision the module's name hides: Qwen3-Next normalizes first and gates second, so the gate has the last word on output magnitude. Mamba-2's otherwise identical module does the reverse — and the difference is not cosmetic, as the plot below shows.

Notation

SymbolDescription
\(\mathbf{x} \in \mathbb{R}^{d_h}\)One value head's readout from the delta-rule recurrence (core_attn_out); \(d_h\) = head_v_dim
\(\mathbf{z} \in \mathbb{R}^{d_h}\)Gate pre-activation for the same head, a slice of the input projection in_proj_qkvz
\(r\)Root mean square of \(\mathbf{x}\): \(\sqrt{\tfrac{1}{d_h}\sum_i x_i^2 + \varepsilon}\)
\(\hat{x}_i\)Normalized readout: \(x_i / r\)
\(\mathbf{w}\)Learned scale (the RMSNorm \(\gamma\)), initialized to ones
\(\sigma(z),\ \mathrm{silu}(z)\)Sigmoid \(1/(1+e^{-z})\) and SiLU/Swish \(z\,\sigma(z)\), applied element-wise
\(\varepsilon\)Numerical-stability constant (rms_norm_eps)

1. Forward Pass

  1. Root mean square (over the head dimension, in fp32) \[r = \sqrt{\frac{1}{d_h}\sum_{i=1}^{d_h} x_i^2 + \varepsilon}\]
  2. Normalize and scale — plain RMSNorm \[\hat{x}_i = \frac{x_i}{r}, \qquad \tilde{y}_i = w_i\,\hat{x}_i\]
  3. Gate — the SiLU output gate is applied after normalization \[y_i = \tilde{y}_i \cdot \mathrm{silu}(z_i) = \tilde{y}_i \cdot z_i\,\sigma(z_i)\]
Result — one line
\[ y_i \;=\; w_i \cdot \frac{x_i}{\sqrt{\tfrac{1}{d_h}\sum_j x_j^2 + \varepsilon}} \cdot z_i\,\sigma(z_i) \]

Two things distinguish this from the RMSNorm that wraps every transformer sublayer:

  • It is per-head, not per-token. The module is built with hidden_size = head_v_dim (128 in Qwen3-Next-80B-A3B), and the readout is flattened from \((B, S, H_v, d_h)\) to \((B \cdot S \cdot H_v,\ d_h)\) before the call. Each value head is normalized independently, so no single head's scale drift can dominate the concatenated output that feeds out_proj.
  • The gate is input-dependent but recurrence-free. \(\mathbf{z}\) is produced by the same matmul that produces \(q, k, v\) — one projection of the layer input, split four ways. It never passes through the convolution or the recurrent state, so it is a clean function of the current token: "given what this token is, how much memory readout does it want?"
This is the same gating primitive as SwiGLU — \(\mathrm{silu}(\text{gate}) \odot \text{value}\) — reused as an output gate on an attention readout instead of a hidden gate inside the FFN.

2. Why Norm-Before-Gate — the Order Matters

Mamba-2 ships an almost identical module (MambaRMSNormGated) with the opposite order: it gates first, then normalizes. Written side by side:

Side by side — where the gate sits
Qwen3-Next — norm, then gate
\[ \mathbf{y} = \Bigl(\mathbf{w} \odot \frac{\mathbf{x}}{\mathrm{rms}(\mathbf{x})}\Bigr) \odot \mathrm{silu}(\mathbf{z}) \]
Mamba-2 — gate, then norm
\[ \mathbf{y} = \mathbf{w} \odot \frac{\mathbf{x} \odot \mathrm{silu}(\mathbf{z})}{\mathrm{rms}\bigl(\mathbf{x} \odot \mathrm{silu}(\mathbf{z})\bigr)} \]

The key fact is that RMSNorm is scale-invariant: \(\mathrm{rms}(c\,\mathbf{x}) = |c|\,\mathrm{rms}(\mathbf{x})\), so for any head-uniform gate value \(c\),

\[ \frac{c\,\mathbf{x}}{\mathrm{rms}(c\,\mathbf{x})} = \mathrm{sign}(c)\,\frac{\mathbf{x}}{\mathrm{rms}(\mathbf{x})}. \]

Gate before the norm, and the normalization undoes the gate's magnitude — only its sign and relative shape survive. Gate after the norm, and the full \(\mathrm{silu}(z)\) magnitude reaches the output: as \(z \to -\infty\) the head's contribution genuinely goes to zero, and nothing rescales it back.

norm → gate (Qwen3-Next): scale = silu(z) gate → norm (Mamba-2, uniform gate): scale = sign(z)

Only norm-before-gate lets the gate close the valve. Each curve is the effective scale multiplying a head's normalized output, as a function of the gate pre-activation \(z\) (held uniform across the head to isolate the magnitude effect). In Qwen3-Next's order (violet) the head is smoothly attenuated to zero for negative \(z\) and can be amplified for positive \(z\). In Mamba-2's order (amber) the norm cancels the gate's magnitude — however hard the gate squeezes, the output comes back at unit RMS, and only the sign flips. Real gates vary element-wise, so the cancellation is partial in practice — but the head-wide component of the gate is always renormalized away.

Why does Qwen3-Next want the gate to have the last word? The team cites output gating as a mitigation for the attention-sink / massive-activation pathology: in standard attention, softmax weights must sum to one, so a head with nothing useful to say learns to dump its attention mass on a sink token (often the first token) as a de facto no-op. An output gate that survives normalization gives every head an honest no-op instead — when the current token has no use for that head's memory readout, \(\mathrm{silu}(z) \approx 0\) silences it outright.

3. The Code

The module, verbatim from Hugging Face transformers (modeling_qwen3_next.py):

class Qwen3NextRMSNormGated(nn.Module):
    def __init__(self, hidden_size, eps=1e-6, **kwargs):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))
        self.variance_epsilon = eps

    def forward(self, hidden_states, gate=None):
        input_dtype = hidden_states.dtype
        hidden_states = hidden_states.to(torch.float32)
        variance = hidden_states.pow(2).mean(-1, keepdim=True)
        # Norm before gate
        hidden_states = hidden_states * torch.rsqrt(variance + self.variance_epsilon)
        hidden_states = self.weight * hidden_states.to(input_dtype)
        hidden_states = hidden_states * F.silu(gate.to(torch.float32))

        return hidden_states.to(input_dtype)

And its call site inside Qwen3NextGatedDeltaNet.forward, condensed to the lines that matter — note where \(\mathbf{z}\) is born and how the per-head flattening happens: 

# one input projection yields q, k, v AND the output gate z
projected_states_qkvz = self.in_proj_qkvz(hidden_states)
query, key, value, z, b, a = self.fix_query_key_value_ordering(projected_states_qkvz, ...)

# q, k, v go through the causal conv + delta-rule recurrence; z does not
core_attn_out, last_recurrent_state = self.chunk_gated_delta_rule(
    query, key, value, g=g, beta=beta, ...)

# flatten (B, S, H_v, d_h) -> (B*S*H_v, d_h): norm + gate act per head
core_attn_out = core_attn_out.reshape(-1, core_attn_out.shape[-1])
z = z.reshape(-1, z.shape[-1])
core_attn_out = self.norm(core_attn_out, z)          # <-- this module

core_attn_out = core_attn_out.reshape(...)           # back to (B, S, H_v * d_h)
output = self.out_proj(core_attn_out)

So the full Gated DeltaNet layer reads:

Where it sits in the layer

input → in_proj (q, k, v, z) → causal conv1d → delta-rule recurrence → per-head RMSNorm ⊙ silu(z) → out_proj

4. Implementation Details Worth Noticing

  • The torch class is the fallback path. When the flash-linear-attention (fla) library is installed, the layer swaps in FusedRMSNormGated — a Triton kernel fusing the normalization and the silu-gate multiply into one launch. Same math, one kernel.
  • fp32 statistics, low-precision storage. The variance and the silu gate are computed in fp32 and the result is cast back to the input dtype — standard practice, since a bf16 sum of 128 squares loses meaningful precision. (The weight multiply happens after an early downcast, a small dtype quirk of this implementation.)
  • Asymmetry with the plain Qwen3NextRMSNorm. Qwen3-Next's ungated norms are zero-centered: weight initializes to zeros and applies as \((1 + w)\,\hat{x}\), so weight decay pulls the effective scale toward 1 (identity) instead of toward 0. The gated variant keeps the classic ones-initialized \(w\,\hat{x}\) — the silu gate already owns the output scale, so the zero-centered trick buys nothing here.
  • The gradient adds one clean factor. Because the gate is applied outside the norm, backprop through this module is the RMSNorm backward with the upstream gradient pre-multiplied by \(\mathrm{silu}(\mathbf{z})\), plus a SwiGLU-style branch \(dz_i = \tilde{y}_i\,dy_i\,\bigl[\sigma(z_i) + z_i\sigma(z_i)(1-\sigma(z_i))\bigr]\) into the gate. Nothing new to derive — the two known backward passes compose.

5. Summary

Forward

\(y_i = w_i\,\tfrac{x_i}{r}\cdot z_i\,\sigma(z_i)\), with \(r = \sqrt{\tfrac{1}{d_h}\sum x_j^2 + \varepsilon}\)

Where

Per value head (\(d_h\) = head_v_dim), on the Gated DeltaNet readout, before out_proj

Why norm first

RMSNorm is scale-invariant — a gate applied before it is renormalized away; applied after, it can truly silence a head
