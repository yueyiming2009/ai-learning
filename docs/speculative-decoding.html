Speculative Decoding — Draft, Verify, and Accelerate

The memory bandwidth wall forces one target model forward pass per output token — but a fast draft model can propose several tokens in one pass. Speculative decoding verifies all draft proposals in a single target forward pass using rejection sampling, producing exactly the target distribution while generating multiple tokens per verification step.

Decode throughput is capped by how fast the model's weights can be loaded from HBM. Making the target model smaller is not always an option. Speculative decoding instead exploits an asymmetry: a small draft model is much cheaper to run than the target, and the target model can verify many positions simultaneously in a single forward pass (just as prefill processes the full prompt in parallel). The result: \(\gamma\) tokens can be generated per target model call, rather than 1.

1 · The single-token-per-step bottleneck

As derived in Prefill & Decode, each decode step loads \(\approx 2N\) bytes of model weights to compute one token. At batch size 1:

Decode throughput ceiling (batch = 1)
\[ \text{tokens/s} = \frac{\text{peak\_bw}}{2N} \]
No software optimization can exceed this without reducing bytes loaded per step or increasing the tokens produced per step.

Batching multiple requests raises the effective batch size \(B\) and improves throughput. But for a single user (or in latency-constrained settings where large batches are not available), the memory bandwidth wall is absolute. The only way to produce more tokens per unit time is to produce more tokens per model call.

2 · The draft-then-verify idea

Autoregressive generation forces serial execution — each token depends on the previous one. But verification is parallel: given a candidate sequence, the target model can score all positions simultaneously in a single forward pass, just like prefill.

One speculative decoding step
  1. Draft: run the small draft model autoregressively for \(\gamma\) steps, producing candidate tokens \(\hat{x}_1, \hat{x}_2, \ldots, \hat{x}_\gamma\) along with their probabilities \(q(\hat{x}_t \mid \ldots)\).
  2. Verify: run the target model on the concatenation [context, \(\hat{x}_1, \ldots, \hat{x}_\gamma\)] — one forward pass that processes all \(\gamma\) positions in parallel. Obtain target probabilities \(p(x \mid \ldots)\) at each position.
  3. Accept or reject: for each draft token \(\hat{x}_t\) (in order), accept it with probability \(\min(1,\, p(\hat{x}_t) / q(\hat{x}_t))\); reject and resample from a corrected distribution on the first rejection.
  4. Bonus token: if all \(\gamma\) draft tokens are accepted, the target model's prediction at position \(\gamma + 1\) is also available for free — so at best we get \(\gamma + 1\) tokens per target model call.

3 · The acceptance criterion — exact distribution, no quality loss

The key correctness claim: the rejection sampling procedure produces tokens drawn exactly from the target distribution \(p\), regardless of the draft distribution \(q\). This is non-obvious — we are using a different model to propose tokens and then modifying its output. The proof is a classical result in rejection sampling:

Why the output distribution is exactly p

Consider a single position with target distribution \(p\) and draft distribution \(q\). The draft proposes token \(x\) with probability \(q(x)\). We accept it with probability \(\min(1, p(x)/q(x))\). The probability of outputting token \(x\) is:

  • Via acceptance: \(q(x) \cdot \min(1, p(x)/q(x)) = \min(q(x), p(x))\).
  • Via rejection + resample: the resample probability for \(x\) is proportional to \(\max(0, p(x) - q(x))\), normalized by the total rejection probability \(\sum_y \max(0, p(y) - q(y))\).

Combining these two paths recovers exactly \(p(x)\) for every token \(x\). The draft model affects efficiency (what fraction of proposals are accepted) but not quality (the marginal distribution of each output token). Speculative decoding has no accuracy loss relative to the target model.

Correctness guarantee
The output distribution of speculative decoding equals exactly the target model's distribution \(p\). The draft model is an implementation detail that affects speed, not quality.

4 · Expected speedup formula

Let \(\alpha\) be the per-token acceptance rate: \(\alpha = \Pr[\hat{x} \text{ accepted}]\). The expected number of output tokens per target model call:

Expected tokens per target call
\[ \mathbb{E}[\text{tokens per step}] = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha} \]
This counts the expected number of accepted draft tokens plus one token from the target model itself (the first rejection position or the bonus token at position \(\gamma+1\) if all are accepted).

The wall-clock speedup also depends on the relative cost of draft vs. target model calls. Let \(c\) be the cost of one draft step as a fraction of one target step:

Wall-clock speedup
\[ \text{speedup} = \frac{\mathbb{E}[\text{tokens per step}]}{\gamma c + 1} = \frac{1 - \alpha^{\gamma+1}}{(1 - \alpha)(\gamma c + 1)} \]

Breakeven condition: speculative decoding is worthwhile when the speedup > 1, i.e., when: \(\mathbb{E}[\text{tokens per step}] > \gamma c + 1\), i.e., when \(\frac{1 - \alpha^{\gamma+1}}{1 - \alpha} > \gamma c + 1\).

5 · Draft model choices

Draft typeDescriptionAcceptance rateDraft cost \(c\)
Small separate model A smaller model from the same family (e.g., Llama-3 8B drafts for Llama-3 70B) High (0.7–0.9) — same training distribution ~0.1–0.2
Medusa draft heads Lightweight MLP heads attached to the target model, each predicting token at offset +k. All heads run in the target model's forward pass. Medium (0.5–0.8) ~0.05 (almost free, runs inside target forward pass)
Eagle / tree-based draft Draft model uses target model's hidden states (passed through) for more accurate proposals; generates a tree of candidates rather than a single sequence. High (0.8–0.95 with tree verification) ~0.1–0.2
N-gram / retrieval draft Propose tokens from a static lookup (prompt n-gram completion or retrieval from a corpus). Zero model cost. Variable (0.3–0.7 for repetitive text) ≈0 (hash lookup)
Self-speculative / layer skipping Use early exit layers of the target model as the draft. No second model needed. Medium (0.5–0.75) ~0.2–0.4

6 · When speculative decoding wins — and when it doesn't

Conditions for a large speedup
  • High acceptance rate \(\alpha\): the draft model's distribution closely matches the target's. This happens when temperature is low (greedy-like sampling), task is predictable (code with repetitive patterns, templated text), or the draft model is closely related to the target.
  • Low draft cost \(c\): the draft model is much smaller or shares computation with the target. A 7B draft for a 70B target: each draft step is ~10× cheaper, so \(c \approx 0.1\).
  • Low to medium batch size: at batch size 1–16, the target model is memory-bound — speculative decoding parallelizes output generation against the fixed memory load. At very large batches, the model is compute-bound and adding more tokens per step may not save time.
Conditions where speculative decoding hurts or is neutral
  • High temperature / diverse outputs: at temperature 1.0 with a diverse vocabulary, \(\alpha\) drops toward 0.3–0.5. Expected tokens per step approaches 1.5–2, providing modest speedup that may not justify the draft overhead.
  • Very large batch sizes: above the GPU ridge point, the bottleneck is compute, not memory bandwidth. Adding draft tokens increases the compute load without improving time-per-token.
  • Expensive draft model: if the draft model costs \(c = 0.5\) of the target, the denominator \(\gamma c + 1 = 3\) for \(\gamma = 4\), requiring \(\mathbb{E}[\text{tokens}] > 3\) — only achievable at very high \(\alpha\).
Speculative decoding optimizes for latency (TPOT at small batch), not throughput (tokens/s at large batch). For batch offline inference where batch size is large and latency is irrelevant, it typically provides no benefit or is mildly harmful. It is most impactful for low-latency online serving and single-user interactive applications.

7 · Summary

The insight

A fast draft model proposes \(\gamma\) tokens; the target verifies all \(\gamma+1\) positions in one parallel forward pass. More tokens per target model call = lower effective TPOT.

No quality loss

Rejection sampling proves the output distribution is exactly the target's \(p\). The draft model changes speed, not quality.

Expected speedup

\(\frac{1 - \alpha^{\gamma+1}}{(1-\alpha)(\gamma c + 1)}\). High \(\alpha\), low \(c\), and moderate \(\gamma\) (4–8) give 2–3× speedups on suitable workloads.

Best case

Low temperature, predictable text (code, templated output), small draft model (7B for 70B target), small to medium batch size.

Worst case

High temperature, diverse outputs, large batch sizes (compute-bound), or draft model too expensive. Reverts toward no speedup.

Draft variants

Separate small model (best \(\alpha\)), Medusa heads (nearly free), Eagle tree drafts (highest \(\alpha\) via tree verification), n-gram lookup (zero cost).
