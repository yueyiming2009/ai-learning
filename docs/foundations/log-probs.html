Log-Probabilities from Logits

Every policy-gradient, PPO, GRPO, and RLHF objective is built on \(\log\pi_\theta(a_t\mid s_t)\) — the log-probability the model assigns to a token it generated — and each treats that number as already computed. This is the forward-pass step underneath: how one log-probability falls out of the output logits as a log_softmax gather, and how per-token logs sum into a sequence log-prob.

The same vector of logits a language model emits at each position can be read two ways. Pick the index of the target token and negate, and you have the cross-entropy training loss. Pick the index of the token the model actually sampled, keep the sign, and you have the \(\log\pi\) that the RL pages consume. This page derives that second reading from scratch — the operator, the numerically stable form, the gather, and the sum over a sequence — then shows exactly where each downstream method picks it up.

1. From logits to a log-probability

A model scores the vocabulary with logits \(\mathbf{z}\), turned into a distribution by softmax:

\[ p_i = \frac{e^{z_i}}{S}, \qquad S = \sum_{j=1}^{V} e^{z_j} \]

(The cross-entropy page covers softmax and its gradient in full.) We want the log-probability of a single chosen token \(a\). Rather than form \(\mathbf{p}\) and then take a log, take the log of softmax directly — the division becomes a subtraction:

\[ \log p_a = \log \operatorname{softmax}(\mathbf{z})_a = \log \frac{e^{z_a}}{S} = z_a - \log \sum_{j=1}^{V} e^{z_j} = z_a - \operatorname{logsumexp}(\mathbf{z}) \]

The chosen logit minus the log-partition: that is the whole computation. The \(\log\sum_j e^{z_j}\) term overflows if any logit is large, so in practice it is stabilized exactly as softmax is — subtract the max logit \(m=\max_j z_j\) before exponentiating (the \(e^{-m}\) factors cancel):

\[ \log p_a = (z_a - m) - \log \sum_{j=1}^{V} e^{z_j - m} \]
Log-probability of one token
\[ \log p_a \;=\; \log \operatorname{softmax}(\mathbf{z})_a \;=\; z_a - \operatorname{logsumexp}(\mathbf{z}) \]
In plain English

"To score a token the model produced: take its own logit, and subtract the log of the summed exponentials of all logits. The subtraction is the normalization — it is how much probability mass the rest of the vocabulary claimed, in log space."

Computing it this way — as log_softmax followed by a gather of index \(a\), never materializing \(\mathbf{p}\) — is what every framework does (PyTorch F.log_softmax(z).gather(-1, a), or Categorical(logits=z).log_prob(a)). It sidesteps both the overflow of large \(e^{z}\) and the underflow of \(\log\) on a tiny \(p\).

2. Loss vs. policy — only the gathered index differs

The forward pass produces the whole vector \(\log\operatorname{softmax}(\mathbf{z}) \in \mathbb{R}^V\) regardless of what you do with it. Which single entry you pull out, and its sign, is the only difference between training a classifier and scoring an action:

ReadingGathered indexQuantityRole
Cross entropy (loss)target class \(k\)\(-\log\operatorname{softmax}(\mathbf{z})_k\)minimize
Policy log-probsampled token \(a\)\(+\log\operatorname{softmax}(\mathbf{z})_a\)score \(\nabla_\theta \log\pi\)

So cross entropy is just the negative log-prob at the token you wanted; the RL log-prob is the (positive) log-prob at the token you got. Same gather, different index — which is why the gradient machinery the loss page derives (\(\partial L/\partial\mathbf{z} = \mathbf{p} - \mathbf{y}\), the clean \(p-y\) residual) carries straight over, now applied at the sampled index.

3. Gather, then sum over the sequence

A language model emits one logit vector \(\mathbf{z}^{(t)}\) per position. Generation is autoregressive, so the probability of a whole sequence factorizes into a product of per-step conditionals — and the log turns that product into a sum:

\[ \log \pi_\theta(y \mid x) = \log \prod_{t=1}^{T} \pi_\theta(a_t \mid s_t) = \sum_{t=1}^{T} \log \operatorname{softmax}\!\big(\mathbf{z}^{(t)}\big)_{a_t} \]
Sequence log-probability
\[ \log \pi_\theta(y \mid x) = \sum_{t=1}^{T} \Big( z^{(t)}_{a_t} - \operatorname{logsumexp}\big(\mathbf{z}^{(t)}\big) \Big) \]

Each term is one gather from one position's log-softmax row; the sequence log-prob is their sum. (This is the same "fold the sequence into the batch" move the loss uses — a per-token quantity summed along the time axis — except the gathered index at each step is the token the policy sampled, not a fixed label.)

In code the whole computation is four lines — and the bugs live in the three practical details the math glosses over: the teacher-forcing shift (position \(t\)'s logits score token \(t{+}1\)), the gather dimension, and masking out prompt and padding tokens before the sum:

import torch.nn.functional as F

def sequence_logprobs(logits, tokens, mask):
    # logits: (B, T, V) model outputs;  tokens: (B, T) sampled/target ids
    # mask:   (B, T) 1 for tokens that count (response, non-pad), else 0
    logp = F.log_softmax(logits[:, :-1], dim=-1)        # z - logsumexp(z), stable; t predicts t+1
    tok  = tokens[:, 1:]
    tok_logp = logp.gather(-1, tok.unsqueeze(-1)).squeeze(-1)  # gather the sampled index a_t
    return (tok_logp * mask[:, 1:]).sum(-1)             # sum per-token logs over the sequence
Each line maps to a step above — log_softmax is §1, gather is §2, * mask).sum is §3. This is essentially what verl's compute_log_probs and TRL's log-prob helpers run on every rollout to score \(\pi_\theta\) and \(\pi_{\theta_{\text{old}}}\).

4. A worked example

Take a two-token generation over a tiny vocabulary, and compute its sequence log-prob.

Position 1 — logits [2.0, 1.0, 0.1], sampled token 0

With \(m = 2.0\):

\[ \operatorname{logsumexp} = 2.0 + \log\!\big(e^{0} + e^{-1} + e^{-1.9}\big) = 2.0 + \log(1.5174) = 2.4170 \]

The three log-probs are \(z_a - 2.4170 = [-0.417,\ -1.417,\ -2.317]\), i.e. probabilities \([0.659,\ 0.242,\ 0.099]\) (they sum to 1, as they must). The sampled token 0 contributes \(\log p^{(1)} = 2.0 - 2.4170 = -0.417\).

Position 2 — logits [0.5, 2.0, 1.0], sampled token 1

With \(m = 2.0\):

\[ \operatorname{logsumexp} = 2.0 + \log\!\big(e^{-1.5} + e^{0} + e^{-1.0}\big) = 2.0 + \log(1.5910) = 2.4644 \]

The sampled token 1 contributes \(\log p^{(2)} = 2.0 - 2.4644 = -0.464\).

The sequence log-probability is the sum, and exponentiating recovers the sequence probability:

\[ \log \pi_\theta(y\mid x) = -0.417 + (-0.464) = -0.881, \qquad \pi_\theta(y\mid x) = e^{-0.881} \approx 0.414 \]

From here the optimizer pushes each sampled logit up or down through the cross-entropy gradient \(p - y\), now evaluated at the sampled index and weighted by that token's advantage — which is precisely what the RL objectives below do.

5. Where this lands in RL

Every LLM RL method is some arrangement of these per-token log-probs. The forward pass is identical; only how the numbers are combined changes:

MethodUses the log-prob as…
Policy gradientdifferentiates it: \(\nabla_\theta \log\pi_\theta(a_t\mid s_t)\), the score function, weighted by return
PPO / GRPOa difference of two gathers, exponentiated: \(\rho_t = \exp\!\big(\log\pi_\theta(a_t\mid s_t) - \log\pi_{\theta_{\text{old}}}(a_t\mid s_t)\big)\) — the importance ratio
RLHF KL penaltya per-token difference \(\log\pi_\theta(a_t\mid s_t) - \log\pi_{\text{ref}}(a_t\mid s_t)\), summed over the sequence

In every case the atom is the same \(z_a - \operatorname{logsumexp}(\mathbf{z})\) computed here. Computing ratios and KL in log space — subtract, then exp only if you need the ratio itself — is what keeps them numerically stable.

6. Summary

The operator

\(\log p_a = z_a - \operatorname{logsumexp}(\mathbf{z})\) — chosen logit minus log-partition

Stable form

\((z_a - m) - \log\sum_j e^{z_j - m}\), \(m=\max_j z_j\)

In code

log_softmax(z) then gather index \(a\); never materialize \(\mathbf{p}\)

Sequence

\(\log\pi_\theta(y\mid x) = \sum_t \big(z^{(t)}_{a_t} - \operatorname{logsumexp}(\mathbf{z}^{(t)})\big)\)

Loss vs. policy

Same gather; target index \(k\) (negated) → CE loss, sampled index \(a\) → \(\log\pi\)

Downstream

Differentiated (PG), subtracted+exp'd (PPO/GRPO ratio), or differenced (RLHF KL)

When you see…Recognize it as
\(\log\pi_\theta(a_t\mid s_t)\) in an RL objectiveOne log_softmax gather at the sampled token
\(\log\pi_\theta(y\mid x)\) for a whole responseA sum of per-token log-probs along the sequence
A ratio \(\pi_\theta/\pi_{\theta_{\text{old}}}\)\(\exp(\log\pi_\theta - \log\pi_{\theta_{\text{old}}})\), computed in log space
The cross-entropy loss \(-\log p_k\)The same operator at the target index, negated
