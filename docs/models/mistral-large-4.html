1. Preview, released weights, and parameter accounting

The October 6 preview announcement promised a later weights release. The subsequent release announcement and official checkpoint establish that weights are now available. Preview benchmark numbers should not silently stand in for this improved checkpoint.

The model is branded as 1T total/52B active. Mistral's docs give 1.05T total, while the checkpoint card distinguishes 49B active excluding embeddings/output layers from 52B including embeddings and output layers. Keep that accounting distinction when comparing sparse models. It accepts text and images, emits text, and supports a 1,048,576-token context.

3. The reported training progression

  1. 1. Train a multimodal foundationMistral reports training from scratch on 3,800 Grace Blackwell GPUs in its European datacenters, with multilingual data spanning more than 160 languages.
  2. 2. Supervised fine-tuning and RLThe preview account attributes gains to both SFT and RL. Tasks cover scientific reasoning, chat, factuality, safety, and long-horizon tool use, sharing composable environment and verification interfaces.
  3. 3. Continue improving after previewThe open-weight announcement reports three additional weeks of RL, incorporating feedback and improving coding and token efficiency.
  4. 4. Release an improved checkpointOne weight set supports low, medium, and high reasoning effort. The released package includes a speculative draft head and an additional official NVFP4 variant.

What the runtime contributes: an autoscaling actor fleet collects tens of thousands of rollouts concurrently while training runs asynchronously. Shared sandboxes, search, and APIs support multiple task types; verifiers combine tests, reward models, judges, and static checks. The preview account reports about 33B generated tokens/day on roughly 3,000 GPUs, of which about 16B are trainable completion tokens after filtering and masking. These are different denominators, not interchangeable throughput measures.

Long trajectories can span multiple context compactions. The announcement reports low-staleness/off-policy controls, but does not specify enough to reconstruct token provenance, the exact objective, or freshness thresholds. Do not substitute another framework's defaults for those missing details.

Disclosure limit: the exact corpus/token budget, complete stage schedule, optimizer settings, loss modifications, and checkpoint handoffs are not established by these sources. A reported SFT → RL progression is not a reproducible launch recipe.

Sources: preview account and weights release. Mechanics: async RL, harness contracts, training lifecycle.

4. A model package is more than the target weights

The main official checkpoint uses blockwise FP8 quantization with higher-precision exceptions. The NVFP4 variant targets Blackwell serving. Neither storage format alone establishes the precision used throughout the original training run.

The card describes an embedded DSpark draft head: three dense MLA draft layers in BF16 proposing a three-token block. It reports up to 1.9× serving throughput versus the target alone, dependent on workload and hardware. This is a serving comparison, not an RL sample-efficiency gain.

The recommended settings are temperature 1.0, top-p 0.95, and reasoning effort low, medium, or high (default). Correct reasoning/tool parsing and a combined reasoning-plus-output budget are part of the interface. Follow the card's version-specific engine guidance; no weights, container, or model code was installed or executed for this page.

Mechanics: speculative decoding and quantized serving.

5. Preserve the checkpoint and benchmark version

The weights-release account reports Terminal-Bench 4.0 improving from roughly 28% at preview to 41%, with 30% fewer output tokens. It reports 48% on the Artificial Analysis Coding Agent Index and a favorable quality/token trade-off. These remain source-reported results, not independently reproduced measurements.

Some integration documentation still repeats preview-era scores. Prefer the release source when discussing the released checkpoint, and retain the benchmark version, harness, and reasoning effort. In particular, Mistral's card cites Intelligence Index v5; the October Muse Spark Open methodology uses v4.3. Their raw aggregate numbers are not directly comparable.

Benchmark attack resistance is measured under a test setup, not a guarantee that any self-hosted agent is safe without deployment-specific controls.

6. Open weights, with a custom license

The Mistral Ecosystem Open-Weight License is modified from MIT, not unmodified MIT. It requires attribution/notices and a separate commercial license when the licensee or an affiliate operates a Model-as-a-Service business and uses the model commercially, subject to its definitions and exceptions. Its internal-use and official-product exceptions are explicit; it does not use the revenue threshold found in some other open-weight licenses.

Read the actual terms for the intended use. Downloadable weights do not imply unrestricted hosted-model commercialization.
