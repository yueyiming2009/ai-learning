Nemotron 3.5 Bolt 74B-A9B

Optimize the model for a memory envelope: search heterogeneous expert capacities, recover text and vision, then spend precision to retain more model capacity.

Nemotron family · Released October 15, 2026

Lineage: compressed from Super VL 120B-A12B. This is an architecture-and-weight transformation, not just quantizing the unchanged parent. Bolt E4B is a different, Gemma-derived branch.

Layer-specific experts · Compression and recovery · Memory arithmetic · Evidence

Evidence: pinned configuration, model card and 19-page technical report, checked November 1, 2026. The 24GB label is a deployment target with explicit exclusions, not a universal peak-memory guarantee.

1. More model capacity, fewer bits

The parent is a 120B/12B-active VLM. Bolt retains a large 74B model, activates roughly 9B parameters/token, and quantizes expert weights aggressively. The design question is not “how small can the parameter count become?” but “which architecture gives the lowest distillation loss within a deployment-memory budget?”

Super VL BF16 → Star Elastic architecture/weight search → fixed 74B text tower → vision reattachment and recovery → SFT/merges + agentic RL → BF16 checkpoint → two-bit QAD → 24GB-targeted release + optional LiLiCorr drafter.

2. The depth stays; expert capacity varies by layer

The pinned block_configs are authoritative. Top-level fallback fields still mention 512 experts, but actual MoE layers use 240, 304, 368, 432, or 496 experts. Their counts across the 40 layers are 12, 6, 9, 10, and 3 respectively. Intermediate widths are 1536, 2048, 2304, or 2560. The residual width remains 4096 and latent expert width 1024.

For two-matrix ReLU² experts, routed matrix parameters are:

\[ P_{\rm routed}=\sum_{i=1}^{40}2\cdot1024\cdot F_i\cdot E_i =66{,}144{,}174{,}080. \]

At top-9, a layer with \(F_i=2304\) performs about 84.9M routed-expert matrix FLOPs/token before compression projections, shared experts, and other layers. The router selects experts; it does not choose the layer's stored capacity at inference time. See Latent MoE for the shared graph and budget assumptions.

The C-RADIO v4-H tower and connector come from the parent. Text/image/video enter one language context; audio is not a supported input in the released contract. The target configuration has no MTP layers—speculation uses a companion LiLiCorr/DFlash-style drafter rather than assuming the parent's MTP head survived compression.

3. Recovery is part of compression, not an optional polish step

  1. Budget-conditioned architecture search. A trainable architecture router chooses per-layer capacities while distillation updates the student weights. A size penalty constrains the target footprint at batch 1/128K context, accounting for low-bit weights and runtime states.
  2. Fix the architecture and recover knowledge. Search converges in the first 8B tokens; training at 8K continues to 72B processed tokens, then another 48B tokens at 128K, for 120B total. The card's separate 80B “training data size” field should not be treated as the same processed-token accounting.
  3. Restore the visual bridge. Reattach the parent's vision tower and train only the connector on an image-text blend of about 6.6M samples/epoch. This stage contains no video or text-only data.
  4. Recover visual and agentic behavior. Vision-heavy joint SFT updates the LLM, connector and vision tower; SLERP checkpoint merging balances capabilities before further RLHF and end-to-end agentic RL.
  5. Train for useful work, not only tokens. MCP and SWE environments optimize multi-turn outcomes and efficiency. The report distinguishes a smooth coverage signal from the thresholded MCP-Atlas pass rate: reward progress need not immediately change a benchmark's binary score.
  6. Quantize and distill again. Experts, including shared experts, use IQ2_XXS. QAD uses a frozen BF16 teacher and distribution-overlap supervision; the report's Jaccard objective is not ordinary supervised next-token loss.

Reported two-bit QAD uses an LR peak of \(10^{-5}\), a 1.2B-token warm-up, and decay toward \(10^{-7}\) over a 25B-token schedule. These are reported recipe settings—not safe defaults for a different model, bit format, or training stack.

Intermediate checkpoint merges and modality-specific recovery matter: compressing the text tower alone does not preserve visual alignment. This is why a compressed checkpoint plus an unchanged image API is not yet the final model.

5. What the results support

The card reports 50.98 on Terminal-Bench 2.1, 66.75 on BrowseComp, and 87.82 on PinchBench. They support the memory-targeted agentic model comparison under those setups, not a universal advantage over every higher-precision model. The report explicitly treats aggressive quantization as lossy: the goal is quality per deployment budget, not perfect BF16 parity.

MCP-Atlas results use its 500-task public subset and a thresholded coverage metric; the report also records cases where measured competitor results differ from vendor reports. Preserve those splits and harness choices. Quantization calibration using on-policy terminal rollouts is distinct from terminal-task RL training.

The release is under OpenMDW-1.1. The card includes remote-code loaders and parser/plugin installation examples; none was installed or run here. Review those integrations and select a bounded local-data path before any actual deployment.
