MoE Routing — Gating, Top-K Selection, and Load Balancing

How a Mixture-of-Experts layer decides which experts process each token: the gating network math, how gradients flow through a discrete top-K selection, and the auxiliary loss that prevents expert collapse.

Prerequisites: SwiGLU → (each expert FFN is a SwiGLU block), Optimizers → (auxiliary loss is additive to the main training objective). Next: MoE Parallelism → — how EP distributes experts across GPUs once routing is defined.

1 · The routing problem

A standard Transformer FFN applies the same two weight matrices to every token — all parameters are active for every input. A Mixture-of-Experts (MoE) FFN replaces this with \(E\) independent expert FFNs and a learned router that selects only \(K\) of them per token (\(K \ll E\)).

This sparsity keeps per-token FLOPs constant (matching a dense FFN of equivalent width) while the total parameter count scales with \(E\). The router must satisfy three properties simultaneously:

  • Differentiable — trainable end-to-end by backpropagation alongside the expert weights.
  • Sparse — activating exactly \(K\) experts per token so FLOPs do not grow with \(E\).
  • Balanced — distributing tokens roughly evenly so no expert is under- or over-utilized.

Sparsity and balance are in tension: the simplest differentiable router (a softmax) is unconstrained and will concentrate tokens on a few experts. This page traces how that tension is resolved.

2 · The gating network

The router input is the token's hidden-state vector \(\mathbf{x} \in \mathbb{R}^D\) — the same post-attention, post-LayerNorm representation that would enter a dense FFN.

Linear projection to expert logits

A single weight matrix \(W_g \in \mathbb{R}^{D \times E}\) maps the token to one scalar score per expert:

\[\mathbf{s} = \mathbf{x} W_g \in \mathbb{R}^E\]

No bias is used in practice — keeping the gate centered stabilizes initialization. Each component \(s_i\) is the unnormalized affinity of this token for expert \(i\).

Softmax normalization

A softmax converts the logits into a probability distribution over all \(E\) experts:

\[p_i = \frac{\exp(s_i)}{\sum_{j=1}^{E} \exp(s_j)}, \qquad \mathbf{p} \in \mathbb{R}^E,\quad \sum_i p_i = 1\]

\(p_i\) is the router's confidence that expert \(i\) is the right expert for this token. The full vector \(\mathbf{p}\) is computed for every token on every forward pass, even though only \(K\) of the \(E\) experts will actually be invoked.

3 · Top-K selection and the layer output

Selecting K experts

The \(K\) experts with the highest router probability are selected:

\[\mathcal{S} = \operatorname{top-K}(\mathbf{p}) \subseteq \{1, \ldots, E\},\quad |\mathcal{S}| = K\]

This step is discrete: it returns a set of indices. It is not differentiable in the usual sense — there is no smooth path from \(\mathbf{p}\) through the index selection to the output. Section 4 explains how gradients still flow despite this.

Renormalization

The selected probabilities are renormalized to sum to 1 over the \(K\) chosen experts:

\[\tilde{p}_i = \frac{p_i}{\sum_{j \in \mathcal{S}} p_j} \quad \text{for } i \in \mathcal{S}\]

Without renormalization, the layer output would have a different total magnitude depending on which experts happened to be selected (e.g., selecting two low-probability experts would give a smaller-than-normal output). Renormalization makes the output magnitude consistent.

Layer output

The MoE layer output is a weighted sum of the selected expert outputs:

\[\mathbf{y} = \sum_{i \in \mathcal{S}} \tilde{p}_i \cdot \operatorname{FFN}_i(\mathbf{x})\]

Each \(\operatorname{FFN}_i(\mathbf{x})\) is a full SwiGLU expert block — with its own gate projection \(W^\text{gate}_i\), up projection \(W^\text{up}_i\), and down projection \(W^\text{down}_i\), all independent of every other expert.

The full forward pass, token by token
\(\mathbf{x} \xrightarrow{W_g} \mathbf{s} \xrightarrow{\text{softmax}} \mathbf{p} \xrightarrow{\text{top-}K} \mathcal{S} \xrightarrow{\text{renorm}} \tilde{\mathbf{p}} \xrightarrow{\sum \tilde{p}_i \cdot \text{FFN}_i} \mathbf{y}\) 
import torch, torch.nn.functional as F

def moe_forward(x, W_gate, experts, K=2):
    # x: [T, D]  W_gate: [D, E]  experts: list of E FFN modules
    T, E = x.shape[0], len(experts)

    # step 1: linear gate + softmax → router probabilities
    probs = F.softmax(x @ W_gate, dim=-1)               # [T, E]

    # step 2: select top-K experts per token, renormalize weights to sum to 1
    topk_w, topk_i = probs.topk(K, dim=-1)              # [T, K] each
    topk_w = topk_w / topk_w.sum(-1, keepdim=True)      # renorm

    # step 3: dispatch — route each token, accumulate weighted expert outputs
    # (production code replaces this loop with scatter/gather + batched matmul)
    out = torch.zeros_like(x)
    for k in range(K):
        for e in range(E):
            mask = topk_i[:, k] == e              # tokens routed to expert e at slot k
            if not mask.any():
                continue
            out[mask] += topk_w[mask, k:k+1] * experts[e](x[mask])
    return out

4 · Gradient flow through the gate

What is differentiable

The layer output \(\mathbf{y} = \sum_{i \in \mathcal{S}} \tilde{p}_i \cdot \operatorname{FFN}_i(\mathbf{x})\) is differentiable with respect to two sets of parameters:

  • Expert weights \(\{W^\text{gate}_i, W^\text{up}_i, W^\text{down}_i\}\): the gradient is \(\tilde{p}_i \cdot \frac{\partial \mathcal{L}}{\partial \mathbf{y}}\), scaled by the router weight for expert \(i\). Experts with higher \(\tilde{p}_i\) receive larger gradient updates.
  • Gate weights \(W_g\): the gradient flows through \(\tilde{p}_i\) → \(\mathbf{p}\) → \(\mathbf{s}\) → \(W_g\), which is a standard chain rule through the softmax.

Why discrete top-K doesn't block gradients

The top-K selection chooses indices — a discrete operation with no gradient of its own. But this is fine because we never need to differentiate through the index selection. The gate weights \(W_g\) enter the loss only through the values \(\tilde{p}_i\), which are continuous functions of \(W_g\) via the softmax. The gradient of the loss with respect to \(W_g\) is:

\[\frac{\partial \mathcal{L}}{\partial W_g} = \sum_{i \in \mathcal{S}} \frac{\partial \mathcal{L}}{\partial \tilde{p}_i} \cdot \frac{\partial \tilde{p}_i}{\partial \mathbf{p}} \cdot \frac{\partial \mathbf{p}}{\partial \mathbf{s}} \cdot \frac{\partial \mathbf{s}}{\partial W_g}\]

The sum is only over the \(K\) selected experts — unselected experts contribute zero. Each term is differentiable: \(\partial \tilde{p}_i / \partial \mathbf{p}\) is the Jacobian of the renormalization, and \(\partial \mathbf{p} / \partial \mathbf{s}\) is the softmax Jacobian.

The gradient blind spot

The key consequence: \(W_g\) receives gradient signal only through selected experts. If expert \(i\) is never selected for any token in the batch, no gradient flows to update \(W_g\) in the direction of expert \(i\). The gate gets no information about whether routing to expert \(i\) would have been better or worse.

This creates a positive feedback loop: an expert selected often → updated often → improves → selected more. Experts selected rarely → stagnate → selected less. Left unchecked, the model collapses to using a small subset of experts. Sections 5 and 6 address this.

5 · Load imbalance and expert capacity

Why imbalance emerges

At initialization, \(W_g\) is small and random. Small differences in the initial logits create small differences in \(p_i\). Because the softmax is winner-take-most for confident distributions, early training quickly concentrates tokens on a handful of experts. Those experts improve faster and pull in more tokens, reinforcing the imbalance.

At training scale with Expert Parallelism (EP), imbalance has a direct throughput cost: all EP ranks must wait for the most-loaded expert to finish before the AlltoAll combine can proceed. The throughput ceiling is \(1/\lambda\) of balanced, where \(\lambda = \max_i L_i / \bar{L}\) is the load factor.

Expert capacity buffer

To bound the runtime impact of imbalance, each expert is given a fixed-size buffer: the expert capacity. With \(T\) tokens in the batch, \(K\) experts per token, and \(E\) experts total, the average load per expert is \(T \cdot K / E\). The capacity is:

\[C = \left\lceil \frac{T \cdot K}{E} \cdot c \right\rceil\]

where \(c \ge 1\) is the capacity factor (typically 1.0–1.25 in training, 1.0–2.0 in inference). Tokens routed to a full expert are dropped: they bypass the expert FFN entirely and are passed through as-is via the residual connection, contributing zeros to the expert output.

Dropped tokens mean lost compute: the model processes those tokens through the rest of the layer with no expert update. With \(c = 1.25\), up to ~20% overflow capacity exists per expert. In a well-trained model with an auxiliary loss, actual drop rates should be near zero.
Capacity factor \(c\) Overflow buffer Memory cost Typical use
1.0None — any overflow is droppedMinimalWell-converged inference
1.2525% above average load+25% activation memory per expertStandard training
2.0Double average load+100% activation memoryEarly training or imbalanced domains

Dropping at the device level, and why \(c = 1.0\)

The table above treats \(c\) as a quality/memory dial. DeepSeek-V2 makes a different choice worth knowing: it caps at exactly \(c = 1.0\), applied per device rather than per expert — compute the average budget for each GPU, then drop that device's lowest-affinity tokens until the budget is met. Since the balance losses (§6) already push the load flat, the cap is a backstop rather than a routine event.

The interesting part is the argument for it. A capacity factor that differs between training and inference is a silent distribution shift: the model learns under one drop regime and serves under another. DeepSeek-V2 handles this by exempting ~10% of training sequences from dropping entirely, so the model always sees some fully-routed data, and then disables dropping at evaluation. The stated goal is not memory but consistency — being free to turn dropping on or off at deployment according to the efficiency you need, without the model noticing.

6 · Auxiliary load-balancing loss

The capacity buffer caps the runtime damage from imbalance but does not fix the root cause. An auxiliary loss is added to the training objective to actively push the router toward uniform expert utilization (Switch Transformer, Fedus et al. 2021).

The two terms

For a batch of \(T\) tokens, define two per-expert quantities:

fi — expert load fraction (discrete)

\(\displaystyle f_i = \frac{1}{T} \sum_{t=1}^{T} \mathbf{1}[i \in \mathcal{S}_t]\) — the fraction of tokens that were routed to expert \(i\). Computed with a hard indicator: non-differentiable. Treated as a constant in backprop.

Pi — mean router probability (differentiable)

\(\displaystyle P_i = \frac{1}{T} \sum_{t=1}^{T} p_{t,i}\) — the mean softmax probability that any token assigns to expert \(i\). Fully differentiable with respect to \(W_g\).

The loss

\[\mathcal{L}_\text{aux} = \alpha \cdot E \cdot \sum_{i=1}^{E} f_i \cdot P_i\]

The total training objective is \(\mathcal{L} = \mathcal{L}_\text{main} + \mathcal{L}_\text{aux}\), where \(\alpha\) is a small coefficient (0.001–0.01 in practice).

Why the product \(f_i \cdot P_i\) works

When expert \(i\) is overloaded (\(f_i\) large), the gradient \(\partial \mathcal{L}_\text{aux} / \partial P_i = \alpha E f_i\) is large. Backpropagating through \(P_i = \frac{1}{T}\sum_t p_{t,i}\) reduces the softmax probabilities \(p_{t,i}\) for all tokens, pushing the router to send fewer tokens to expert \(i\).

At perfectly uniform routing, \(f_i = 1/E\) and \(P_i = 1/E\) for all \(i\), giving:

\[\mathcal{L}_\text{aux} = \alpha \cdot E \cdot E \cdot \frac{1}{E} \cdot \frac{1}{E} = \alpha\]

Any deviation from uniform routing increases \(\mathcal{L}_\text{aux}\) above \(\alpha\), providing a gradient that pushes back toward balance. The \(E\) prefactor normalizes the loss so that the minimum value is always \(\alpha\) regardless of the number of experts.

\(f_i\) is a constant in the backward pass — only \(P_i\) provides gradients. This asymmetry is intentional: we use the hard routing decision to identify which experts need correction, then use the soft probabilities to perform the correction differentiably.

Beyond one level — balancing the hardware, not just the experts

\(\mathcal{L}_\text{aux}\) as written balances experts. That is a statement about the model. Once experts are sharded across GPUs, what actually stalls the step is imbalance between devices and between their message volumes — and perfectly balanced experts can still leave one GPU hot if the router happens to favour the experts that live on it.

DeepSeek-V2 keeps the \(\sum f \cdot P\) form and instantiates it three times, at three granularities. Partition the \(E\) routed experts into \(D\) device groups \(\{\mathcal{E}_1,\dots,\mathcal{E}_D\}\):

LevelLoad termProbability termWhat it preventsCoefficient
Expert \(f_i\) — fraction of tokens to expert \(i\) \(P_i\) Routing collapse; dead experts \(\alpha_1 = 0.003\)
Device \(f'_j = \frac{1}{|\mathcal{E}_j|}\sum_{i \in \mathcal{E}_j} f_i\) \(P'_j = \sum_{i \in \mathcal{E}_j} P_i\) One GPU doing more expert FLOPs than the rest \(\alpha_2 = 0.05\)
Communication \(f''_j\) — fraction of tokens sent to device \(j\) \(P''_j = \sum_{i \in \mathcal{E}_j} P_i\) One GPU receiving a disproportionate share of the AlltoAll \(\alpha_3 = 0.02\)

The communication term is the least obvious and the most revealing. Device-limited routing (see MoE Parallelism) bounds how many devices each token sends to — but nothing bounds how many tokens a device receives. The third loss closes that gap from the model side, pushing each device toward receiving its fair share of incoming hidden states.

Read the coefficients

\(\alpha_2 = 0.05\) and \(\alpha_3 = 0.02\) are an order of magnitude larger than the classic anti-collapse term \(\alpha_1 = 0.003\). In a large EP deployment the dominant load-balancing pressure is not "don't let experts die" — it is "don't let one rank become the straggler." The auxiliary loss has quietly become a systems knob.

All three losses distort the routing gradient — that is how they work, and it is a real cost: the router is being pulled away from the assignment it would otherwise choose. The successor line tries to remove that distortion by moving balance out of the loss: DeepSeek-V3 adds a per-expert bias to the selection scores only (leaving the mixture weights \(\tilde p_i\), and therefore the gradient, untouched), and later models solve for that bias in closed form instead of nudging it with a step size.

7 · Why attention heads need none of this

Multi-head attention is, on paper, the same situation this page has been fixing: \(H\) parallel modules with independently initialized weights and no assigned roles. Yet heads specialize on their own — previous-token heads, induction heads, positional heads — with no balancing loss, no router jitter, no capacity buffers. The difference is one structural bit: heads are assigned work by summation; experts are assigned work by selection. Everything in Sections 4–6 follows from that bit being flipped.

Follow the gradient of a losing module

Every head processes every token, so every head appears in the forward pass and receives a gradient on every step. A currently-useless head still feels the error the network is making — through its own slice of \(W_O\) — as a pull toward whatever structure remains unexplained. Its situation is self-correcting: being bad at everything is precisely what generates the signal to become good at something.

An unselected expert does not execute, so it receives exactly zero gradient — Section 4's blind spot. Being bad is what prevents it from ever improving: the situation is self-reinforcing. Both systems have the same rich-get-richer dynamic on initial noise; only MHA gives its losers a floor.

Why redundancy is penalized in one and invisible in the other

Head outputs co-occur on the same token inside one sum, \(\sum_h W_O^h\,\text{head}_h\). If two heads compute the same thing, the second one's marginal contribution is ~zero while residual error still flows through it — the gradient actively reallocates it to an unfilled niche. Two experts, by contrast, almost never process the same token: they occupy different parts of the input distribution, not the same sum, so no single token's loss can compare them or push them apart. Expert specialization is shaped only by the router's partition — and the router is trained myopically on "who is best right now."

The decisive asymmetry: which bad equilibrium is stable

MHA's failure state — all heads identical clones — is unstable: any perturbation off it is amplified, because de-duplicating reduces the loss and every head receives the gradient saying so. Training falls out of it for free. MoE's failure state — one expert takes all the traffic — is absorbing: the router's choice is locally correct (that expert genuinely is best by then), and the starved experts emit no gradient that could revise the verdict. One bad equilibrium repels, the other traps — which is why heads need no intervention while expert collapse must be prevented from ever being entered, not corrected afterward.

The control experiment: make the MoE dense

Run all \(E\) experts on every token, weighted by the full softmax — a "soft MoE." Collapse largely disappears, because every expert now always receives gradient, exactly like a head. But the point of MoE was to not run \(E-1\) of the experts. Sparse compute is the product; selection is the mechanism that buys it; starvation collapse is that mechanism's failure mode; the auxiliary loss is the tax that keeps it in check. Top-\(K\) routing is a bandit problem the network would otherwise solve greedily — the aux loss plays the role of forced exploration. Attention heads never face the bandit, because they never have to choose.

8 · Token-choice vs expert-choice routing

The description above is token-choice routing: each token independently picks its top-\(K\) experts. This is the most common scheme (GShard, Switch Transformer, Mixtral, DeepSeek-V2) but it is not the only one.

Routing scheme comparison
Token-choice (top-K per token)
  • Each token selects its \(K\) highest-scoring experts
  • Every token is always processed by \(K\) experts — no coverage gaps
  • Load imbalance: multiple tokens can select the same expert
  • Requires capacity buffer + auxiliary loss to manage
  • Natural AlltoAll dispatch: each token has a fixed target rank
Expert-choice (top-C per expert)
  • Each expert selects its \(C = T/E\) highest-scoring tokens
  • Guaranteed perfect load balance — every expert processes exactly \(C\) tokens
  • Coverage gap: a token might not be selected by any expert
  • Requires all-to-all probability exchange before selection
  • Less common; typically paired with shared always-on experts

Expert-choice routing solves the load-imbalance problem exactly but trades it for a coverage problem. In practice, token-choice with an auxiliary loss is the dominant approach in large production models because it guarantees every token is processed and has a simpler dispatch pattern for Expert Parallelism.

Expert granularity — the axis that isn't \(K\)

Everything above treats \(E\) and \(K\) as given and asks how to route. There is a prior question: how big should an expert be? Early MoE layers made each expert a full-width FFN and set \(K = 1\) or \(2\). DeepSeekMoE (and DeepSeek-V2 at scale) changes the answer — split each expert into \(m\) narrower ones and raise \(K\) to \(mK\). Activated parameters are unchanged, and so is total parameter count; only the granularity moves.

What that buys is combinatorial. The set of expert combinations a token can be assigned is \(\binom{E}{K}\), and splitting grows it violently:

Reachable expert combinations at fixed activated params
\[ \binom{16}{2} = 120 \qquad \longrightarrow \qquad \binom{160}{6} \approx 2.1 \times 10^{10} \]
Left: 16 full-width experts, top-2. Right: DeepSeek-V2 — 160 experts of FFN width 1536, top-6. Same FLOPs per token, eight orders of magnitude more distinct assignments.

The argument for why that matters is about specialization. A wide expert asked to serve many unrelated token populations must learn a blend of all of them; a narrow expert can commit to one, and the router composes six of them per token instead of picking one blend off the shelf. Granularity is therefore a lever on how sharply experts can specialize — independent of \(K\), independent of total size, and not visible anywhere in the gating math of §2–§3.

It is not free. Six selected experts instead of two means the token's targets span more GPUs, so the AlltoAll fan-out grows — which is exactly why fine-grained MoE arrived together with device-limited routing (cap each token's experts to at most \(M\) devices) rather than before it. Fine granularity is a routing idea that only ships with a communication fix attached. The trend has continued: later models run 8-of-256 and beyond.

Shared experts

The same architectures pair granularity with a small number of shared experts that activate for every token, regardless of routing. The router then selects \(K\) additional specialized experts on top (DeepSeek-V2: 2 shared alongside 160 routed).

The motivation is a direct consequence of fine granularity. Some knowledge — syntax, basic semantics, whatever every token needs — is required by every expert, so in a purely routed layer each of the 160 experts must learn its own redundant copy, spending capacity that was supposed to buy specialization. Isolating that common load in an always-on expert lets the routed ones keep only what distinguishes them. It also reduces the coverage risk of expert-choice and can stabilize training at large expert counts.

Shared experts have a systems side-effect worth knowing: because they run for every token, they need no dispatch — which makes their compute the natural thing to overlap with the AlltoAll for the routed experts. See MoE Parallelism.

9 · Summary

The gate

\(\mathbf{s} = \mathbf{x}W_g\) → softmax → \(\mathbf{p}\). One linear layer, \(D \times E\) params, produces a probability distribution over \(E\) experts per token.

Top-K & renorm

Select \(\mathcal{S} = \text{top-}K(\mathbf{p})\). Renormalize: \(\tilde{p}_i = p_i / \sum_{j \in \mathcal{S}} p_j\). Layer output: \(\mathbf{y} = \sum_{i \in \mathcal{S}} \tilde{p}_i \cdot \text{FFN}_i(\mathbf{x})\).

Differentiability

Top-K index selection is discrete, but gradients flow through the continuous renormalized weights \(\tilde{p}_i\) — only selected experts contribute to \(\partial \mathcal{L}/\partial W_g\).

Expert capacity

Cap each expert at \(C = \lceil TK/E \cdot c \rceil\) tokens. Overflow tokens are dropped (residual bypass). Capacity factor \(c = 1.25\) is common in training.

Auxiliary loss

\(\mathcal{L}_\text{aux} = \alpha E \sum_i f_i P_i\). Hard load \(f_i\) identifies overloaded experts; soft probability \(P_i\) carries the gradient that redistributes tokens.

Three levels of balance

The same \(\sum f \cdot P\) form applied to experts, devices, and received message volume. In DeepSeek-V2 the two hardware terms carry ~10× the coefficient of the anti-collapse term.

Granularity

Splitting \(E\) experts into \(mE\) narrower ones and raising \(K\) to \(mK\) holds FLOPs fixed while growing reachable combinations \(\binom{E}{K}\) by orders of magnitude — a specialization lever independent of \(K\).

Rich-get-richer fix

Without the aux loss, popular experts improve faster and attract more tokens. The aux loss adds opposing pressure: overloaded experts get penalized until routing spreads out.

Selection vs summation

Attention heads self-organize with no machinery: every head runs on every token, so losers keep getting gradient and redundancy is penalized in the shared sum. Top-\(K\) selection removes both properties — balance must be legislated.
