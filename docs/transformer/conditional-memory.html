Transformer & Pretraining

Conditional Memory

N-gram embedding tables as a second sparsity axis: parameters you address with a hash instead of a router, which is why they cost no FLOPs, live in host memory, and — as Qwen3.8-Next's ablations show — are not interchangeable with experts.

Mixture-of-Experts is how a Transformer grows its parameter count without growing its per-token compute: a router picks \(K\) of \(E\) FFNs, and the other \(E-K\) sit idle. That is conditional computation — the sparsity decides which FLOPs to run. This page is about the other way to be sparse. Some of what a language model stores is not a computation at all but a lookup: the continuation of a fixed phrase, the identity of a named entity, the gloss of a rare token pair. A table indexed by the last few tokens answers those in one memory read. DeepSeek's Engram paper named this axis conditional memory; Qwen3.8-Flash-Next ships it at scale, with 51B parameters of n-gram tables held off the accelerator alongside a 125B-parameter MoE backbone, and — more usefully for understanding it — publishes the ablations that show what those tables do and do not buy.

1. The Premise — Parameters Without FLOPs

The Engram paper's framing is the sharpest: "while Mixture-of-Experts scales capacity via conditional computation, Transformers lack a native primitive for knowledge lookup, forcing them to inefficiently simulate retrieval through computation." A pattern that is genuinely a table — this 3-gram means that — still has to be reconstructed by attention heads and FFN matrices, spending FLOPs and early-layer depth on work a hash map would do for free.

Every Transformer already has exactly one lookup table: the input embedding, indexed by a single token id. N-gram embeddings generalize it. Instead of one row per token, keep tables keyed by the short n-grams ending at each token, and add what they return to the token's representation. Two properties follow from the key being a deterministic function of the token ids, and both matter more than the modeling idea itself:

  • Zero FLOPs per parameter. A table of a billion rows costs the same per token as a table of a million rows: hash, fetch one row, add. Capacity scales with parameter count while per-token compute stays flat — the Qwen report's phrase is "negligible additional per-token FLOPs and latency."
  • The address is known before the forward pass starts. A routed expert's identity is computed in flight, from a hidden state that does not exist until the preceding layers have run. An n-gram key depends only on the input tokens. That is what makes the tables offloadable to host memory and prefetchable — Section 5.
Two ways to be sparse
Conditional computation (MoE experts)

A learned router selects which FFNs run. Selection is content-dependent and computed mid-forward. Each selected parameter costs FLOPs. Needs balancing machinery because the router can collapse.

Conditional memory (n-gram tables)

A fixed hash of the last \(n\) token ids selects which rows are read. Selection is known from the input. Each parameter costs a memory read, not a multiply. No router, so nothing to balance or collapse.

The last cell deserves emphasis because it is the mirror image of everything on the MoE routing page. There, discrete learned selection buys sparse compute at the cost of a gradient blind spot, an auxiliary loss, and routing instability. Hashed selection is discrete too, but it is not learned: the loss never has to shape the partition, only the contents of the rows the partition lands on. What you give up is the ability to route by meaning rather than by surface form — which is exactly why the two axes end up complementary rather than competing (Section 4).

2. The Mechanism

The Qwen report's own description is one sentence: "short n-grams ending at each token serve as keys into embedding tables, and the retrieved vectors augment the corresponding token representation." Unpacked, with the Engram module as the reference design the report cites:

Step A — Form the keys

For token position \(t\), take the n-grams that end there — the bigram \((x_{t-1}, x_t)\), the trigram \((x_{t-2}, x_{t-1}, x_t)\), and so on up to the chosen maximum order. Each is a deterministic function of token ids only; nothing about the hidden state enters.

Step B — Hash into tables

Each n-gram is mapped to a row index by a fixed hash. In Engram, "each head \(k\) maps the compressed context to an index within an embedding table \(E_{n,k}\) (of prime size \(M_{n,k}\)) via a deterministic function," and the retrieved embeddings across orders and heads are concatenated. The table sizes are the capacity knob: Qwen quotes them as multiples of its 250K base tokenizer vocabulary, and the ablations run from 5× to 200× — roughly 1.25M to 50M slots. Since the address space is far smaller than the number of distinct n-grams in a corpus, rows are shared by collision; the table is a learned, lossy hash map, not a dictionary.

Step C — Fuse into the residual stream at one layer

The retrieved vector is added to the token's representation at a single layer. Engram does this with a gated read: "the current hidden state \(\mathbf{h}_t\) — which has aggregated global context via preceding attention layers — serves as a dynamic query, while the retrieved memory \(\mathbf{e}_t\) serves as the source for both key and value projections," and the output is scaled by a gate \(\alpha_t\). Qwen's optimizer section confirms the same shape — it lists "the key/value projection in N-gram embedding layers" among the matrices it trains with Muon — so the layer is not a bare add but a small, gated read whose weights live on the accelerator while the table does not.

Qwen3.8-Flash-Next, as shipped
One n-gram embedding layer, placed at Layer 2 of the backbone. 51B parameters of tables, held off the accelerator and prefetched from host memory, next to a 125B-parameter (6B activated) MoE backbone.

Note the ratio. The tables are 40% as large as the entire backbone, and they contribute zero to the "6B activated" figure — which is why the report can report them as a separate line, "# N-gram Embedding Params: 51B", in its model comparison table. The activated-parameter count measures conditional computation; conditional memory has to be counted on its own axis.

3. Where to Put It

If the table is one layer, which layer? The report ablates placement under a fixed total n-gram parameter budget, at 300 tokens per active parameter, with single-layer variants at shallow (1–4), intermediate (10, 15) and deep (25) positions, plus two-layer splits of the same budget (Table 7, downstream average over nine benchmarks):

Four readings, all the report's own:

  • No depth regime dominates. Loss sits in a 0.004 band from Layer 1 to Layer 25. The first two layers are strongest downstream, but intermediate and deep placements "remain competitive."
  • Splitting the budget across layers buys nothing consistent. The 2 + 25 split has the lowest loss of all (1.540) and does not beat single Layer 2 downstream. "A single N-gram embedding layer is sufficient."
  • Placement is insensitive to the mixer. The relative ordering of placements is similar whether the backbone's token mixing is full attention or Gated DeltaNet.
  • The tie is broken by systems, not loss. Layers 1, 2 and 25 are indistinguishable at 1.541. The report picks Layer 2 "allowing host-memory prefetching to overlap with the computation of the first layer."

That the answer is "almost anywhere" is itself informative. A lookup keyed on surface n-grams supplies information the network can absorb at any depth; the modeling gain does not depend on where the injection happens, so the choice is free to be made on latency grounds. Engram's paper reads the early-layer benefit mechanistically — the module "relieves the model of the early stages of feature composition," effectively deepening the network — which is consistent with Layers 1–2 leading on benchmarks, but the Qwen numbers say the effect is small relative to the total gain.

4. Experts vs. Memory Are Not Fungible

The interesting question is not whether n-gram tables help — every row in Table 7 beats the baseline — but whether they are the same kind of parameter as an expert. If they were, a fixed parameter budget would have an optimal split, and you would find it by trading experts for table slots. Engram formulated this as the "Sparsity Allocation" problem and reported a U-shaped scaling law: with \(\rho\) the fraction of the sparse budget given to MoE, "reallocating roughly 20%–25% of the sparse parameter budget to Engram yields the best performance," with the optimum stable at \(\rho \approx 75\%\)–\(80\%\) across the regimes they tested. Meituan's LongCat-Flash-Lite pushes further, putting over 30B of 68.5B parameters into embeddings and reporting that it "surpasses parameter-equivalent MoE baselines."

And then the other columns decline to agree. Out-of-domain "uncheatable" perplexity barely moves (5.54–5.59). MMLU is highest with no tables at all. Engram, at 27B, reports the opposite downstream picture against a "strictly iso-parameter and iso-FLOPs MoE baseline": MMLU +3.4, CMMLU +4.0, BBH +5.0, ARC-Challenge +3.7, HumanEval +3.0, MATH +2.4. The two labs agree on the loss-level optimum and disagree on whether it survives to benchmarks. The Qwen report does not explain the discrepancy, and neither source documents enough about the other's setup to attribute it — so treat "trade experts for memory" as an open question, not a settled win in either direction.

Loss falls monotonically, 1.585 → 1.553 → 1.541 → 1.534 → 1.526, with no sign of stopping. The benchmarks split into two populations. Most of them take a large step at 20× and then saturate or fluctuate: GSM8K and MATH peak at 20× and drift down by 200×; MMLU gains two points and flattens. The Chinese benchmarks are the exception — C-Eval climbs 66.91 → 74.94 and CMMLU 68.10 → 73.24, improving at every step. The report does not offer a mechanism, and this page will not invent one; the pattern is what it is: more table capacity keeps lowering the loss, and only some downstream capabilities keep cashing that in.

This is the headline the report chose for its abstract — "enlarging the n-gram vocabulary lowers loss monotonically while downstream accuracy saturates" — and it is the strongest argument against reading conditional memory off a loss curve alone. The parameter is cheap enough to scale indefinitely, and loss will reward you for doing so. What the extra rows are learning past ~50× looks, on this evidence, like something the English-centric benchmark suite does not measure.

What did not work

The report also lists the parameter-efficiency tricks it tried on the tables and dropped, all with "no consistent performance gains" under its recipe: token normalization for vocabulary compression (Engram's approach), non-uniform allocation of slots across n-gram orders, and frequency-based partitioning of embedding slots. The shipped design is the plain version — uniform, unnormalized, hashed — with the size dial turned up.

5. The Systems View — Why the Tables Can Leave the GPU

Everything that distinguishes conditional memory operationally comes back to the address being a function of token ids. Consider what an inference engine knows and when:

What has to be resident on the accelerator
Routed expert

Which \(K\) of \(E\) experts a token needs is known only after the router at that layer runs on that token's hidden state. Every expert must be reachable at that moment. Prefetching is impossible in principle; the route does not exist yet.

N-gram row

Which rows a token needs is known the instant the token id is known — before Layer 1 runs in prefill, and the instant the previous token is sampled in decode. The fetch can be issued asynchronously and its latency hidden behind compute.

Engram spells out the consequence: deterministic addressing "naturally decouples parameter storage from computation," so "the system can asynchronously retrieve embeddings from abundant host memory via PCIe," with the module "placed at specific layers" to mask the transfer. Their measurement: offloading a 100B-parameter table costs a peak 2.8% throughput on an 8B backbone. Qwen's Layer-2 placement is the same argument applied — Layer 1's compute is the window the prefetch hides in — and the report's Figure 1 caption states it as a property of the architecture: the n-gram layer "scales capacity off the accelerator via host-memory prefetching."

Per token, the resident cost is one row per (order, head) — a few kilobytes fetched over PCIe — against a table that would otherwise occupy more HBM than the whole activated model. This is what "parameters that cost nothing" means in practice: not that they are free to train, but that they do not compete with the KV cache and the experts for the memory that bounds decode batch size (KV cache page for why that memory is the scarce resource).

Training the tables

Qwen trains the backbone with Muon and applies it to "the two-dimensional weights that genuinely act as linear maps" — including the key/value projections inside the n-gram layer. The tables themselves are excluded: "the n-gram embedding table runs on Adam with weight decay disabled." The report gives no further reason, but the same treatment goes to the input embeddings (AdamW, no Muon), and the natural reading is that an embedding table is not a linear map — each row is an independent parameter that receives gradient only on the steps its n-gram appears — so orthogonalizing its "update matrix" is meaningless, and a per-step weight decay would shrink rarely-seen rows toward zero between the sparse updates that are the only signal they ever get.

6. The Field Converging

Qwen3.8-Next is the most detailed public ablation, not the first instance. The report's own related-work list reads as a timeline of the same idea arriving from several directions:

  • Engram — DeepSeek, "Conditional Memory via Scalable Lookup: A New Axis of Sparsity for LLMs" (Jan 2026): the framing, the Sparsity Allocation problem, the 27B result, the host-memory prefetch argument.
  • LongCat-Flash-Lite — Meituan, "Scaling Embeddings Outperforms Scaling Experts in Language Models" (Jan 2026): 68.5B total, ~3B activated, over 30B in embeddings.
  • Gemma 3n Per-Layer Embeddings — Google DeepMind, 2025 (model overview): the unigram, per-layer form of the same offloadable-embedding idea.
  • RWKV-8 DeepEmbed — RWKV architecture wiki, 2025.
  • STEM — "Scaling Transformers with Embedding Modules" (Sadhukhan et al., 2026).
  • L3: Large Lookup Layers — Tseng & De Sa, ICML 2026.
  • X-GRAM — "Beyond N-gram: Data-aware X-GRAM Extraction for Efficient Embedding Parameter Scaling" (2026).
  • N-Grammer — "Augmenting Transformers with Latent n-grams" (2022): the pre-MoE-era ancestor.

The convergence is on the systems property more than the modeling one. Latent n-gram features are a 2022 idea; what changed in 2025–26 is that frontier labs are HBM-bound at decode and began treating host memory as a tier for parameters — and the only parameters that can live there are the ones whose address is known in advance.

7. Summary

Premise

MoE selects FLOPs; a table selects rows. Transformers have no native lookup primitive, so table-shaped knowledge gets simulated with computation.

Mechanism

Hash the n-grams ending at each token into tables (5×–200× the 250K vocab), concatenate the rows, fuse via a gated K/V read at one layer.

Placement

Loss is flat from Layer 1 to 25; splitting the budget gains nothing; mixer-agnostic. Qwen picks Layer 2 so the prefetch hides behind Layer 1.

Not fungible

Trading experts for slots finds a loss optimum at 10× (25%) but no downstream gain. "Distinct roles" — so Qwen keeps the MoE and adds 51B of tables on top.

Loss ≠ benchmarks

20V → 200V: loss 1.585 → 1.526 monotonically; most benchmarks saturate after 20×; C-Eval and CMMLU keep climbing.

Systems

Address = f(token ids) → tables in host memory, asynchronous prefetch, negligible latency. Experts cannot do this: their route is computed in flight.

Optimizer

K/V projections on Muon; the table on Adam, no weight decay — an embedding row is a sparsely updated parameter, not a linear map.

No router

Hashed selection is discrete but not learned: no gradient blind spot, no aux loss, no collapse — and no routing by meaning either.
