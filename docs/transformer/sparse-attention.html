Sparse Attention

Attend to a thousand entries, not a million: static patterns, learned selection, and the lightning indexer — the cheap scoring pass that lets DeepSeek's models pick what full attention gets to read.

Softmax attention reads everything: each new token's query is scored against every cached entry, every step. FlashAttention makes that read fast, and MLA makes each entry small — but neither changes the count. At a million tokens of context, "read everything" is the budget item that dominates decode, and the empirical observation that motivates this whole page is old and robust: trained attention distributions are already sparse. For most queries, a few hundred entries carry nearly all the probability mass. Sparse attention architectures try to find those entries without paying for the rest.

1. The Design Space

Four families, distinguished by who decides what gets read, and when:

FamilyMechanismExamplesWeakness
Static patterns Fixed, content-blind masks: sliding windows, strides, global tokens Longformer, BigBird, Mistral's SWA A content-dependent long-range link (page 3 cites page 700) is invisible unless the pattern happens to cover it
Cache eviction Permanently delete "unimportant" entries as decode proceeds H2O, StreamingLLM, SnapKV Lossy and irreversible — a deleted entry cannot matter later, and "later" is exactly what long contexts are for
Learned selection Keep everything; a trained scorer picks top-\(k\) entries per query NSA, DSA (V3.2), CSA (V4), Quest Adds a scoring pass and a second model component that must be trained to agree with attention
Sequence compression Merge runs of tokens into single entries before caching V4's CSA (4:1) and HCA (128:1) Individual-token resolution at long range is gone by construction; needs a raw-token window for local precision

The modern DeepSeek line combines the last two: learned selection is the core mechanism (this page), and V4 layers compression underneath it (the V4 page). The critical property separating selection from eviction: selection is per-query and reversible — an entry ignored by this token is fully available to the next one. Nothing is forgotten; things are merely not read.

2. NSA — The Trainable-Sparsity Template

NSA (Native Sparse Attention, DeepSeek, early 2025) established the template that later designs refine. Each query runs three branches over the same history, and a learned per-query gate blends them:

  • Compression branch — attend to block-level summaries of the history (one learned summary per block of tokens): cheap global gist.
  • Selection branch — score blocks, pick the top-\(n\), attend to the raw tokens inside the winners: sharp retrieval where it matters.
  • Sliding-window branch — attend to recent raw tokens: local syntax, guaranteed.

Two ideas here outlived the specific design. First, block-granular sparsity: selecting contiguous blocks instead of scattered tokens keeps memory reads coalesced, which is what makes sparse attention actually faster on a GPU rather than merely FLOP-count-smaller (memory-hierarchy page for why scattered reads lose). Second, native trainability: NSA is trained sparse from scratch — the model learns to concentrate its attention within what the sparse machinery can deliver, instead of having sparsity imposed post-hoc on a dense-trained model and hoping the approximation holds.

3. DSA — The Lightning Indexer

DSA (DeepSeek Sparse Attention, shipped in V3.2-Exp) strips the template to one mechanism: a single cheap scoring pass — the lightning indexer — followed by top-\(k\) selection, feeding the model's ordinary MLA core attention.

Step A — Score every entry, cheaply

For query token \(t\) and each cached position \(s\), a small set of indexer heads computes

\[ I_{t,s} \;=\; \sum_{j=1}^{H_I} w_{t,j}\cdot \mathrm{ReLU}\!\bigl(q^{I}_{t,j}\cdot k^{I}_{s}\bigr) \]

— \(H_I\) indexer heads (dozens, not hundreds) with small head dim, per-head weights \(w_{t,j}\) produced from the query token, ReLU keeping scores sparse and cheap. The whole pass runs in very low precision (FP8 in V3.2; V4 pushes the QK compute to FP4), because the indexer only has to get the ranking roughly right — its scores never touch the value path.

Step B — Keep the top-k, attend normally

The \(k\) highest-scoring entries (V3.2: \(k = 2048\)) form the query's shortlist; core attention — full-precision, full-width, softmax — runs over the shortlist only. Everything else about the layer is unchanged: the sparse machinery is a filter in front of attention, not a new attention.

The economics: an indexer head-set costing ~1/15th of core attention per entry scans all \(T\) entries, so that core attention — the expensive part — touches only \(k\) of them. The total is \(c_{\text{idx}} \cdot T + c_{\text{core}} \cdot k\): still linear in \(T\), but with a slope more than an order of magnitude shallower, and with the expensive term now constant.

4. How the Indexer Learns to Agree with Attention

The top-\(k\) is a hard, non-differentiable selection, and the indexer's scores never enter the output — so where does its gradient come from? Not through the selection at all. DSA trains the indexer by distillation from the attention it serves:

  1. Dense warm-up. Run attention dense (no selection). Train the indexer — alone — to match the real attention distribution: KL from the (head-summed) attention scores to the indexer's softmaxed scores. The main model is briefly frozen from the indexer's perspective; the indexer is learning to predict where attention will land.
  2. Sparse stage. Switch selection on. The main model trains normally — its gradients flow through the \(k\) selected entries only, exactly like attention over a shorter sequence — and the indexer keeps distilling, now against the attention distribution over the selected set.

Both failure directions are self-limiting: if the indexer drifts from what attention wants, the distillation loss pulls it back; if attention starts needing entries the indexer suppresses, those entries' scores rise in the (dense-computed) target the moment they get selected again. What is not self-limiting is a region the indexer never selects and attention never sees — the miss that stays a miss. That residual risk is why V4 pairs its selective layers with dense-over-summaries layers as a backstop (§6).

5. What It Costs

Selection makes the expensive part constant; the cheap part inherits the slope. Per-token decode attention cost vs. context length (illustrative constants: MLA ≈147K MACs/entry across 128 heads; indexer ≈8K MACs/entry across 64 small heads; \(k = 2048\)), log–log. DSA crosses below dense around \(T \approx 2k\) and settles at ≈18× cheaper: past ~100K tokens essentially all remaining cost is the indexer's linear scan, while full-precision attention (dashed) is a flat floor. That readout is the setup for V4: once the indexer is the cost, the next win must shrink what the indexer scans — which is exactly what scoring 4:1 compressed summaries does.

6. From Tokens to Summaries — Where V4 Takes It

V4's CSA keeps the DSA skeleton and changes the unit of selection: the indexer scores 4-token summaries instead of tokens, so its scan covers \(T/4\) entries, and \(k\) halves (2048 → 1024) because each selected entry now carries four tokens' worth of content. Both terms of the cost shrink. The mechanics of the compression, the shared-KV core attention behind it, and the 128:1 HCA layers that guarantee nothing is ever fully invisible are on the DeepSeek-V4 page — from this page's perspective, V4 is the answer to the plot above: after DSA, the indexer is the bottleneck, so compress its input.

Compressing the scan is not the only answer. Within weeks of each other in 2026, GLM-5.2 ("IndexShare") and Meituan's LongCat-2.0 ("Cross-Layer Indexing") independently attacked the same bottleneck along the depth axis: one indexer's top-\(k\) selection is computed once and reused by every sparse layer in a group of four, on the observation that adjacent layers' attention concentrates on heavily overlapping token sets. GLM-5.2 reports ≈2.9× lower per-token attention FLOPs at 1M context from this alone (details on the GLM-5 page). Amortize the indexer across depth, or compress what it scans along the sequence — by mid-2026, the indexer's linear term is the most-attacked quantity in frontier attention design.

7. Selection vs. State — the Two Long-Context Bets

Failure modes, side by side
Learned selection (DSA/CSA)

Exact attention — conditional on the indexer surfacing the right region. Failure is a retrieval miss: rare, discrete, potentially unrecoverable within a layer. Memory still grows with \(T\) (shallower slope).

Recurrent state (linear attention hybrids)

Constant memory, no indexer to miss — but the state is lossy always: everything is stored approximately, and verbatim long-range recall needs the hybrid's few full-attention layers. Failure is gradual blur, not a discrete miss.

These are the two live philosophies in 2026's frontier open models — DeepSeek-V4 on the selection side, Qwen3.5 and Kimi K3 on the state side (hybrid attention page for that design pattern). Notably, each camp imports the other's insurance: V4 interleaves dense-over-summaries layers (state-like unconditional coverage), and the hybrids keep a few exact softmax layers (selection-like precision). Neither trusts its own failure mode unhedged.

8. Summary

Premise

Trained attention is already sparse — a few hundred entries carry the mass. Find them cheaply.

Mechanism

\(I_{t,s} = \sum_j w_{t,j}\,\mathrm{ReLU}(q^I_{t,j}\cdot k^I_s)\) — low-precision scoring pass, top-\(k\) shortlist, full attention on the shortlist.

Training

No gradient through the top-\(k\): the indexer distills from attention's own distribution (dense warm-up → sparse stage).

Cost shape

\(c_{\text{idx}}T + c_{\text{core}}k\): the expensive term goes constant; the cheap scan owns the slope — and becomes the next target.

Vs. eviction

Per-query and reversible: unselected entries stay cached, unlike H2O-style deletion.

The lineage

NSA (three branches) → DSA (one indexer, V3.2) → CSA (indexer over 4:1 summaries, V4).
