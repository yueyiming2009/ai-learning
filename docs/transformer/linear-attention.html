Linear Attention

Remove the softmax and attention collapses into a fixed-size recurrent state — O(1) memory and compute per decoded token. What you gain, what you lose, and the fixes that led to RetNet, Mamba-2, and Gated DeltaNet.

The Basic Idea

Softmax attention answers every query by scoring it against every key seen so far. That exactness has a price that grows with context length \(T\): the KV cache stores \(O(T)\) vectors, and each decoded token reads all of them — \(O(T)\) memory traffic and FLOPs per token.

Linear attention asks: what if the similarity score were a plain dot product, with no softmax wrapped around it? Then — by nothing deeper than associativity — the entire history can be pre-summed into one fixed-size matrix \(S\), updated once per token and never growing. Attention becomes an RNN with a matrix-valued hidden state:

\[ S_t = S_{t-1} + k_t v_t^\top, \qquad o_t = S_t^\top q_t . \]

The catch: a \(d_k \times d_v\) matrix can only hold so much. The page follows that trade end to end — the two-step derivation (§1), the RNN reading of the result (§2), the three computational forms that make it practical (§3), what a fixed-size memory costs you (§4), and the escalating fixes — decay, gates, the delta rule, hybrids — that every modern variant (RetNet, GLA, Mamba-2, Gated DeltaNet) is built from (§5). A closing aside (§6) answers the theory question the derivation raises: couldn't a cleverer feature map have kept the softmax? Skim it freely — nothing later depends on it.

1. The Derivation — Two Steps and a Cleanup

Every attention mechanism is the same template with one slot to fill — a scoring function \(\mathrm{sim}(q, k)\) that answers "how much should this query attend to that key?":

\[ o_t = \frac{\sum_{j \le t} \mathrm{sim}(q_t, k_j)\, v_j}{\sum_{j \le t} \mathrm{sim}(q_t, k_j)} . \]

Softmax attention fills the slot with \(\mathrm{sim}(q,k) = \exp(q^\top k)\) (scale absorbed into the vectors). As a similarity, \(\exp\) is excellent — the problem is its algebraic shape. \(\exp(q^\top k)\) is a joint function of the pair: were it separable as \(g(q)\,h(k)\), taking logs would equate the interaction \(q^\top k\) with a sum of two independent terms — impossible. Because query and key are tangled inside the exponential, nothing about the history can be pre-computed; every query must revisit every stored key, and that is exactly the \(O(T)\)-per-token cost of softmax decoding.

So the whole derivation is one move: replace the similarity with one that factors. Everything else follows mechanically.

Step A — Choose a factorizable similarity

Pick a feature map \(\phi\) and score with \(\mathrm{sim}(q,k) = \phi(q)^\top \phi(k)\):

\[ o_t = \frac{\sum_{j \le t} \bigl(\phi(q_t)^\top \phi(k_j)\bigr) v_j}{\sum_{j \le t} \phi(q_t)^\top \phi(k_j)} \]

Katharopoulos et al. (2020) used \(\phi(x) = 1 + \mathrm{elu}(x)\) to keep scores positive; modern variants mostly use the identity, i.e. score with the raw dot product \(q^\top k\). (Whether some \(\phi\) could approximate the dropped \(\exp\) is the §6 aside — the derivation doesn't need it.)

Step B — Pull the query out of the sum (associativity)

\(\phi(q_t)\) does not depend on the summation index \(j\), so it factors out of both sums:

\[ o_t = \frac{\phi(q_t)^\top \overbrace{\textstyle\sum_{j \le t} \phi(k_j)\, v_j^\top}^{S_t}} {\phi(q_t)^\top \underbrace{\textstyle\sum_{j \le t} \phi(k_j)}_{z_t}} \;=\; \frac{S_t^\top \phi(q_t)}{z_t^\top \phi(q_t)} \]

The sums over \(j \le t\) are still there — but the query is no longer inside them, so they are pure functions of the history: the same two objects, \(S_t\) (a \(d_k \times d_v\) matrix) and \(z_t\) (a \(d_k\) vector), serve every present and future query. Three consequences:

  • Fixed size. \(S_t\) is \(d_k \times d_v\) numbers whether ten tokens or a million went in. No stored \(k_j, v_j\), no cache that grows.
  • Incremental update. \(S_t = S_{t-1} + \phi(k_t)\,v_t^\top\) — a prefix sum, one rank-1 addition costing \(O(d_k d_v)\) per token. No revisiting the past.
  • "Independent of \(T\)" means size and cost, not value. \(S_t\)'s entries of course depend on the whole history — encoding it is \(S_t\)'s entire job.
Step C — Drop the denominator (the modern cleanup)

Modern linear-attention layers discard \(z_t\) entirely: the normalizer is numerically fragile (it can pass near zero) and turns out to be unnecessary if the output is normalized another way. That "another way" is the per-head gated RMSNorm that Qwen3-Next applies to the readout — the norm plays the softmax denominator's role, after the fact. From here on the equations use the un-normalized form, with \(\phi\) absorbed into \(q, k\).

2. Attention as an RNN

What Step B produced is worth staring at — attention has become a recurrence:

Result — linear attention, recurrent form
\[ S_t = S_{t-1} + k_t v_t^\top, \qquad o_t = S_t^\top q_t \]

(feature maps absorbed into \(q, k\); denominator dropped per Step C)

Read it as an associative memory with a write operation and a read operation:

  • Write: the outer product \(k_t v_t^\top\) stores the association "key \(k_t\) ↦ value \(v_t\)" superimposed onto everything already in \(S\).
  • Read: \(S_t^\top q_t = \sum_{j \le t} (k_j^\top q_t)\, v_j\) retrieves a mixture of all stored values, weighted by how much each key aligns with the query — un-normalized attention weights.

Per decoded token this costs \(O(d_k d_v)\) compute and \(O(d_k d_v)\) memory — constant in \(T\). The comparison with the KV cache is stark:

softmax attention: KV cache = 2·T·d floats linear attention: state = d × d floats

The state never grows. Per-head decode-time memory (in K floats) versus context length, for head dimension \(d = 128\). The KV cache passes the fixed \(d \times d\) state at just \(T = 64\) tokens and keeps climbing — at a 32k context it is 512× larger, and every decoded token must read all of it. GQA shrinks the softmax line by a constant factor; it cannot change the slope.

3. One Mechanism, Three Computational Forms

The same equations evaluate three ways, and a production layer uses all three — this duality is the reason linear attention is practical at all:

FormComputationCostUsed for
Parallel \(O = \bigl(QK^\top \odot M\bigr)V\) with causal mask \(M\) \(O(T^2 d)\) Short sequences; identical to un-normalized attention
Recurrent \(S_t = S_{t-1} + k_t v_t^\top;\ o_t = S_t^\top q_t\) \(O(T\, d_k d_v)\), sequential Decoding — one rank-1 update per token
Chunked Split \(T\) into chunks of \(C\): exact parallel attention within a chunk + recurrent state carried between chunks \(O(T C d + T\, d_k d_v)\), matmul-heavy Training and prefill — tensor-core friendly

The chunked form is the workhorse: within a chunk, tokens attend to each other with dense matmuls (parallel form); the inter-chunk history arrives through the state (recurrent form). Sequence length enters only linearly, and all the heavy work is matrix multiplication. This is what chunk_gated_delta_rule computes in Qwen3-Next's prefill path — the full algorithm, including the decay and delta-rule cases, is derived on the chunkwise kernel page.

4. What You Lose — a Fixed-Size Memory Fills Up

Softmax attention is a lossless lookup: every key–value pair remains individually addressable forever. Linear attention compresses the whole history into \(d_k \times d_v\) numbers. Two distinct things break, and it pays to keep them separate: retrieval gets noisy (crosstalk), and selection gets soft (no winner-take-all).

Crosstalk: additive writes interfere

The write in §2 is a blind superposition — nothing is ever moved aside, nothing is ever removed. Retrieving a stored item therefore returns the item plus interference from everything else:

\[ S_T^\top k_i \;=\; \underbrace{(k_i^\top k_i)\, v_i}_{\text{what you wanted}} \;+\; \underbrace{\textstyle\sum_{j \ne i} (k_j^\top k_i)\, v_j}_{\text{crosstalk from every other item}} \]

Random directions in \(d\) dimensions overlap by \(\sim 1/\sqrt{d}\) on average, so crosstalk grows with the number of stored items: the memory gets noisier with every write. A related way to say it — the attention matrix \(\phi(Q)\phi(K)^\top\) has rank at most the feature dimension, while a softmax attention matrix is generically full rank; a \(T \times T\) pattern of sharply-selected entries with \(T\) far above the rank simply doesn't fit.

No winner-take-all: keys stop competing

Softmax makes keys compete: exponentiate, then renormalize, and a modest score gap becomes a near-one-hot winner. A factorized similarity is additive — every key contributes independently, and nothing suppresses the losers:

softmax: \(\sigma(\Delta)\), any base score linear, base score s = 1 linear, base score s = 4

Softmax can do winner-take-all; a factorized similarity cannot. Two keys compete for a query: the weaker scores \(s\), the stronger \(s + \Delta\). Softmax gives the winner a share \(\sigma(\Delta)\) of the readout — it saturates toward 1 exponentially fast and depends only on the margin \(\Delta\), not the base score. Normalized linear attention gives \((s{+}\Delta)/(2s{+}\Delta)\): it approaches 1 only harmonically, and the larger the base score, the flatter it gets. The losing key is never truly silenced — which, multiplied over thousands of keys, is exactly the crosstalk sum above.

Where this shows up in practice: recall-intensive tasks — exact retrieval over long context, in-context lookups, needle-in-a-haystack — are where linear attention measurably trails softmax. The gap is a capability gap of the mechanism, not an approximation error you can tune away; §5 is the field's response.

5. The Fix Ladder — Decay, Gates, Delta, Hybrid

Each fix targets the failure just derived: crosstalk accumulates because writes are additive and nothing is ever removed. The ladder escalates from "forget uniformly" to "overwrite precisely" to "stop pretending one matrix is enough":

  1. Decay (RetNet): \(S_t = \gamma S_{t-1} + k_t v_t^\top\) with a fixed \(\gamma \in (0,1)\) — old associations fade geometrically, bounding total interference at the price of a hard-coded recency bias.
  2. Gated decay (GLA, Mamba-2): \(S_t = \alpha_t\, S_{t-1} + k_t v_t^\top\) with \(\alpha_t\) computed from the input — the model decides when to forget.
  3. The delta rule (DeltaNet, Gated DeltaNet): stop adding blindly — read what the memory already predicts for this key and write only the correction, overwriting stale associations instead of superimposing onto them. Derived in full on the Gated DeltaNet page.
  4. Hybrid stacks (Qwen3-Next, MiniMax-01): accept that a fixed state can't do exact long-range recall, and interleave a few full-attention layers into a mostly-linear stack — Qwen3-Next runs 3 Gated DeltaNet layers for every 1 softmax-attention layer.

Note what the ladder does not do: none of these steps try to make the similarity behave more like \(\exp\). Modern variants keep the identity feature map and spend all their effort on the mechanism — which raises the obvious question the aside below answers: why did the field stop chasing the softmax kernel?

6. Aside — Couldn't a Better \(\phi\) Recover the Softmax?

Step A quietly replaced \(\exp(q^\top k)\) with \(\phi(q)^\top \phi(k)\) and moved on. This section is for the reader who stopped there and asked: is that replacement principled? Could a clever \(\phi\) make it exact, or nearly so? The answer is a nice piece of kernel theory — and it explains the design choice (identity \(\phi\), effort spent elsewhere) that §5 took for granted.

The kernel trick, forwards and in reverse

The classic (SVM-era) kernel trick: you want similarity measured on a rich feature expansion, but the expansion is huge — so keep it implicit and evaluate a closed form instead. Smallest example, degree-2 monomials in \(d = 2\):

\[ \varphi(x) = \bigl(x_1^2,\ \sqrt{2}\,x_1 x_2,\ x_2^2\bigr) \quad\Longrightarrow\quad \varphi(x)^\top \varphi(y) = (x^\top y)^2 . \]

Three features per side, or one squared dot product. \(\exp(q^\top k)\) is such a kernel taken to its limit — the Taylor expansion below exhibits it as the inner product of all tensor-power features at once — so softmax attention has been using the kernel trick all along, comparing two infinite feature expansions for the price of one exponential. Linear attention crosses the same equivalence in the opposite direction, because the expensive resource moved:

One equivalence, crossed in both directions
Kernel trick (SVM era)

The features are the expensive part (huge or infinite); data points are few. Escape: keep the features implicit, evaluate the closed-form kernel per pair. Explicit features → implicit kernel.

Reverse (attention era)

The kernel is cheap, but it couples every query–key pair — and \(T\) is the expensive part. Escape: choose explicit finite features so the sum over keys factors and is computed once. Implicit kernel → explicit features.

Classical kernel machines hit the same \(O(T^2)\)-in-samples wall and escaped it the same way — Rahimi & Recht's random features (2007), which Performer (below) re-runs on the softmax kernel. Which side of the equivalence you compute on depends only on which resource you have run out of.

Exactness needs infinitely many features

Expand the exponential as a Taylor series and each term factorizes on its own:

\[ \exp(q^\top k) = \sum_{n=0}^{\infty} \frac{(q^\top k)^n}{n!}, \qquad (q^\top k)^n = \bigl\langle\, q^{\otimes n},\, k^{\otimes n} \bigr\rangle , \]

so the exact feature map is \(\phi(x) = \bigl(1,\ x,\ x^{\otimes 2}/\sqrt{2!},\ x^{\otimes 3}/\sqrt{3!},\ \dots\bigr)\) — every polynomial degree at once, with the degree-\(n\) block alone costing \(d^n\) dimensions. Any finite \(\phi\) is therefore a compromise, and the design space is which compromise:

Feature mapIdeaFidelity to the exp kernel
Identity (RetNet, GLA, DeltaNet, …) Don't approximate — accept a plain bilinear similarity None intended; scores can go negative, no sharpening
\(1 + \mathrm{elu}(x)\) (Katharopoulos et al., 2020) Keep scores positive so the denominator is safe Shape-only; not an approximation of \(\exp\)
Taylor truncation (Based, 2024) Keep the series through degree 2: \(1 + q^\top k + \tfrac{(q^\top k)^2}{2}\) Exact for small logits; \(1 + d + d^2\) features
Random features (Performer, 2021) Monte-Carlo estimate of the kernel with \(m\) sampled features Unbiased; error \(\sim 1/\sqrt{m}\), worst where attention is sharp

Performer's random features make "approximating softmax" precise: an unbiased Monte-Carlo estimate of the kernel whose error shrinks as \(1/\sqrt{m}\) — but with a constant that grows exponentially in the logit magnitude, so it is accurate where attention is diffuse and unreliable exactly where attention is sharp. And sharpness is the point: §4 showed the properties that matter — full rank, winner-take-all competition — are structural, beyond any finite \(\phi\).

Hence the field's eventual answer: stop chasing \(\exp\) altogether. Accept a different similarity (identity \(\phi\)), and spend the modeling budget on the mechanism instead — decay gates, the delta rule, output normalization. That is precisely the §5 ladder, and it is why the modern accuracy question is a capability gap measured on recall tasks, not a kernel-approximation error.

7. Summary

The trick

Factorizable similarity → associativity → history pre-summed into \(S_t = \sum \phi(k_j) v_j^\top\)

The win

\(O(1)\) state and \(O(1)\) work per decoded token, vs \(O(T)\) for softmax attention

The cost

Fixed capacity: additive writes interfere and recall blurs as context grows

The fixes

Decay → gated decay → delta rule → hybrid stacks with a few softmax layers
