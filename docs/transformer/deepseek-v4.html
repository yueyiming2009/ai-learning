Model Architectures

DeepSeek-V4

The generation that retired MLA: attention over a million tokens by compressing the sequence itself — sparse selection over 4-token summaries, dense attention over 128-token summaries, and a Sinkhorn-constrained residual stream, trained with Muon on 33T tokens.

DeepSeek-V4 (preview release, April 2026) is DeepSeek's answer to a specific question: what does a transformer have to look like when every request may carry a million tokens of context? V3's answer to long context was MLA — shrink each token's cache entry. V4's answer is more radical: shrink the number of entries. The series ships in two sizes, both MIT-licensed with open weights:

Architecturally, V4 changes four things at once: the attention stack (CSA + HCA replace MLA), the residual stream (manifold-constrained hyper-connections), the optimizer (Muon becomes primary), and the numerics (FP4 expert weights via quantization-aware training). This page walks each one, in that order, because the attention redesign is what everything else serves.

1. Lineage — Three Answers to the Same Wall

The cost of softmax attention at decode is proportional to the number of cached entries: every new token reads the whole KV cache. Three DeepSeek generations attacked that constant from three different directions:

  • V2/V3 — compress the channel axis. MLA stores one low-rank 576-element latent per token instead of GQA-8's 2048. The per-entry cost shrinks 3.6×, but the entry count still grows one-per-token: at 1M tokens the cache is still ∝ \(T\).
  • V3.2-Exp — skip most entries. DSA (DeepSeek Sparse Attention) keeps every token's entry but lets each query attend to only the top-\(k\) of them, chosen by a cheap "lightning indexer" scoring pass. Core-attention FLOPs become constant in \(T\) — but the memory is untouched, and the indexer itself still scans all \(T\) entries.
  • V4 — store fewer entries in the first place. Compress runs of tokens into single cache entries — 4-to-1 in most layers (CSA), 128-to-1 in the rest (HCA) — and run the indexer and the attention over the compressed entries. Both memory and FLOPs now scale with \(T/m\), and MLA disappears entirely: there is no per-token latent left to cache.
Two compressions that sound alike but are orthogonal
MLA — channel compression (V2/V3)

Each token keeps its own cache slot; the slot gets narrower (2048 → 576 elements). Cache = \(T \times 576\). Exact attention over every token is still possible — nothing is merged.

CSA/HCA — sequence compression (V4)

Tokens share slots: 4 (or 128) consecutive tokens are summarized into one 512-dim entry. Cache = \(\tfrac{T}{4} \times 512\) (or \(\tfrac{T}{128}\)). Attention over individual distant tokens is now approximate by construction.

That last clause is the bet the whole architecture makes: most of a million-token history is only ever needed in summary. Two mechanisms hedge the bet — a sliding window of raw, uncompressed recent tokens in every layer (local precision), and the interleaving of two compression strengths (§3) so that what one resolution loses the other can still see.

2. CSA — Compressed Sparse Attention

CSA is a three-stage pipeline: compress the history, select from it, attend to the selection.

Step A — Compress: 4 tokens → 1 entry

Each run of \(m = 4\) consecutive tokens is reduced to a single 512-dimensional cache entry by a learned, softmax-weighted combination of the tokens' states, with learnable position-in-group biases. Two compression branches (\(C_a\), \(C_b\)) run with overlapping windows, offset from one another — so a phrase that straddles one branch's group boundary sits in the middle of the other's. Compression happens once per token-group at prefill and is cached; it is never recomputed.

Step B — Select: the lightning indexer, now over summaries

A lightweight scoring head — 64 indexer heads of dimension 128, ReLU activations, computed in FP4 — scores every compressed entry against the current query token. The top-\(k\) entries win (\(k = 1024\) for Pro, 512 for Flash) and only they enter core attention. This is V3.2's DSA mechanism — including its distillation-trained indexer — inherited almost verbatim, with one big difference: it now scans \(T/4\) summaries instead of \(T\) tokens, so the one remaining \(O(T)\) pass got 4× cheaper too.

Step C — Attend: shared-KV MQA over the shortlist

Core attention is multi-query: 128 query heads (Pro) share a single KV head of dimension 512, and each compressed entry serves as both the key and the value — one vector, read twice. Queries are produced low-rank from a compressed latent (\(d_c = 1536\), shared with the indexer's queries), per-head RMSNorm is applied to queries and to the KV entry, and two extras round out the softmax:

  • a sliding window of the last \(n_{\text{win}} = 128\) raw (uncompressed) tokens, always attended — local syntax never depends on the indexer;
  • a learnable per-head attention sink logit in the softmax denominator — the "attend to nothing" option, so heads with no relevant match aren't forced to smear probability over the shortlist.

The output side is also restructured: instead of one \(128 \cdot 512 \times d\) output projection, the 128 heads are split into 16 groups, each projected to a 1024-dim intermediate and then to \(d\) — a low-rank, grouped W_O that cuts the projection cost several-fold.

Everything the indexer never selects is still in the cache — selection is per-query, not a deletion. Two queries ten thousand tokens apart can shortlist entirely different regions of the history. This is what separates CSA from cache-eviction schemes (H2O, StreamingLLM): nothing is forgotten, only deprioritized per step.

3. HCA and the Interleaved Stack

HCA (Heavily Compressed Attention) is CSA's coarse sibling: \(m' = 128\) tokens per entry, non-overlapping, and no selection at all — the entry count is so small (a 1M-token history compresses to ~8K entries) that dense attention over all of them is affordable. Where CSA retrieves precisely from a shortlist, HCA reads a cheap global gist of everything.

Division of labor
CSA — precise, sparse

4:1 compression, indexer picks top-1024, MQA attends to those. Sharp retrieval — but only over what the indexer surfaces.

HCA — coarse, dense

128:1 compression, no indexer, attend to all entries. Blurry — but nothing in the history is ever invisible to it.

The stack interleaves them: V4-Pro opens with two HCA layers, then alternates CSA and HCA to the top. An indexer miss in a CSA layer is not fatal, because the adjacent HCA layers maintain unconditional (if low-resolution) access to the full history — the same "cheap global layers backstop the precise ones" logic that hybrid linear-attention stacks use, with compression strength in place of state size (compare Qwen3.5 and Kimi K3, which interleave linear-attention layers with full-attention layers in a 3:1 ratio). V4-Flash replaces its first two layers with pure sliding-window attention instead — at 13B active params, the cheapest possible opening.

Every scheme is still linear in \(T\) — a straight line of slope 1 here — but each compression drops the line by its factor: MLA sits 3.6× below GQA-8, CSA 4× below MLA, HCA 32× below CSA. At 1M tokens per layer: GQA-8 ≈ 4.1 GB, MLA ≈ 1.2 GB, CSA ≈ 256 MB, HCA ≈ 8 MB. Averaged over V4-Pro's interleaved stack and with FP8 storage of the non-RoPE dims, the paper's official figure is a cache ≈ 2% of a BF16 GQA-8 baseline — and 10% of V3.2's MLA cache.

4. Positions — Partial RoPE and the −i Output Trick

Only the last 64 of each 512 dimensions carry RoPE (\(\theta = 10{,}000\); compressed entries use a longer-wavelength \(\theta = 160{,}000\)), with YaRN ×16 rescaling taking trained positions to 1M. The rest of the dimensions are position-free — the now-standard partial-RoPE compromise (Qwen3.5 rotates 64 of 256; Kimi K3 goes all the way to NoPE on its global layers).

Shared-KV creates a subtle position bug that V4 patches with a novel trick. In standard RoPE, keys are rotated by their position \(i\) and queries by \(t\); the dot product depends only on \(t - i\), and values pass through unrotated. But in V4 the same rotated vector is key and value — so each attended entry now injects its absolute rotation \(R_i\) into the output, and the layer's output would depend on absolute position. The fix: rotate the core-attention output by \(-t\) (the query's own position, negated).

Why the output rotation restores relativity

On the RoPE dims, the attended mixture is \(\sum_i a_i R_i e_i\) for entry vectors \(e_i\). Applying \(R_{-t}\) to it gives \(\sum_i a_i R_{i-t}\, e_i\) — every term now depends on the relative offset \(i - t\) only, exactly the property plain RoPE has for free when values are unrotated. One extra rotation per token; absolute-position leakage cancelled.

5. MoE — Familiar Skeleton, Three Sharpened Edges

The MoE substrate is recognizably DeepSeekMoE — fine-grained experts (1 shared + 384 routed, top-6 for Pro), aux-loss-free bias-based balancing (bias update speed 0.001) with a tiny sequence-wise balance loss (weight \(10^{-4}\)) — with three changes worth noting:

  • Routing score: sigmoid → \(\sqrt{\mathrm{softplus}}\). V3 scored expert affinity with a sigmoid, which saturates: once a favored expert's logit is high, gradient through the gate value dies. \(\sqrt{\mathrm{softplus}(x)}\) is monotone, positive, and unbounded but square-root-tempered — combining weights can keep growing (and keep receiving gradient) without exploding.
  • Hash routing for the first 3 layers. V3 kept its first three FFN layers dense because early-layer routing is unstable. V4 makes them MoE anyway but routes by a predefined hash of the token ID — deterministic, perfectly balanced by construction, zero routing parameters to destabilize. Every block in the model is now MoE.
  • Node-limited routing removed. V3 constrained each token's experts to at most \(M\) nodes to bound all-to-all traffic; V4 drops the constraint entirely and lets the expert-parallel fabric take the hit — a statement about how much their interconnect stack improved.

Routed expert weights are stored and served in FP4, trained quantization-aware; most other tensors train in FP8 (e4m3). The released checkpoint is the FP8/FP4 artifact — quantization is not a post-hoc conversion (quantization page for why that distinction matters).

6. mHC — A Doubly-Stochastic Residual Stream

The residual stream is the one part of the block that has barely changed since 2017: each sublayer adds its output to a single running vector. Hyper-connections (and V4's manifold-constrained variant, mHC) widen and re-learn it:

  • The stream is widened to \(n_{hc} = 4\) parallel lanes.
  • Each layer applies a learned mixing matrix \(B_\ell\) across lanes — but projected onto the Birkhoff polytope (the set of doubly stochastic matrices: rows and columns each sum to 1, entries ≥ 0) via 20 iterations of Sinkhorn–Knopp row/column normalization.
  • Sigmoid gates control what each sublayer reads from and writes to the lanes.

The constraint is the point. An unconstrained learned mixing can amplify or attenuate the stream and compound across 61 layers into exactly the signal explosion the residual highway was meant to prevent; a doubly stochastic mixing is an averaging — total lane mass is conserved, so the stream can be re-routed but never inflated. Kimi K3 attacks the same rigidity with a different tool (softmax attention over previous layers' outputs — see Block AttnRes); that two frontier labs independently redesigned the residual stream in the same half-year marks it as the block's next contested component. mHC parameters are small, sensitive, and trained with AdamW rather than Muon.

7. Training — Muon, Clamps, and Anticipatory Routing

V4 is the first DeepSeek flagship trained primarily with Muon: matrix parameters take orthogonalized momentum updates (momentum 0.95, weight decay 0.1, update-RMS rescaled to 0.18), while embeddings, the prediction head, RMSNorm gains, and mHC parameters stay on AdamW (\(\beta_1 = 0.9\), \(\beta_2 = 0.95\), \(\varepsilon = 10^{-20}\)). Peak LR 2.0e-4 (Pro). Two stability mechanisms are more unusual:

  • SwiGLU clamping. Throughout training, the SwiGLU linear branch is clamped to \([-10, 10]\) and the gate capped at 10 — a hard ceiling on the activation blow-ups that plague low-precision MoE training. (Kimi K3 solves the same problem more surgically, by changing the activation itself — see SiTU-GLU on the K3 page.)
  • Anticipatory Routing. When a loss spike is detected, routing decisions switch to a slightly stale parameter copy \(\theta_{t-\Delta t}\) (precomputed one step ahead) while the expert computation uses current \(\theta_t\), with a short rollback. The idea: a spike means current parameters are momentarily unreliable — so don't let them decide where tokens go. Costs ~20% wall-clock while active; engaged automatically, only on spikes. This is a training-time cousin of the routing-instability problem covered on the MoE routing page — there, stale-vs-fresh routing appears at the RL train/inference boundary; here, inside a single pretraining run.

The rest of the recipe: 33T tokens with sample-level attention masking (documents packed into one sequence can no longer attend across document boundaries — new vs. V3), staged context extension 4K → 16K → 64K → 1M, and batch-invariant deterministic kernels giving bitwise train/inference reproducibility — which removes an entire class of RL train/rollout mismatch bugs by construction. MTP survives unchanged from V3: one sequential module, loss weight 0.3 decayed to 0.1.

The payoff, per the tech report: at 1M-token context, V4-Pro decodes at 27% of V3.2's per-token attention FLOPs with 10% of its KV cache (Flash: 10% and 7%) — and V3.2 was already the sparse-attention generation.

8. V4 Against Its Contemporaries

2026's three frontier open releases agree on almost everything except attention. All three are extreme-sparsity MoE with MTP, Muon-family or undisclosed optimizers, 4-bit-precision weights, and ~1M context. But where Qwen3.5 and Kimi K3 answer "attention over a million tokens" with recurrent state — most layers become linear attention with a fixed-size memory — V4 keeps every layer softmax attention and shrinks what it reads. Summaries vs. states: the two live hypotheses for long-context token mixing.

9. Summary

The move

Compress the sequence axis: 4 tokens → one 512-dim shared-KV entry (CSA), 128 → 1 (HCA). MLA retired.

CSA

Compress → lightning-indexer top-1024 → MQA over the shortlist, + 128-token raw window + attention sinks.

HCA

128:1 compression, dense attention, no indexer — the always-on global gist that backstops CSA's misses.

Positions

Partial RoPE on 64/512 dims; output rotated by \(-t\) to cancel the absolute-position leak shared-KV creates.

Beyond attention

mHC doubly-stochastic 4-lane residual stream; \(\sqrt{\mathrm{softplus}}\) routing + hash-routed early MoE; Muon primary; FP4 experts.

The numbers

At 1M context vs V3.2: 27% attention FLOPs, 10% KV cache (Pro). Cache ≈ 2% of a BF16 GQA-8 baseline.
