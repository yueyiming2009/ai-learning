Recurrent Depth — Looping a Transformer Block

Ordinary transformers buy depth with new parameters. A loop transformer applies one shared core repeatedly to a changing latent state, turning inference compute into an architectural scaling axis.

The standard transformer stack uses a different parameter set at every depth. Recurrent-depth models — also called loop transformers or depth-recurrent transformers — keep a small physical stack and execute it several times. The weights are shared; the hidden state is not. Each pass revises the representation left by the previous pass.

This page explains mechanisms documented in the Universal Transformer, Adaptive Computation Time, PonderNet, and the open Huginn recurrent-pretraining work. OpenAI's public GPT-6 Astra materials do not currently disclose a recurrent-depth architecture; the evidence boundary is documented on the Astra case-study page.

1. Four Different Meanings of "Recurrence"

The word is overloaded. The state index tells you which mechanism you are looking at:

MechanismState advances overShared operationWhat extra compute buys
Ordinary transformer depth layer \(\ell\) none: \(F_{\theta_\ell}\) differs by layer new parameters and a new transformation
Recurrent depth revision \(r\) the same core \(F_\theta\) another latent-state refinement
Sequence recurrence token position \(t\) a state update such as Mamba or DeltaNet more context processed through a fixed-size memory
Long reasoning trace generated token \(t\) the whole model, once per token more explicit language-space reasoning

Mamba and Gated DeltaNet recur across the sequence. Long chain-of-thought and search on the test-time compute page recur through generated tokens. A loop transformer instead revises the same token representations several times before the output head reads them.

Untied stack versus shared-depth loop
\[ \text{ordinary:}\quad H^{(\ell+1)} = F_{\theta_\ell}\!\left(H^{(\ell)}\right), \qquad \text{recurrent:}\quad H^{(r+1)} = F_{\theta}\!\left(H^{(r)}, E, s_r\right). \]

\(E\) is an input representation that can be reinjected every pass, and \(s_r\) is an optional recurrence-step embedding or control signal. Sharing \(\theta\) is the defining move. Without it, repeatedly drawing the same box in a diagram is just an ordinary deep network.

2. Prelude → Recurrent Core → Coda

A practical decoder-only design usually keeps a few untied layers around the loop. The prelude converts token embeddings into a stable input representation; the core performs \(R\) revisions; the coda converts the final latent state into the representation consumed by the language-model head.

\[ E=P_\phi(x),\qquad H^{(0)}=\operatorname{Init}(E),\qquad H^{(r+1)}=F_\theta(H^{(r)},E,s_r),\qquad p(x_{t+1}\mid x_{\le t})=\operatorname{softmax}\!\left(W_U C_\psi(H^{(R)})\right). \]

Why inject the input again?

A pure iteration \(H^{(r+1)}=F_\theta(H^{(r)})\) can gradually forget the original token evidence or collapse toward an attractor. Concatenating or adding \(E\) at each pass turns the update into repeated refinement conditioned on the problem. A step embedding \(s_r\) also tells shared weights where they are in the computation, so pass 20 need not behave like pass 1. 

e = prelude(embed(tokens))
h = initialize(e)

for r in range(num_recurrences):
    h = shared_core(fuse(h, e), step=r)

logits = unembed(coda(h))

The core can contain several transformer blocks. "One loop" therefore means one application of the whole core, not necessarily one attention-plus-MLP block.

Can We Turn an Intermediate Revision Back Into Tokens?

An activation is a continuous vector, not a token ID, so it cannot literally be passed to the tokenizer's decoder. What we can do is apply the model's vocabulary readout early. This produces a probe of the intermediate state: a provisional next-token distribution that the real forward pass has not emitted.

Start with an ordinary 12-layer transformer. At token position \(t\), layer 6 leaves a residual vector \(h^{(6)}_t\). The simplest readout sends that vector through the model's final normalization and unembedding matrix: 

layer-6 residual h_t^(6)
        |
        v
final RMSNorm / LayerNorm
        |
        v
unembedding W_U
        |
        v
vocabulary logits -> top-k token strings
\[ \operatorname{logits}^{(6)}_t = W_U\,\operatorname{FinalNorm}\!\left(h^{(6)}_t\right). \]

This is the logit lens. It asks, "If layer 6 were already the final layer, which token would the output head prefer?" For a causal model, the readout at position \(t\) is a provisional prediction for position \(t+1\), not a reconstruction of the token currently occupying position \(t\).

Illustrative trajectory

For the final position of The capital of France is, a probe might evolve as:

layer 2:   broad grammatical continuations
layer 6:   "Paris" begins to rank highly
layer 10:  "Paris" dominates
layer 12:  final next-token distribution

These are snapshots of a changing distributed representation, not a transcript in which each layer writes one word of private reasoning.

The Jacobian lens asks a better downstream question

The logit lens silently assumes that the remaining layers are the identity map. In the 12-layer example, it reads \(h^{(6)}\) as though layers 7–12 would not rotate, gate, or otherwise transform it. That approximation is often reasonable near the output and much weaker in early or middle layers.

Anthropic's Jacobian lens instead estimates how the remaining network typically transports a perturbation from layer 6 to the final residual stream:

\[ \bar J_6 = \mathbb{E}\!\left[ \frac{\partial h_{\mathrm{final},t'}} {\partial h^{(6)}_t} \right]. \] 
Logit lens:
    h6 -----------------------------> W_U -> tokens
         assume remaining map is I

Jacobian lens:
    h6 -> average Jacobian of layers 7-12 -> W_U -> tokens
          approximate downstream transport

Its vocabulary readout is conceptually

\[ \operatorname{lens}\!\left(h^{(6)}\right) = \operatorname{softmax}\!\left( W_U\,\operatorname{norm}\!\left(\bar J_6 h^{(6)}\right) \right). \]

The same distinction applies to recurrent depth. After recurrence \(r\), a logit lens directly unembeds \(H^{(r)}\). A Jacobian lens asks how the remaining applications of the shared core plus the coda would normally transform a direction in \(H^{(r)}\) before it affects the final token logits.

ReadoutIntermediate-to-final mapInterpretation
Logit lens assume identity What token does this state resemble in the final vocabulary basis right now?
Tuned lens learn a per-layer affine map What final output can a fitted probe predict from this state?
Jacobian lens use the model's averaged downstream derivative How does the remaining computation tend to turn this direction into final logits?
A decoded intermediate token is not necessarily "what the model is thinking." The hidden vector simultaneously carries syntax, entities, uncertainty, routing information, and many other superposed features. Reading its top vocabulary direction discards almost all of that information. Replacing the activation with the embedding of that one token would therefore be a destructive intervention; merely reading it is harmless.

3. Parameters Stay Flat; Executed Depth Does Not

Let \(L_P\), \(L_R\), and \(L_C\) be the numbers of blocks in the prelude, recurrent core, and coda. The stored block parameter sets and the number of block applications are:

Storage versus execution
\[ D_{\text{stored}}=L_P+L_R+L_C, \qquad D_{\text{executed}}(R)=L_P+R\,L_R+L_C. \]

Weight sharing is a parameter-efficiency claim, not a free-compute claim. FLOPs and serial latency still grow roughly linearly with \(R\). A recurrent model can therefore be small on disk while behaving like a much deeper computation graph at inference.

At \(R=32\), eight stored blocks execute as 132 block applications; an untied model with the same executed depth would need a separate parameter set for every one of those applications.

4. Training a Loop Without Letting It Cheat

Sample the recurrence count

If every example always uses exactly \(R=32\), the core can specialize to a 32-step schedule and fail at 8 or 64. Sampling depth during training teaches one transition operator to remain useful across a range of budgets and makes test-time scaling possible.

Backpropagate through only the tail

Full backpropagation through \(R\) applications stores \(R\) sets of activations. A scalable compromise runs early iterations without a gradient graph, then differentiates through the final \(K\) iterations. This is truncated backpropagation through depth: compute still pays for all \(R\), while activation memory scales mainly with \(K\).

Make repeated application stable

The same Jacobian is encountered again and again. Small expansive directions can compound into exploding activations; overly contractive dynamics can erase useful state. Residual paths, normalization, careful initialization, input reinjection, and training across varied depths all matter more when one core must remain well behaved under repeated composition.

More loops are not guaranteed to help. A model can overthink, oscillate, converge to a bad fixed point, or move its output distribution only cosmetically. Training at varied depths and measuring answer quality — not merely latent convergence — are essential.

5. Fixed Budgets, Learned Halting, and Convergence

Once depth is a loop, the iteration count can be chosen per request, sequence, or token. Three families make different tradeoffs:

PolicyStopping ruleStrengthFailure mode
Fixed \(R\) run an externally chosen number of loops simple, deterministic, batch-friendly wastes compute on easy inputs; may underthink hard ones
ACT / PonderNet learn a halting distribution and penalize computation task-adaptive and trainable sensitive objective; divergent token-level loop counts hurt batching
Convergence exit stop when successive predictions change by less than \(\delta\) can retrofit a trained recurrent model stable predictions can still be confidently wrong

Adaptive Computation Time

ACT adds a halting unit \(a_r=\sigma(w^\top H^{(r)}+b)\), accumulates probability mass, and stops once the mass reaches \(1-\epsilon\) or a hard cap:

\[ N=\min\left\{M,\min\left\{n:\sum_{r=1}^{n}a_r\ge 1-\epsilon\right\}\right\}, \qquad \mathcal{L}_{\text{total}}=\mathcal{L}_{\text{task}}+\tau\,\mathcal{P}. \]

The ponder penalty \(\tau\mathcal{P}\) prices computation. Without it, the easiest way to reduce task loss is usually to keep thinking.

PonderNet and convergence exits

PonderNet predicts a conditional halt probability \(\lambda_r\), inducing a stopping distribution \(q_r=\lambda_r\prod_{j<r}(1-\lambda_j)\), then regularizes it toward a geometric prior. A simpler inference-only rule compares consecutive output distributions:

\[ N=\min\left\{r:D_{\mathrm{KL}}\!\left(p_{r-1}\,\|\,p_r\right)<\delta\right\}. \]

ACT and PonderNet learn when to stop; a KL threshold merely detects that the answer has stopped moving. Those are not equivalent guarantees.

6. Open Case Study — Huginn

Geiping et al.'s Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach is the clearest inspectable decoder-only example. The released 3.5B-parameter model was trained on 800B tokens and exposes both its configuration and recurrence loop.

The implementation makes truncated depth explicit: it samples no-gradient and gradient-bearing iteration counts, executes the first group under torch.no_grad(), then checkpoints and differentiates through the tail. The same core_block module is called every time, after concatenating the current state with the prelude representation.

"Effective depth 132" describes 132 block applications, not 132 independently learned layers. Weight sharing changes the function class: the core learns an iterative algorithm, while an untied stack can assign a completely different transformation to every depth.

7. The Systems Bill Still Arrives

  • Latency is serial. Loop \(r+1\) needs \(H^{(r)}\), so recurrent depth cannot be parallelized like best-of-\(n\) samples.
  • FLOPs scale with the loop count. Shared weights reduce parameter memory, not matrix multiplications.
  • Training activations are the pressure point. Truncated gradients and checkpointing trade extra recomputation for memory.
  • Adaptive exits fragment batches. If examples or tokens stop at different depths, hardware either masks finished work or compacts the batch between iterations.
  • Autoregressive caching becomes subtle. Different recurrence depths create different latent histories; token-wise early exits can leave loop-specific cache entries missing.
  • Serving needs a new budget axis. Schedulers must account for prompt length, output length, and recurrent iterations rather than tokens alone.

9. Summary

Definition

Apply one shared transformer core repeatedly over latent depth: \(H^{(r+1)}=F_\theta(H^{(r)},E)\).

Scaling axis

Stored parameters stay fixed while executed depth, FLOPs, and serial latency grow with \(R\).

Training

Sample loop counts, reinject the input, stabilize repeated Jacobians, and truncate gradients when needed.

Halting

Fixed budgets are simple; ACT/PonderNet learn a compute policy; convergence exits only measure stability.

Open evidence

Huginn: 2–4–2 stored blocks, mean 32 recurrences, mean 8 gradient-bearing recurrences.

Not the same as

Sequence recurrence, shared embed/unembed weights, MTP drafting, or more chain-of-thought tokens.

Reading a revision

Logit lens unembeds it directly; the Jacobian lens approximates how the remaining loops and coda transform it first.
