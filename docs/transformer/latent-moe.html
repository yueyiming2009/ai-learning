Latent MoE

Keep the residual stream wide. Send a smaller representation through the routed experts. Understand what the two projections save, what they cost, and what remains model-specific.

A conventional routed expert maps the model width \(D\) to an internal width \(F\) and back. Latent MoE changes the expert's input and output width to \(d<D\), using shared projections around the whole routed branch. It is not merely choosing fewer experts, shrinking the hidden expansion \(F\), or quantizing the same tensors. Start with MoE routing for top-\(K\) and balancing.

1. Follow one token through the branch

Using row vectors, let \(A\in\mathbb R^{D\times d}\), \(B\in\mathbb R^{d\times D}\), and selected experts \(e_i:\mathbb R^d\to\mathbb R^d\). Without optional normalization:

\[ z=xA,\qquad u=\sum_{i\in\mathcal S(x)}p_i(x)e_i(z),\qquad y=uB+S(x). \]

A gated expert uses two \(d\times F\) projections, an elementwise gated activation, and one \(F\times d\) return projection. A non-gated ReLU² expert uses only two matrices. The \(d\to D\) projection runs once after aggregation, not once for every selected expert. Routing, weighting, normalization, and balancing remain separate choices.

Normalization order matters: \(N(\sum_i p_i e_i(z))\) generally differs from \(\sum_i p_i N_i(e_i(z))\). Kimi normalizes the aggregate; Muse normalizes compressed inputs and individual expert outputs. Moving these norms for convenience changes the model.

2. Gradients reconnect the narrow branch to the wide model

Fix the selected expert set locally, as in ordinary top-\(K\) routing, and denote the upstream row gradient by \(\bar y\). For the unnormalized template:

\[ \bar u=\bar yB^\top,\quad \nabla_B L=u^\top\bar y,\quad \bar p_i=\langle\bar u,e_i(z)\rangle,\quad \bar z=\sum_{i\in\mathcal S}\operatorname{VJP}_{e_i}(p_i\bar u). \]
\[ \nabla_A L=x^\top\bar z,\qquad \bar x=\bar zA^\top+\bar x_{\rm router}+\bar x_{\rm shared}. \]

The down-projection learns from all selected experts; the router has a separate gradient through the selected combination weights. Discrete index changes are not differentiated as a smooth operation. Insert each normalization's VJP at its actual position in the graph; do not reuse these simplified formulas unchanged for a normalized variant. See routing gradients and gated-FFN backward.

3. Three different budgets: parameters, FLOPs, and traffic

Let \(E\) be stored routed experts, \(K\) active experts/token, \(F\) each expert's intermediate width, and \(g=3\) for gated FFNs or \(g=2\) for a two-matrix FFN. Count a multiply-add as two FLOPs. Hold \(E,K,F\) fixed when comparing widths.

Routed branch onlyFull-width expertsLatent experts + projections
Stored matrix parameters\(gEDF\)\(2Dd+gEdF\)
Forward matrix FLOPs/token\(2gKDF\)\(4Dd+2gKdF\)
Logical dispatch + combine, n tokens, b bytes/element\(2nKDb\)\(2nKdb\)

Exclude the router, optional shared path, norms, activations, attention, and residual operations from both sides. Actual network traffic also depends on expert placement, per-destination token deduplication, local experts, quantization, and aggregation. \(Kdb\) is a logical payload count, not a measured NIC-byte or latency prediction.

The compute break-even is \(d/D < gKF/(2D+gKF)\). More routing multiplicity can amortize the two shared projections, but increasing \(K\) spends some of the saved compute and bandwidth. If \(d=D\) while both projections remain, there is no compression saving and there is still projection overhead.

Worked example: Muse's half-width routed branch

With \(D=8192,d=4096,F=4096,E=256,K=8,g=3\), the expert matrices contain 12.885B parameters/layer, plus 67.109M in the two projections. Full-width experts at the same \(F,E\) would contain 25.770B. Forward matrix work falls from 1.611 to 0.940 GFLOPs/token/layer, including the projections. Logical BF16 dispatch plus combine falls from 256 to 128 KiB/token/layer. These are counterfactual shape calculations, not equal-quality model comparisons or measured speedups.

Can the full-width shared expert become the slow branch?

Yes, but “every token” does not normally mean one GPU receives the entire global batch. A shared expert can be replicated on token-owning ranks or tensor-sharded; each replica processes its local tokens in batched GEMMs. Unlike a routed expert, it does not require MoE token dispatch, but TP collectives and training-state/gradient communication may still apply.

For \(N\) tokens across \(P\) balanced EP ranks with replicated shared weights, \(S\) shared experts, \(K\) routed experts/token, and per-token costs \(c_s,c_r\):

\[ W_{\rm shared/rank}=\frac NP S c_s,\qquad W_{\rm routed/rank}=\frac{NK}{P}c_r,\qquad \frac{W_{\rm shared}}{W_{\rm routed}}=\frac{S c_s}{K c_r}. \]

Comparing one shared expert with one routed expert misses that a rank normally owns several routed experts. With \(S=1,K=8,c_s=c_r\), shared work is one eighth of routed work per rank under these assumptions—not automatically a straggler.

It can become a critical-path bottleneck if it is much wider, insufficiently sharded, centralized, or competes for the same compute/bandwidth as the routed branch. Latent compression can make the full-width shared path a larger fraction of the layer. Ideal overlap gives a branch time near \(\max(T_{\rm shared},T_{\rm dispatch}+T_{\rm routed}+T_{\rm combine})\), but resource contention can make actual time higher. “Hidden under communication” is conditional latency hiding, not free compute. See shared-expert placement and overlap.

5. What compression does not solve

  • Representational restriction: the routed output \(uB\) lies in the row space of \(B\), of rank at most \(d\). This does not make the whole residual block rank-\(d\): the residual, full-width router, and optional shared experts retain other paths.
  • Load imbalance: smaller messages do not stop too many tokens choosing one expert. Router balancing and runtime scheduling still matter.
  • Precision and stability: projection chains and sums over many experts can change activation scale. Norm placement, bounded activations, and precision choices are implementation decisions, not consequences of the word “latent.”
  • Inference regime: stored expert weights affect memory; active expert coverage across a batch affects weight traffic. Neither is determined by a single-token active parameter count. See MoE serving.
  • No free equivalence: moving a projection through a nonlinear expert or an RMSNorm generally changes the function. This is an architecture to train, not a lossless post-hoc shrink operation on arbitrary pretrained experts.
