Loop Transformers in Practice

Reuse the same layers to do more work per token. A short guide to the open models, how they learn to loop, and what that extra computation costs.

Looped transformers are already downloadable language models, not just a research idea. Huginn and Ouro established open examples in 2025; Inkling 2 Mini now brings the approach to a 26.4B-parameter agent model. This guide covers selected releases through November 2026.

1. The Idea: Reuse Layers, Not Tokens

An ordinary transformer passes each token through its layers once. A looped transformer applies the same layers several times, updating the hidden representation on each pass. The weights stay the same; the state they process changes.

This buys more computation without storing a separate set of weights for every extra layer. It can improve reasoning without generating a longer chain of thought. A model can also do both: loop internally and write reasoning tokens.

The idea goes back to Universal Transformers (2018). Here, recurrence means extra depth within a token's computation, rather than a state carried across token positions as in Mamba. See Recurrent Depth for the equations.

More Computation, Not a Bigger Encyclopedia

Extra passes can help a model find and connect information already in its context. In TML's variable-loop experiments, long-context benchmarks GraphWalks BFS and MRCR v2 improve with more passes, while knowledge-intensive AA-Omniscience, SimpleQA Verified, SimpleVQA, and WorldVQA do not. Repeating the same weights adds reasoning work, not newly learned facts.

Search and tools help fill that gap by bringing outside information into context. Mini's launch reports leading results among similarly sized open-weight models on BrowseComp, DeepSearchQA, and MCP Atlas, plus strong tool-assisted knowledge work. Looping helps use evidence; search and tools help obtain it. The Inkling guide connects these results.

Inkling 2 Mini: Looping for Agentic Work

Mini runs six input layers once, the middle twelve three times, and six output layers once: 6 + 12 × 3 + 6 = 48 layer applications from 24 stored layers. Each core pass receives the input layers' output; later passes also receive a learned, gated message from the previous pass.

Its MoE has 26.4B total parameters, 3.4B nominally active, and 5.4B weight activations per token when repeated passes are counted. Native mixed NVFP4/MXFP8 weights occupy about 20GB, with additional memory needed for context and runtime. The launch reports 48.2% on DeepSWE v1.1 and 46.5% on Vals Index v2.2, leading its under-100B open-weight comparison on both.

Its contribution is a practical combination of looping, sparse experts, low-precision deployment, and extensive agent training—not the invention of looping. The Inkling model guide covers the architecture and full disclosed recipe.

3. How Models Learn to Loop

Train with recurrence from the start. Huginn and Ouro learn to refine hidden states across repeated passes during pretraining. Huginn's training code, data, and intermediate checkpoints make it a useful starting point for studying the process.

Add recurrence, then continue training. Retrofitting Recurrence turns TinyLlama, Llama, and OLMo checkpoints into input layers, a shared core, and output layers. Continued training teaches that core to handle repeated visits. Mini also introduces looping during training, then combines expert pruning with 1T distilled healing tokens, SFT, and 2.2T RL tokens over 2,000 steps.

Introduce feedback gently. Mini initially blocks the previous pass's message, so each pass starts from familiar prelude information. Training then learns how much feedback to use and what to send. A trainable gate can receive a gradient even at zero; the worked gate example shows how repetition can become learned refinement.

Simply repeating an arbitrary pretrained layer can make its states drift. Training-free looping experiments damp those updates; their public path primarily targets prefill and likelihood evaluation rather than looping every generated token.

Fixed Versus Adaptive Depth

Fixed depth gives every token the same number of passes; released Mini uses three. A variable-depth model lets experiments choose the pass count. Adaptive depth chooses it per token or example, spending more work where needed. Mixture-of-Recursions provides training code for token routing and loop-aware caches.

TML's separate variable-loop research model improves serial lookup reasoning out to ten passes, while LoopCoder-v2's comparisons favor two loops over three or four. Choose depth by measured task performance.

4. What It Costs to Run

Weight reuse saves storage, not computation. Three costs determine whether looping pays off:

  • Time per token. Each pass adds work, usually in sequence. Shorter answers can offset that work, so compare total task time and success rate—not just token counts.
  • KV-cache memory. The same layer produces different keys and values on each pass. A straightforward implementation stores a separate cache for each visit, even though the weights are shared.
  • Batch efficiency. Adaptive halting saves time only if the runtime skips the remaining work and keeps the GPU busy with other tokens. Selecting an early answer after computing every pass saves nothing.

Compare at the same quality. In TML's unpruned comparison, the non-looping model was cheaper to train but needed 2.4× the inference compute to match the looped model's loss. Extra work per token can pay off if it replaces still more expensive computation needed for that quality. See the training-versus-inference comparison for the numbers; this measures prediction loss, not serving speed.

Current work attacks those costs directly: MELT uses gated cache updates, Looped Latent Attention compresses caches across loops, and partial-stack designs such as Mini repeat only the middle layers. Runtime support is model-specific; use the release's documented engine and version.
