Loop Transformers in Practice

Open models, recurrent pretraining, pretrained-model retrofits, adaptive depth, and the systems work required to turn shared-weight loops into usable language models.

Landscape verified September 6, 2026. "Open" is graded explicitly below: some projects release training code, data, and checkpoints; some release weights and custom inference only; others remain paper-level results. Reported benchmark numbers are not treated as independent reproductions.

The Recurrent Depth page explains the mechanism. This page asks the practical follow-up: who has trained it, what can be downloaded, whether existing checkpoints can be converted, and which systems problems still block broad deployment?

1. What Counts as a Loop Transformer?

The defining operation is repeated application of shared transformer parameters over computational depth:

\[ H^{(r+1)}=F_\theta(H^{(r)},E). \]

Extra iterations refine the hidden representation without requiring a new parameter set for every depth. That excludes several adjacent ideas that use "recurrence" or "latent reasoning" differently.

FamilyWhat repeats?Included here?
Looped / recurrent-depth transformer shared transformer blocks over latent depth yes — the main subject
Mamba, RWKV, recurrent sequence mixers a state update across token positions no — sequence recurrence
Coconut and continuous latent CoT hidden states inserted into later latent/token positions related, but a different execution pattern
Universal Transformer / ACT shared depth transitions, optionally with halting historical foundation
HRM / Tiny Recursive Models task-specific latent or answer-state updates relevant research, not general-purpose LM checkpoints

A model can combine recurrent depth with generated chain-of-thought. Ouro-Thinking and IQuest's Loop-Thinking checkpoints do both: hidden-state loops happen inside each language-model call, while ordinary autoregressive decoding can still emit visible reasoning tokens.

Huginn — the reproducibility reference

Huginn's repository, checkpoint, and training data expose the complete path from preprocessing to variable-depth generation. The 3.5B checkpoint was trained on 800B tokens. Its custom cache, adaptive-compute experiments, and intermediate checkpoints make it the best laboratory even though it is not the strongest application model.

Ouro — compact pretrained LoopLMs

ByteDance's Ouro-2.6B and related checkpoints use iterative shared-weight computation, intermediate-depth supervision, and a learned exit distribution. They are Apache-2.0 and convenient to load, but the public release is stronger on weights and inference than on reproducing the full 7.7T-token pretraining run.

An exit distribution is not automatically an efficient early exit. The inspected Hugging Face implementation computes all configured recurrences before selecting or combining intermediate outputs. A policy can choose an earlier answer after the expensive work has already happened.

Application-oriented releases

Nanbeige4.2-3B is a small general and agentic model with public SGLang, vLLM, llama.cpp, and Ollama branches. LoopCoder-v2 is a 7B two-loop coding model whose three- and four-loop variants regress sharply — direct evidence that recurrent depth is not a monotonic quality knob. IQuest-Coder-V1 40B Loop is the largest accessible checkpoint verified here and has merged vLLM support, but uses a custom license rather than plain Apache or MIT.

4. Three Ways to Obtain a Looped Model

Native pretraining

Design the recurrent trajectory before training and optimize the shared core end to end. Huginn, Ouro, Nanbeige, LoopCoder, and GRT follow this broad path.

Retrofitted recurrence

Map selected layers from an existing dense checkpoint into prelude/core/coda roles, add input injection, then continue training at varied depths.

Training-free wrapper

Keep a checkpoint frozen and reapply a middle layer window with damped residual substeps. Cheapest to try, but narrower evidence and weaker generation support.

Retrofitting recurrence

Teaching Pretrained Language Models to Think Deeper with Retrofitted Recurrence converts TinyLlama-1.1B, Llama-3.2-1B, and OLMo-2-0425-1B. The conversion scripts preserve selected pretrained layers, assign them to prelude/shared-core/coda roles, add Huginn-style input injection, verify the initial mapping, and then continue training with a recurrent-depth curriculum. Released checkpoints are collected on Hugging Face.

Training-free looping

Training-Free Looped Transformers wraps frozen Qwen3 checkpoints at inference. Naive reapplication usually drifts, so the method treats a pre-norm block as an ODE step and replaces one large residual update with smaller damped substeps anchored to the ordinary representation.

The public reproduction path primarily loops prefill or log-likelihood evaluation; incremental decoding bypasses the loop. Its gains should not be read as a demonstrated general-purpose latent-reasoning decoder.

5. Adaptive Depth — Routing Is Ahead of Scheduling

A fixed-loop model gives every token the same recurrent depth. Adaptive computation instead asks which tokens or examples deserve another pass. Four distinct capabilities are often conflated:

  1. produce a valid prediction at intermediate depths;
  2. learn or fit a policy that chooses a depth;
  3. actually stop executing when the policy fires;
  4. regroup unfinished work so the accelerator remains full.

Mixture-of-Recursions (MoR) is the strongest substantial open codebase for this problem. It routes tokens to different recursive depths with token-choice or expert-choice routing, then handles recursion-specific KV state. Its experiments span roughly 135M through 1.7B baseline configurations, with public training code and author-linked checkpoints.

Ouro supplies learned exit distributions; Huginn supplies zero-shot criteria such as entropy change, latent change, KL change, and argmax stability. Recent adaptive-depth diagnostics find that the supervision used to shape intermediate trajectories can matter as much as the gate itself: a better classifier cannot rescue states that were trained to be useful only at the final loop.

6. Why Serving Is the Hard Part

Sharing weights reduces parameter storage. It does not automatically reduce recurrent FLOPs, activation traffic, or KV-cache memory.

ProblemWhy recurrence creates itCurrent direction
Serial latency loop \(r+1\) depends on loop \(r\) two-loop designs, partial-stack loops, parallel-loop attention
KV-cache growth the same physical layer produces different K/V states on each visit cache sharing, compression, gated updates, cross-loop attention
Batch divergence different tokens or requests halt at different depths routing, masking, compaction, depth-aware schedulers
Training memory backpropagation spans repeated applications of the same core truncated depth gradients and activation checkpointing
Runtime support standard engines assume one visit per physical layer custom Transformers code and model-specific vLLM/SGLang forks

The most concrete serving progress is model-specific: IQuest's looped implementation is present in upstream vLLM; Nanbeige publishes deployment branches; LoopCoder-v2 uses a specialized vLLM fork; Huginn's plugin remains explicitly experimental. There is not yet one common loop-transformer cache and scheduler interface.

MELT proposes one gated KV cache per physical layer so memory remains independent of loop count, while Looped Latent Attention compresses the trajectory across loop-indexed KV states. Both are important directions, but no complete official artifact release was verified for this snapshot.

7. The Research Frontier

  • Stability: DeepLoop derives residual scaling for parameters revisited many times; GRT adds state-conditioned update gates. The recurrent operator's dynamics, not just nominal depth, decide whether extra loops settle, oscillate, or drift.
  • What should loop: full-block recurrence is expensive. Mixer-only and partial-stack designs investigate whether repeated attention/state transport captures most of the gain without repeatedly executing the dense FFN.
  • Matched-budget evidence: SMELT reports compute/parameter/KV-matched MoE experiments up to 54B non-embedding parameters, but no public weights were verified.
  • Interpretability: Jacobian-lens work now studies whether recurrent models preserve a readable global workspace across loop boundaries. Different models carry and reconstruct information in materially different ways.
  • Depth extrapolation: useful behavior beyond the trained loop range remains inconsistent. More iterations can improve, saturate, or damage the answer.
GitHub contains many "reconstructions" of rumored closed architectures. They are useful personal experiments, but they should not be placed beside projects with primary papers, trained checkpoints, reproducible evaluations, and explicit licenses. This landscape includes the latter and treats unverifiable releases as a watchlist, not evidence.

9. Summary

Maturity

Looped LMs have crossed from toy tasks into multi-billion-parameter open checkpoints and specialized serving integrations.

Best learning artifact

Huginn remains the most complete open path from data and training code to variable-depth inference.

Best adaptive code

Mixture-of-Recursions addresses token routing, missing KV entries, and batch efficiency in one framework.

Largest checkpoint

IQuest-Coder-V1-40B-Loop is the largest publicly accessible looped checkpoint verified here.

Central warning

More loops are not monotonically better; recurrent trajectories must be trained and stabilized for their deployment depth.

Main blocker

Efficient adaptive serving still needs loop-aware KV caches, compaction, and scheduler support.
