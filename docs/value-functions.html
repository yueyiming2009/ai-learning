Value Functions — V, Q, and the Bellman Equations

How to measure how good a state (or a state–action pair) is under a given policy — and the recursive equations that let you compute it one step at a time.

🎓
David Silver's Reinforcement Learning Course (DeepMind/UCL)

Covers the same ground as Lectures 2–3 (MDPs and planning by dynamic programming — Bellman equations, V*, Q*, value iteration).

The MDP defines the problem: maximize expected return \(\mathbb{E}[G_t]\). But computing \(G_t\) requires running a full episode to the end. Value functions give us a shortcut — a way to evaluate any state or action without needing to simulate the future. They are the central object almost every RL algorithm is either computing, estimating, or implicitly using.

1. V — The State-Value Function

The state-value function \(V^\pi(s)\) answers: if I am in state \(s\) right now and follow policy \(\pi\) forever after, what total discounted reward should I expect?

State-value function
\[ V^\pi(s) = \mathbb{E}_\pi\!\left[ G_t \;\middle|\; s_t = s \right] = \mathbb{E}_\pi\!\left[ \sum_{l=0}^{\infty} \gamma^l r_{t+l} \;\middle|\; s_t = s \right] \]

The expectation is taken over randomness in both the policy (\(a_t \sim \pi(\cdot \mid s_t)\)) and the environment (\(s_{t+1} \sim P(\cdot \mid s_t, a_t)\)). \(V^\pi\) is always defined relative to a specific policy — a state's value changes if you change how you act from it.

Intuition

Think of \(V^\pi(s)\) as the answer to "how much total reward, on average, will I rack up if I start here?" It's a single number per state that summarises the long-run quality of being there.

2. Q — The Action-Value Function

The action-value function \(Q^\pi(s, a)\) adds one more piece of information: it conditions on both the state and the first action taken, then follows \(\pi\) for all subsequent steps.

Action-value function
\[ Q^\pi(s, a) = \mathbb{E}_\pi\!\left[ G_t \;\middle|\; s_t = s,\; a_t = a \right] \]

\(Q^\pi\) is also called the Q-function or quality function. It answers: if I am in state \(s\), I commit to action \(a\) right now (regardless of what \(\pi\) would normally say), and then follow \(\pi\) — how much return do I get?

\(V^\pi(s)\)

Average over all actions the policy might take from \(s\). Tells you how good the state is — unconditionally.

Used as the baseline in advantage estimation.

\(Q^\pi(s, a)\)

Committed to action \(a\) first, then averages over everything after. Tells you how good a specific action is from \(s\).

The signal that tells the policy which actions to do more or less of.

The relationship between V and Q

\(V^\pi\) is just \(Q^\pi\) averaged over actions according to the policy — if you weight each action's Q-value by how likely the policy is to take it, you recover V:

\[ V^\pi(s) = \sum_a \pi(a \mid s)\, Q^\pi(s, a) \]

And conversely, \(Q^\pi\) is immediate reward plus the discounted V of the next state:

\[ Q^\pi(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^\pi(s') \]

These two identities interlock V and Q. Substituting one into the other gives the Bellman equations.

3. The Bellman Expectation Equations

The Bellman equations express V and Q in terms of themselves — a recursive, one-step look-ahead structure. They are the foundation of almost every RL algorithm.

Derivation — expanding the return one step

Start with the definition and expand \(G_t\) using the recursion \(G_t = r_t + \gamma G_{t+1}\):

\[ V^\pi(s) = \mathbb{E}_\pi[G_t \mid s_t = s] = \mathbb{E}_\pi[r_t + \gamma G_{t+1} \mid s_t = s] \]

By linearity of expectation, split the sum. The first term averages the immediate reward over the policy's action choice; the second averages the discounted future value over the transition:

\[ = \sum_a \pi(a \mid s) \left[ R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^\pi(s') \right] \]

The key move is using the Markov property: \(\mathbb{E}[G_{t+1} \mid s_{t+1} = s'] = V^\pi(s')\), so we can replace the future return with the value of the next state.

Bellman expectation equation for V
\[ V^\pi(s) = \sum_a \pi(a \mid s) \left[ R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^\pi(s') \right] \]

The same logic applied to \(Q^\pi\) gives:

Bellman expectation equation for Q
\[ Q^\pi(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a) \sum_{a'} \pi(a' \mid s')\, Q^\pi(s', a') \]
Why these equations matter

They turn "compute the value of a state" — which seems to require simulating infinite trajectories — into a system of equations. In a small tabular MDP with \(|\mathcal{S}|\) states you can solve it exactly by linear algebra. In large or continuous spaces (like LLM token contexts) you can't solve it exactly, but you can use it as a learning signal: if \(V^\pi(s) \neq r + \gamma V^\pi(s')\), your estimate is wrong and should be updated. This is the idea behind TD learning.

4. Optimal Value Functions

Once we can evaluate any policy, the natural question is: what's the best possible value? The optimal value functions are defined as the maximum over all policies:

\[ V^*(s) = \max_\pi V^\pi(s) \qquad Q^*(s, a) = \max_\pi Q^\pi(s, a) \]

If you know \(Q^*\), you immediately know the optimal policy: at each state, take the action with the highest Q-value:

\[ \pi^*(s) = \arg\max_a\, Q^*(s, a) \]

The optimal value functions satisfy the Bellman optimality equations — the same one-step look-ahead structure, but with \(\max\) replacing the policy average:

Bellman optimality equation for V
\[ V^*(s) = \max_a \left[ R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^*(s') \right] \]
Bellman optimality equation for Q
\[ Q^*(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a) \max_{a'} Q^*(s', a') \]
The Bellman expectation equations (§3) are linear in V — you can solve them exactly for a fixed policy. The Bellman optimality equations are nonlinear (the \(\max\) is inside the sum), so they can't be solved by simple linear algebra. Iterative methods like value iteration or Q-learning are needed.

5. The Advantage Function

The advantage function \(A^\pi(s, a)\) measures how much better or worse action \(a\) is compared to the average action from state \(s\) under \(\pi\):

Advantage function
\[ A^\pi(s, a) = Q^\pi(s, a) - V^\pi(s) \]

Some key properties:

  • Zero mean: \(\mathbb{E}_{a \sim \pi}[A^\pi(s, a)] = 0\) — averaged over the policy's action distribution, advantage is zero by construction. Actions better than average have positive advantage; worse-than-average actions have negative advantage.
  • Policy-invariant sign: if \(A^\pi(s, a) > 0\), action \(a\) is better than average regardless of what specific value \(V^\pi(s)\) happens to be.
  • Credit assignment: V measures "this state is generically good/bad." A strips that out, leaving only the signal about the action. This is the teaching signal the policy gradient uses.
Why use advantage instead of raw return?

If you land in a very good state, \(G_t\) will be high — but that's mostly because the state was good, not because you made a smart decision at that step. Using \(A_t = G_t - V(s_t)\) subtracts out the baseline value of being in that state, isolating the part of the return that was due to the specific action taken. This significantly reduces variance in policy gradient estimates.

6. Value Functions in LLM RL

In LLM RL, the state at step \(t\) is the full context: \(s_t = [\text{prompt},\, t_1, \ldots, t_t]\). The value functions map this onto a scalar:

FunctionIn LLM RLIn practice
\(V^\pi(s_t)\) Expected total reward from the current context onward — "how likely is this partial response to end up scoring well?" Learned by the critic \(V_\psi\): a separate head (or model) trained to predict return from context. Used in PPO.
\(Q^\pi(s_t, a_t)\) Expected reward if we commit to generating token \(a_t\) next, then continue under \(\pi\) Rarely estimated directly — too expensive. Recovered implicitly from \(V\) via the Bellman equation or TD errors.
\(A^\pi(s_t, a_t)\) How much better/worse was token \(a_t\) compared to the average token the policy would have generated here? Estimated via GAE (see Policy Gradient §3). This is the signal that nudges the policy gradient.
Why the critic is hard to learn

The state space in LLM RL is astronomically large — every possible prefix of tokens is a distinct state. The critic \(V_\psi\) must generalise across all of them using the transformer's own representations as input. This is why the critic is typically initialised from the same pre-trained weights as the policy, and why its training is noisy: it is regressing on targets (\(\hat R_t\)) that are themselves estimates derived from incomplete rollouts.

GRPO: bypassing V entirely

GRPO avoids learning a critic by sampling \(G\) full responses to the same prompt and using the group mean reward as an implicit baseline. This estimates \(V^\pi(s_0)\) at the start-of-episode state cheaply — but only there. Per-token advantages are not available, so the advantage is applied uniformly across all tokens in a response. See the GRPO page for the full derivation.

Why exact computation is impossible

The Bellman equations tell you exactly what \(V^\pi(s)\) should be — but computing it requires summing over all successor states \(s'\), weighted by \(P(s' \mid s, a)\). In LLM RL:

  • The vocabulary alone has tens of thousands of tokens. A context of length 512 has \(\approx 50{,}000^{512}\) possible states.
  • The transition dynamics \(P\) are deterministic (appending a token) but the state space is still intractable to enumerate.
  • There is no closed form for \(V^\pi\).

The solution is approximation: either sample actual returns (Monte Carlo) or bootstrap from the current estimate of \(V\) (TD learning). Both are covered in the next pages.
