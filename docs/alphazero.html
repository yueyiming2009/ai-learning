AlphaZero

MCTS + a dual-headed neural network + self-play. The network guides the search; the search improves the network. No human knowledge — learned from scratch in chess, Go, and shogi in hours.

🎓
David Silver's Reinforcement Learning Course (DeepMind/UCL)

Covers the AlphaGo/AlphaZero lineage from Lecture 10 (classic games — self-play, MCTS + neural networks). AlphaZero postdates the course; Lecture 10 covers AlphaGo.

AlphaZero (Silver et al., 2017) is the clearest realisation of a simple idea: if you can evaluate positions and generate plausible moves with a neural network, and you have MCTS to plan ahead, you can generate better training data than any human label — by playing the current best version of yourself. The result is a self-improving loop that, given compute, converges to superhuman play in any two-player zero-sum game with a perfect simulator.

1. The Key Idea: MCTS as a Policy Improvement Operator

A raw neural network policy \(P_\theta(a \mid s)\) is fast but imperfect — it learned from patterns in data, not from careful lookahead. MCTS, given \(P_\theta\) as a prior to focus search, produces \(\pi_\text{MCTS}\): a refined policy that reflects hundreds of simulated futures. It is almost always stronger than the raw network.

AlphaZero exploits this asymmetry in a loop:

  1. Use the network to guide MCTS — \(P_\theta\) focuses search budget on plausible moves; \(V_\theta\) replaces expensive random rollouts.
  2. Use MCTS output as a training target — \(\pi_\text{MCTS}\) is better than \(P_\theta\), so train the network to match it.
  3. Repeat — a stronger network produces better MCTS, which produces better training targets, which produces a stronger network.
Why this is self-improving

At each iteration the network bootstraps off its own best thinking. There is no ceiling imposed by human knowledge or human-labelled data — the only ceiling is compute and the complexity of the game. This is what "tabula rasa" learning means: the only inputs are the rules of the game and raw self-play.

2. The Neural Network — Dual Heads on a Shared Trunk

AlphaZero uses a single deep residual network (ResNet) with a shared trunk and two output heads:

Shared trunk
ResNet — deep residual blocks processing the board state \(s\)
(In chess: 20 residual blocks, 256 filters each; raw input = 8×8×119 feature planes)
Policy head
\(P_\theta(a \mid s)\)

Probability distribution over all legal actions. Gives MCTS its starting prior — focuses the search on moves the network considers plausible.

Value head
\(V_\theta(s) \in [-1, 1]\)

Scalar estimate of expected game outcome from state \(s\). Replaces the random rollout in MCTS — one forward pass instead of an entire simulated game.

Both heads train jointly from the same self-play data. The shared trunk forces the network to learn representations useful for both evaluating positions and selecting moves — an inductive bias that turns out to be very beneficial.

3. Self-Play Data Generation

Training data comes entirely from games the network plays against itself. For each move in a self-play game:

  1. At the current state \(s_t\), run \(K\) MCTS simulations using the current network \(f_\theta\).
  2. Each simulation uses PUCT for selection (see the MCTS page), \(V_\theta\) instead of a rollout, and \(P_\theta\) as the prior.
  3. Compute the MCTS policy from visit counts: \[ \pi_\text{MCTS}(a \mid s_t) = \frac{N(s_t, a)^{1/\tau}}{\sum_{a'} N(s_t, a')^{1/\tau}} \] Early in the game \(\tau = 1\) (proportional to visit counts, more exploration); later \(\tau \to 0\) (deterministic, take the most-visited action).
  4. Sample action \(a_t \sim \pi_\text{MCTS}(\cdot \mid s_t)\) and play it.
  5. Store \((s_t,\, \pi_\text{MCTS}(\cdot \mid s_t))\) — the outcome \(z\) is filled in after the game ends.

At game end the outcome \(z \in \{+1, 0, -1\}\) is known. Each stored position is labelled with \((s_t, \pi_\text{MCTS}, z_t)\) where \(z_t = \pm z\) depending on whose turn it was at step \(t\). These triples go into the replay buffer \(\mathcal{D}\).

4. The Loss Function

Sample a mini-batch from \(\mathcal{D}\) and minimise a combined loss over both heads plus L2 regularisation:

AlphaZero loss
\[ \mathcal{L}(\theta) = \underbrace{(z - V_\theta(s))^2}_{\text{value loss}} \;-\; \underbrace{\pi_\text{MCTS}^\top \log P_\theta(s)}_{\text{policy loss}} \;+\; \underbrace{\lambda \lVert\theta\rVert^2}_{\text{L2 reg}} \]
Value loss
\((z - V_\theta(s))^2\)

Regress the value head toward the actual game outcome \(z\). Same MSE loss as the PPO critic.

Policy loss
\(-\pi_\text{MCTS}^\top \log P_\theta(s)\)

Cross-entropy between the MCTS visit distribution and the network's prior. Trains \(P_\theta\) to mimic the search.

Regularisation
\(\lambda \lVert\theta\rVert^2\)

L2 weight decay. Prevents overfitting to the current self-play distribution.

Why cross-entropy for the policy loss?

\(-\pi_\text{MCTS}^\top \log P_\theta(s) = H(\pi_\text{MCTS},\, P_\theta)\) is the cross-entropy between the target distribution \(\pi_\text{MCTS}\) and the network's output \(P_\theta\). Minimising it is the same as maximum likelihood: train \(P_\theta\) to assign high probability to moves that MCTS visited often. The MCTS distribution is a soft target — moves with many visits get high probability, not a one-hot label — which provides a richer learning signal than a single best-move label.

5. The Training Loop

Three processes run continuously in parallel:

Stage 1
Self-play

Many workers play games using the latest network + MCTS, generating \((s, \pi_\text{MCTS}, z)\) triples. Fill the replay buffer \(\mathcal{D}\).

→
Stage 2
Training

Sample mini-batches from \(\mathcal{D}\), compute \(\mathcal{L}(\theta)\), update \(\theta\) via SGD. Running continuously as new self-play data arrives.

→
Stage 3
Evaluation

Periodically pit the new network against the previous best. If win rate exceeds a threshold (e.g. 55%), promote it as the new best and use it for self-play.

Algorithm — AlphaZero training loop
Require: network fθ, MCTS simulations per move K, win threshold τ_win
Initialize: fθ with random θ;  θ_best ← θ;  𝒟 ← ∅

repeat
    ▷ Self-play: generate training data
    for each game do
        s ← initial position
        while s is not terminal do
            π ← MCTS(s, fθ, K)              ▷ PUCT search with Vθ leaf eval
            a ← sample from π(· | s)
            record (s, π);  s ← transition(s, a)
        end while
        z ← game outcome ∈ {−1, 0, +1}
        add {(sₜ, πₜ, z)}t=0T to 𝒟
    end for

    ▷ Training: gradient steps on the combined loss
    for each gradient step do
        𝒝 ← sample mini-batch from 𝒟
        for each (s, π, z) ∈ 𝒝 do
            (P, V) ← fθ(s)
            ℒ ← (z − V)² − π⊤ log P + λ‖θ‖²
        end for
        θ ← θ − α · ∇θ ℒ
    end for

    ▷ Evaluation: keep only a strictly stronger network
    if fθ beats fθ_best in > τ_win fraction of games then
        θ_best ← θ                            ▷ promote; workers switch weights
    end if
until training complete

6. Why It Works: Generalised Policy Iteration

AlphaZero is an instance of Generalised Policy Iteration (GPI) — the classical RL idea that alternating between policy evaluation and policy improvement converges to the optimal policy.

Classical GPIAlphaZero equivalent
Policy evaluation
Compute \(V^\pi\) for current \(\pi\)		 MCTS estimates \(Q(s,a)\) for the current network policy by simulating games — evaluating how good each action is under the current best play
Policy improvement
\(\pi' \leftarrow \arg\max_a Q^\pi(s,a)\)		 \(\pi_\text{MCTS}\) is the improved policy — concentrating probability on high-\(Q\) actions discovered by search
Repeat
Iterate until \(\pi = \pi^*\)		 Train \(P_\theta \leftarrow \pi_\text{MCTS}\), use improved \(P_\theta\) to focus the next round of search — iterate until superhuman

The neural network serves two roles simultaneously: it is the policy (the policy head is directly used to act or to guide MCTS), and it approximates the value function (the value head). Both improve together because they share a trunk — better representations help both.

7. The AlphaGo → AlphaZero → MuZero Lineage

2016
AlphaGo

First version to beat a professional Go player. Used supervised learning on 30M human moves to bootstrap the policy, a separate fast rollout network for MCTS simulation, and a value network trained on those human-seeded games. Go only.

2017
AlphaGo Zero

Eliminated all human data — random initialisation, pure self-play from scratch. Replaced the separate rollout network with the value head (one network instead of three). Beat the original AlphaGo 100–0 after 3 days of training. Go only.

2017
AlphaZero

Generalised AlphaGo Zero to any two-player zero-sum game with a perfect simulator. A single algorithm mastered chess, Go, and shogi — beating the strongest dedicated programs in each. Chess in 4 hours, shogi in 2 hours, Go in 8 hours from random play.

2019
MuZero

Removed the requirement for a known environment model. MuZero learns a latent dynamics model \(\hat{P}\) alongside the value and policy, then plans inside that learned model. Mastered Atari (no rules given) and board games from the same algorithm.

The key progression: AlphaGo (human data + three networks) → AlphaGo Zero (no human data + one network) → AlphaZero (no human data + one network + any game) → MuZero (no human data + no model + any game). Each step removes an assumption.

8. AlphaZero and LLM RL

The AlphaZero paradigm maps onto LLM reasoning and alignment in ways that are actively shaping current research:

AlphaZero conceptLLM equivalent
Policy head \(P_\theta(a \mid s)\) The language model itself — next-token probabilities
Value head \(V_\theta(s)\) Outcome reward model (ORM) or process reward model (PRM) scoring a partial response
Self-play Generating training data by having the model solve problems and verify its own answers (works for math, code, logic — any domain with a verifier)
MCTS search at inference Test-time compute scaling — run MCTS over reasoning steps to find better solutions, then use those solutions as training data
Game outcome \(z\) Verifier signal: is the final answer correct? (binary for math/code; scalar for open-ended tasks)
GPI loop Model generates solutions → verifier scores them → train model on high-scoring solutions → model improves → repeat

The critical requirement AlphaZero transfers directly: a verifier. In games, the simulator provides ground truth (did you win?). In LLM RL, you need an equivalent — a reward signal that is reliable and hard to game. This is easy for formal domains (unit tests for code, exact-match for math) and hard for open-ended tasks (helpfulness, style, safety), which is exactly why RLHF with human preference labels exists for the latter.

Reinforcement learning from verifiable rewards (RLVR)

Training LLMs with outcome-based verifiers — no human labels, just "is the answer correct?" — is sometimes called RLVR. DeepSeek-R1-Zero demonstrated this at scale: a base LLM trained purely on math and code correctness signals, with no supervised reasoning traces, spontaneously developed chain-of-thought and self-correction behaviours analogous to AlphaZero's emergent move sequences. The AlphaZero insight — give the model a verifiable signal and let search find the solution — applies directly.
