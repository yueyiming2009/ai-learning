Agentic RL · Engineering Guide

From Training Metrics to Trace Diagnosis

Find the episode behind the curve, the event behind the episode, and the training sample that actually reached the optimizer.

Evidence boundary — November 6, 2026.

Based on official OpenTelemetry, Weave, MLflow, Langfuse, Phoenix, verl and Agent Lightning sources. The local lab is synthetic, not a captured production incident or benchmark. Backend integrations and GPU training have not been executed for this guide. Custom rl.* fields and the deployment design below are recommendations, not a cross-vendor standard. Use only reviewed, approved SDKs, images and destinations; no plugin, integration, or external service is needed to explore this page.

This guide owns collection → inspection → diagnosis. Read Async RL Monitoring for optimizer statistics, Harnessed Agentic RL for token contracts, and Practical Agentic RL Training for the experiment sequence. A successful model API call is not a successful task; a successful task is not necessarily a valid training sample; a valid sample is not proof of an applied update.

1. Three connected data planes, not one giant log

PlaneQuestionRecord / retention contract
MetricsWhich run, step, task source or harness regressed?Aggregated rewards, valid/invalid counts, queue age, latency histograms, throughput, KL and gradient statistics. Compute population counts before trace sampling.
Diagnostic tracesWhat happened during a particular attempt?Model/tool/verifier spans, dependencies, errors, safe previews and artifact references. Can be sampled, bounded and redacted.
Training ledger + artifactsWhat evidence generated this update?Durable task/attempt manifest, exact sampled tokens, masks, behavior logprobs, rewards, group membership, admission decisions, sample hashes and update receipts. Complete for the admitted data, within the approved retention policy.
 
scheduler / harness / model gateway / tools / verifier / learner
    | safe spans + context                 | authoritative training events
    v                                      v
local Collector -> gateway -> trace UI      durable ledger + artifact storage
    |                                      |
    +------- run / attempt / sample IDs ----+
                       |
           metrics dashboard -> cohort -> episode -> sample -> update

A sampled trace backend is not the training database. Export queues can lose spans, UIs truncate payloads, and tail sampling deliberately biases the visible population. Capture training-critical evidence durably before accepting a sample, independently of whether its diagnostic trace survives. If mandatory evidence is missing, quarantine the sample under an explicit policy; do not silently replace missing rewards or probabilities with zero.

Conversely, an unavailable trace UI need not stop learning if the authoritative ledger remains healthy. Separate these failure policies. For long-running episodes, emit bounded operation spans and durable lifecycle events rather than relying on one root span that exports only at completion.

3. Identity is the integration: a trace tree is not training lineage

One episode may contain multiple attempts and subagents. One attempt may produce several training samples after context compaction; one optimizer update consumes many samples. Some samples may be used in multiple optimization epochs. Those are different relationships.

ObjectProposed join keysEvidence to preserve
Run / taskrl.run_id, task-set version, task ID, splitImmutable run manifest: source/config revisions, harness, environment image, verifier, tokenizer and chat-template identities.
Rollout grouprl.group_id, expected member IDsPrompt identity, requested group size, attempted/valid/admitted membership and the actual reward normalization rule.
Episode / attemptrl.rollout_id, rl.attempt_idTerminal state, retry reason, task outcome, invalid classification and timeout budget. Keep invalid attempts in the manifest.
OperationOTel trace/span IDs; model-call, tool-call, branch and agent IDsParent or span links, start/end timestamps, queue versus execution time, finish reason and structured errors.
Generation segmentCall ID, behavior policy version, token rangeExact prompt/response IDs, sampled-action logprobs, sampling settings and finish/truncation state. Versions may change within one episode.
RewardAttempt ID, verifier version, reward event IDRaw components, grading validity, transformations, persisted reward, delivery acknowledgement and artifact digest.
Training samplerl.sample_id, source call/event IDs, content digestSelected branch, prefix/compaction decisions, masks, reward/advantage assignment, admission or rejection reason.
Update / checkpointUpdate ID, sample-use records, checkpoint digestLearner version, epoch/minibatch, correction/filtering decisions and successful update/checkpoint receipt.

rl.* above is a proposed application namespace. Keep standard OTel fields such as service.name and documented gen_ai.operation.name separate. Pin the instrumentation and semantic-convention versions in the manifest, and test the backend's mapping with one known trace before assuming that a custom attribute is indexed.

Parent-child spans express execution nesting. Use links for fan-in, retries with independent execution, or a learner batch consuming many episode traces. Keep the durable many-to-many lineage table even if the UI cannot render span links. Do not parent an update under one arbitrary rollout or keep a training-run span open for days.

Transport retries reuse the logical event's idempotency key but get distinct send-attempt records. A new harness action after seeing a failure is a new action, even if its prompt is identical. A new rollout attempt gets a new attempt ID. Deduplicate transport delivery, not legitimate exploration. OTel context is correlation metadata, never an authorization credential.

4. Collection recipes: start with the boundary you control

A. Existing verl agent loop: native traces first

The source-pinned verl guide and implementation support weave, mlflow and trackio. This is a configuration overlay for an already-working agentic recipe, not a complete training launcher. Provision the approved backend and inject credentials through your secret manager before enabling export.

actor_rollout_ref:
  rollout:
    mode: async
    trace:
      backend: weave
      token2text: false
      max_samples_per_step_per_worker: 2
trainer:
  project_name: agentic-rl
  experiment_name: code-debug-preflight
  logger: [console, wandb]

The cap selects up to two unique samples per worker per step, with their GRPO rollouts. With four workers and four rollouts per selected sample, the nominal ceiling is 2 × 4 × 4 = 32 traced trajectories per step, not two globally. Check actual worker assignment and membership in the exported data. This is a diagnostic trace-volume knob, not a training-data filter. rollout.mode=async enables the relevant rollout execution path; it does not by itself mean the learner updates asynchronously.

  1. Run one approved preflight task. In Weave, filter on experiment_name, step, sample_index and rollout_n. Inspect the agent-loop operation and its per-turn model calls, then compare a successful and a failed sibling rollout.
  2. For MLflow instead, use backend: mlflow, the approved MLFLOW_TRACKING_URI, and optionally logger: [console, mlflow]. The pinned recipe uses experiment-level Traces and a filter such as tags.step = '1'. Verify run association rather than assuming it.
  3. Inspect the pinned rollout_trace_op/rollout_trace_attr hooks before adding custom operations. Built-in tracing covers instrumented functions, not every remote service. Add correlation at the sandbox, verifier, sample-construction and learner boundaries.
token2text: false is not redaction. It disables extra decoded-text fields; the adapter still captures function inputs/outputs and can retain token IDs. Tokens can reconstruct sensitive text. Review captured payloads and restrict the destination before turning tracing on; use synthetic tasks for the first export.

B. External harnesses and workers: propagate context explicitly

Use reviewed automatic instrumentation where available, then fill missing boundaries. A local context variable does not automatically cross a Ray task, process, queue or Kubernetes Job. The following OTel API pattern is an integration sketch: each process needs its own configured provider/exporter, and the queue/application functions are yours. It intentionally propagates W3C trace context, not arbitrary baggage.

from opentelemetry import trace
from opentelemetry.trace.propagation.tracecontext import TraceContextTextMapPropagator

tracer = trace.get_tracer("agentic-rl")
propagator = TraceContextTextMapPropagator()

def enqueue_verification(queue, run_id, attempt_id, artifact_ref):
    with tracer.start_as_current_span("verifier.enqueue"):
        carrier = {}
        propagator.inject(carrier)
        queue.put({
            "trace_context": carrier,
            "run_id": run_id, "attempt_id": attempt_id,
            "artifact_ref": artifact_ref,
        })

def process_verification(job, verify, persist):
    parent = propagator.extract(job["trace_context"])
    with tracer.start_as_current_span(
        "verifier.execute", context=parent,
        attributes={"rl.run_id": job["run_id"], "rl.attempt_id": job["attempt_id"]},
    ) as span:
        result = verify(job["artifact_ref"])
        receipt = persist(job["attempt_id"], result)
        span.set_attribute("rl.reward_event_id", receipt.event_id)
        return receipt

Authenticate the worker and authorize artifact access independently. Strip trace context at unapproved egress boundaries; never propagate secrets or prompts in baggage. Correlate structured logs with trace/span and attempt IDs. Record queue timestamps and a separate queue-wait operation: an enqueue span only measures the send, not the consumer's wait. Use monotonic time for durations within a process; do not subtract unrelated hosts' monotonic clocks.

For a Langfuse destination, the official integration accepts OTLP/HTTP at /api/public/otel/v1/traces; do not configure a gRPC exporter for that endpoint. Its current v4 instructions require x-langfuse-ingestion-version: 4 for real-time ingestion and propagate filterable metadata to every relevant observation. Obtain the region-specific base URL and auth from the approved deployment. For Phoenix, its phoenix.otel.register wrapper configures a provider; auto_instrument=True activates installed OpenInference instrumentors, not all libraries by magic. Avoid initializing multiple competing global providers. See Langfuse OTLP and Phoenix setup.

C. Token-faithful training capture: observe at the model gateway

Agent Lightning v1.0 supplies a concrete public design: rollout/attempt-specific proxy URLs, append-only model_request and reward events, and trainer-side conversion into samples. The gateway captures prompt IDs, sampled response IDs and chosen-token logprobs; the controller owns execution lifecycle.

Use that separation when the harness is a binary or owns its own context management. A generic chat tracer cannot recover exact sampled token IDs or the actual sampling distribution after the fact. A model proxy cannot see every filesystem mutation or failed tool launch either. Join gateway events to runtime/tool events, and inspect the sample-stitching contract rather than training on a transcript downloaded from the UI.

5. Operate the telemetry pipeline as a real service

Small preflight: one approved trace backend, explicit context propagation and a complete local artifact/attempt ledger. Distributed training: node/pod-local collection, a gateway tier, bounded queues and separate durable training storage. A Collector is useful for OTLP traffic; it is not automatically in the path of a framework's native SDK exporter.

LayerConcrete deployment responsibilityFailure to exercise
SDK / local collectorBatch export, size limits, source-side safe-field allowlist, shutdown flush, measured CPU/latency overhead. Bind local receivers to loopback where possible.A short-lived worker exits with queued spans; a process crashes before its root span closes.
Gateway collectorAuthenticated/TLS ingress, memory limits, tenant routing, batch/retry and an exporter sending queue backed by file_storage on persistent storage where required.Backend outage, full queue, expired retry window, disk exhaustion and collector restart.
Buffer / storageAdd a durable broker such as Kafka only when the outage budget justifies its complexity. Track retention and consumer lag. A Collector WAL improves resilience but is not exactly-once delivery.Duplicates, out-of-order arrival, acknowledged-but-unindexed events and broker retention expiry.
Trace backendSearch indexes for safe cohort metadata, latency/cost views, artifact access checks, ingestion-lag monitoring and retention/deletion enforcement.A trace appears incomplete because indexing is delayed, not because the agent skipped a step.
Training ledgerIdempotent event writes, expected-attempt manifest, immutable/versioned artifacts and an admission gate that requires complete evidence.A trace exports successfully while the reward or training artifact fails to persist.

The Collector resiliency guide documents sending queues, WALs and broker tiers, including their remaining loss modes. Watch queue size/capacity, failed exports, dropped/refused spans and ingestion delay. Validate the final configuration with the approved Collector binary's validate --config=... command; component names and availability depend on the pinned distribution.

Langfuse's published self-hosted architecture makes the operational cost concrete: Web/API and Worker services, PostgreSQL for transactional data, ClickHouse for observability data, Redis/Valkey for cache/jobs, and object storage for raw events/attachments. Self-hosting is a data-control option, not “run one container and forget backups.” Its raw-event storage does not automatically become your complete RL training ledger.

Sampling without corrupting the learning story

During a bounded synthetic preflight, retain all diagnostic traces. At scale, retain a random baseline plus selected errors, slow traces, unusual rewards and new policy/harness versions. Record the selection policy; record inclusion probabilities where known. Population success rates and latency percentiles must come from the complete attempt ledger or unsampled metrics, not the error-heavy trace explorer.

Head sampling cannot guarantee retention of later failures. Tail sampling cannot recover spans already dropped by an upstream sampler. It also needs consistent routing of a trace's spans, enough memory and a decision window appropriate to the workload. Hour-long episodes and delayed graders do not fit a casually chosen 30-second window: use bounded linked traces and explicit completion events, and retain durable evidence outside the sampling pipeline. Configure and test late-span handling.

Preserve the entire comparison group in the ledger even when the UI shows one rollout. GRPO advantages depend on sibling rewards. Selecting only successful traces for inspection is useful; selecting them as if they were the complete group changes the learning problem. UI sampling and training admission are separate policies.

Cost estimate: 2,000 spans/second at an illustrative 2 KiB per encoded span produce about 4.1 MB/second, or 354 GB/day before compression, indexes and replicas. A ten-minute outage needs about 2.46 GB of payload buffering, plus overhead. Measure actual sizes; do not log full token arrays on every span. Use restricted artifact references with bounded previews. Task/trace IDs belong in searchable events, not unbounded metric-label sets.

Redaction is not a training transform. Redact or omit sensitive content in diagnostic views before export. Preserve authorized exact training artifacts in a restricted store, or exclude the sample when policy forbids retention. Never redact token arrays in place and then reuse the old logprobs. Enforce tenant ACLs on artifact dereference, avoid permanent signed URLs in logs, and propagate deletion to derived datasets and backups under the retention policy.

7. Diagnose the first broken boundary, then test the explanation

  
Start from an anomalous cohort: fixed task source, harness/version, policy version and
  budget. Preserve its denominator. Compare representative successes, failures and invalid attempts;
  inspect a matched baseline where possible. One trace establishes what happened in that execution,
  not the population prevalence or the causal effect of a proposed fix.

  
Case A: verifier success, reward-delivery failure

  
The first trace's verifier records raw_reward=1. The reward delivery returns a 503,
  no durable receipt exists, yet sample construction substitutes reward=0 and admits it.
  The model's answer is not the first broken boundary: reward persistence/admission is.
  Missing score and valid zero score must be distinct states.

  
The synthetic group has verifier rewards [1, 0, 1, 0]. For an explicitly
  mean-centered, non-standardized objective, the intended advantages are
  [0.5, -0.5, 0.5, -0.5]. With the first score silently zero-filled, the batch sees
  [0, 0, 1, 0] and computes [-0.25, -0.25, 0.75, -0.25].
  The successful first rollout now receives a negative advantage, and every sibling changes.
  This is not the z-scored formula used by every GRPO implementation; log your actual reduction.

  
Action: quarantine the affected group pending its declared completeness policy,
  recover the reward from immutable verifier evidence or rerun only the verifier when valid,
  persist with an idempotency key, rebuild the group, and verify admission no longer accepts missing
  receipts. If an update already consumed it, identify impacted updates/checkpoints and use the run's
  recovery policy; changing a trace in the UI does not undo a gradient.


  
Case B: slow episode, fast model

  
The second episode takes 42 seconds. Its two model calls take 6 and 2 seconds.
  The tool span takes 31 seconds, but its children separate 30 seconds waiting for a sandbox
  from 1 second executing. A parallel branch takes 11 seconds and finishes before the
  sandbox becomes available. The fixture's scheduler evidence says no sandbox slot was available.

  
Action: inspect sandbox pool occupancy, provisioning, quotas and queue age for
  this cohort; compare against an otherwise matched healthy attempt. Test one capacity/admission change
  and remeasure completed valid episodes per hour. Increasing model GPU capacity does not directly
  remove this queue. Extra rollout concurrency can increase KV pressure and policy lag, so check both
  before calling a throughput change an improvement.


  
Case C: healthy-looking task, invalid training sample

  
The third verifier and reward delivery succeed. Its materialized toy sample has roles
  [assistant, tool, assistant] but mask [1, 1, 1].
  In this policy-gradient recipe the tool token was not sampled by the policy; its mask must be zero.
  Its missing behavior logprob is another admission failure, not a value to invent.
  The sample builder nevertheless admits it. A pretty conversation view and positive reward miss
  this bug completely.

  
Action: stop admission, reconstruct from original call/token events and compare
  the chosen branch, prefix boundaries, token alignment, behavior probabilities and mask.
  Re-tokenizing the displayed transcript is not a repair. Replay sample construction and check the
  expected artifact digest before resuming; then audit which updates consumed the invalid version.

8. Reproduce the reward-to-advantage audit offline

  
This page embeds the same synthetic evidence used by the inspector. From a repository checkout,
  run the following standard-library-only command. It reads the HTML as data;
  it does not execute its JavaScript, call a provider, install a package, or run training.
  Keep the expected-member manifest when adapting this to real ledger exports.

  
python3 - docs/rl/agentic-rl-observability.html <<'PY'
import json
import sys
from html.parser import HTMLParser
from pathlib import Path

class FixtureParser(HTMLParser):
    def __init__(self):
        super().__init__()
        self.capture = False
        self.parts = []

    def handle_starttag(self, tag, attrs):
        self.capture = tag == "script" and dict(attrs).get("id") == "trace-fixtures"

    def handle_endtag(self, tag):
        if tag == "script":
            self.capture = False

    def handle_data(self, text):
        if self.capture:
            self.parts.append(text)

parser = FixtureParser()
parser.feed(Path(sys.argv[1]).read_text())
data = json.loads("".join(parser.parts))
assert data["schema_version"] == 1
case = next(c for c in data["cases"] if c["id"] == "reward")
spans = {s["id"]: s for s in case["spans"]}
assert len(spans) == len(case["spans"]), "duplicate span ID"
verifier = spans["verify"]["evidence"]
delivery = spans["deliver"]["evidence"]
sample = spans["sample"]["evidence"]
update = spans["update"]["evidence"]
assert verifier["valid"] and verifier["raw_reward"] == 1
assert not delivery["persisted"] and delivery["receipt_id"] is None
assert sample["admitted"] and sample["reward"] == 0
assert sample["sample_id"] in update["sample_ids"]
assert update["optimizer_applied"] and update["receipt_id"]

group = data["group"]
rows = {r["rollout_id"]: r for r in group["members"]}
expected = group["expected_rollouts"]
assert len(set(expected)) == len(expected), "duplicate manifest member"
assert len(rows) == len(group["members"]), "duplicate observed member"
assert set(rows) == set(expected), "missing or unexpected member"
assert rows[case["rollout_id"]]["materialized_reward"] == sample["reward"]
assert group["reward_transform"] == "identity"
assert group["advantage_rule"] == "mean_center_only"

def centered(values):
    mean = sum(values) / len(values)
    return [round(v - mean, 2) for v in values]

raw = [rows[key]["verifier_reward"] for key in expected]
used = [rows[key]["materialized_reward"] for key in expected]
print("BOUNDARY FAILURE: missing reward receipt was admitted as zero")
print("verifier rewards:", raw)
print("materialized rewards:", used)
print("intended advantages:", centered(raw))
print("materialized advantages:", centered(used))
assert centered(raw) == [0.5, -0.5, 0.5, -0.5]
assert centered(used) == [-0.25, -0.25, 0.75, -0.25]
print("ACTION: quarantine/recover the group; identify affected updates")
PY

  
The assertions deliberately confirm an injected bad state and its consequence.
  They are not a production validator accepting such data. A real admission validator should
  reject missing reward receipts, invalid grading, non-finite trainable logprobs,
  inconsistent token/mask lengths, unexpected group membership and unresolved lineage.
  Keep raw reward, transformed reward and learner advantage as separate fields.


  
9. Replay has three different meanings

  

    
ReplayInputsClaim it can support

    
      
Regrade evidenceRetained patch/output/environment evidence plus pinned verifier and grading configuration.Whether the same evidence receives the same verdict, or how a changed grader scores it. Version new results; never overwrite the historical reward.

      
Rebuild samplesImmutable model-call events, exact token data, stitching/mask rules, branch selection and group records.Whether the materialized training sample and advantages can be regenerated. Compare hashes and arrays; this is the most controlled replay boundary.

      
Re-execute the agentTask snapshot, harness/tools, image, model/sampling settings and permitted external state.Behavior under a recreated environment, not guaranteed reproduction of the original trajectory. Seeds alone do not control remote services, GPU nondeterminism or concurrent state.

    
  

  
Record whether tools are stubbed, sandboxed or live. Do not replay state-changing tools against
  production accounts. A new execution gets a new attempt ID and a link to the original.
  A changed verifier or sample builder creates a new artifact version. Replay is not an implicit
  authorization to re-enroll data in training.

  
Promote confirmed incidents into a small regression corpus: missing reward receipt, tool timeout,
  intentional retry, subagent branch, compaction boundary, mixed policy versions and malformed masks.
  Preserve the independent task-success checks in
  Agent Evaluation; a trace classifier
  or LLM judge should propose a failure category with cited events, not replace verifiable outcomes.


  
10. Acceptance gates before scaling collection

  

    
GateEvidence required

    
      
One complete episodeDashboard cohort resolves to attempt, model/tool/verifier operations, durable reward, materialized sample and update receipt. Join errors are explicit, not empty UI panels.

      
Group integrityAll expected attempts are accounted for; invalid and excluded attempts have reasons. Show raw rewards, admitted membership, normalization and sample-use records.

      
Failure injectionDrop a reward acknowledgement, kill a worker, interrupt the backend and duplicate a transport message. No silent sample admission, denominator shrinkage or duplicate training use.

      
ReplayRegrading and sample rebuilding pass on retained authorized fixtures; nondeterministic re-execution is labeled separately.

      
Telemetry healthMeasure overhead against tracing disabled, queue/disk limits, dropped spans, freshness and costs at expected load. Test shutdown flush and long-episode/late-span behavior.

      
Access and retentionSynthetic secret/redaction probes, cross-tenant access checks, approved export destinations, artifact ACLs and deletion propagation. Never use real credentials as probes.

    
  

  
Done means an engineer can explain one update from retained evidence.
  Not just “the dashboard has lines,” but which attempts contributed, what the agent and environment
  did, how the verifier scored them, which tokens carried loss, and why those samples were admitted.
