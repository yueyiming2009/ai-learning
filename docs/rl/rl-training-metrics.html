RL Training Basics & Metrics

What the actor is optimizing, what advantages and returns mean, and how to read loss, rollout, length, and throughput fields without mistaking them for model quality.

Start here when a dashboard shows actor/loss, actor/pg_loss, critic/advantages, critic/returns, or global_seqlen. The concepts apply broadly; the exact keys below describe a pinned verl implementation, not a universal logging standard. For asynchronous failure diagnosis, continue to Monitoring & Diagnosis for Async RL.

Source-checked 2026-10-23 against public verl commit 3c6d9b43b67c: RayPPOTrainer, the engine-worker PPO/value losses, and the vanilla policy-loss mode. Optional losses, other estimators/backends, and custom loggers can change what is emitted. Source inspection, not a training-run benchmark.

1. The training loop: data becomes a signed learning signal

In token-level LLM RL, a state is the prompt and available history, an action is a generated token, and a policy assigns probabilities to possible next tokens. A rollout is the sampled response or, for an agent, a trajectory interleaving model actions and environment observations. A reward scores an outcome; it is not itself a differentiable loss through the sampled text.

  1. 1. Prompt and rolloutSample tasks and generate one or more responses per prompt. Retain action tokens, masks, and behavior-policy log-probabilities.
  2. 2. Score and rewardA verifier or reward model scores the response. Shaping, such as a reference-policy KL penalty, may alter the rewards used for training.
  3. 3. BaselinesPPO evaluates a critic. GRPO instead compares multiple responses to the same prompt. Neither baseline is the actor's loss.
  4. 4. Returns and advantagesConstruct value targets and signed action weights: which sampled decisions should become more or less likely?
  5. 5. Loss and updateRecompute probabilities with the trainable actor, form a masked surrogate loss, backpropagate, and update parameters. PPO also fits its critic.
  6. 6. Repeat and evaluatePublish updated rollout weights and collect more data. Measure held-out task quality separately from optimization and throughput metrics.
RoleQuestion it answersWhen it changes
Actor \(\pi_\theta\)Which action should I take? Its log-probability \(\log\pi_\theta(a\mid s)\) supplies the gradient.At actor optimizer updates.
Rollout / behavior policy \(\mu\)Which policy actually sampled this action?When rollout workers receive weights; async workers may lag behind.
Old / proximal snapshotWhat is the fixed denominator of this PPO update's probability ratio?At the chosen snapshot boundary, not every minibatch update. It may differ from \(\mu\).
Reference policy \(\pi_{\rm ref}\)How far have we moved from an anchor, often the initial fine-tuned model?Usually frozen for the run; not the same as the old-policy snapshot.
Critic \(V_\psi(s)\)How much future reward do I expect from this state?At critic updates in PPO/GAE. Standard GRPO has no learned critic.

A reward model judges an outcome; a critic predicts future return from a state. They are different roles even if both output scalars. See Value Functions, Policy Gradient, and Behavior vs Target Policy for the underlying definitions.

2. A tiny PPO example: reward, return, advantage, loss

Take one response with two valid action tokens, no padding or KL penalty, and a true terminal state after token 2. Let \(\gamma=\lambda=1\), rewards be \([0,1]\), and frozen critic estimates be \([0.2,0.4]\), with terminal value zero. GAE works backward:

\[ \delta_t=r_t+\gamma V_{t+1}-V_t,\qquad A_t^{\rm raw}=\delta_t+\gamma\lambda A_{t+1}^{\rm raw},\qquad \widehat R_t=A_t^{\rm raw}+V_t. \]
TokenReward \(r_t\)Value \(V_t\)TD error \(\delta_t\)Raw advantageReturn target
100.20 + 0.4 - 0.2 = 0.20.2 + 0.6 = 0.80.8 + 0.2 = 1
210.41 + 0 - 0.4 = 0.60.60.6 + 0.4 = 1

Return: the critic's target is 1 at both positions here. With other \(\lambda\), discounts, or bootstrapping boundaries, a GAE return need not equal the undiscounted episode score. Advantage: both actions had better outcomes than the frozen critic predicted. The actor receives detached advantages, not a gradient through the reward computation or critic.

The pinned GAE function builds returns before whitening advantages. With these two tokens, the raw advantage mean is 0.7 and the sample standard deviation is \(\sqrt{0.02}\). Whitening produces approximately \([+0.7071,-0.7071]\). The critic still targets \([1,1]\); adding the whitened advantages to values would be wrong. Whitening centers the actor's weights within this batch, so a negative normalized weight does not necessarily mean a negative raw advantage or a failed response. Estimator source.

Why zero policy loss can still learn

Ignoring optional corrections and dual clipping for this illustration, minimize the PPO surrogate

\[ L_{\rm PG}=-\operatorname{mean}_{m_t=1} \min\!\left(q_t\widehat A_t,\, \operatorname{clip}(q_t,1-\epsilon,1+\epsilon)\widehat A_t\right), \qquad q_t=\exp(\log\pi_\theta(a_t\mid s_t)-\log\pi_{\rm old}(a_t\mid s_t)). \]

At the start of a fresh update, \(q_t=1\), so our token-mean loss is approximately zero. But the ratios are functions of the actor parameters, not constants to remove before differentiating:

\[ \nabla_\theta L_{\rm PG}\big|_{q=1} =-\tfrac12\left(0.7071\nabla_\theta\log\pi_\theta(a_1\mid s_1) -0.7071\nabla_\theta\log\pi_\theta(a_2\mid s_2)\right). \]

The two score gradients generally differ, so they need not cancel. A near-zero pg_loss and zero clip fraction are compatible with a real update. Conversely, a nonzero loss does not prove useful learning. Check gradients, parameter updates, and held-out outcomes.

What changes for GRPO?

Sample a group of responses to the same prompt and compare their sequence rewards: \(A_i=(R_i-\bar R_{\rm group})/(s_{\rm group}+\varepsilon)\), or just subtract the mean when standard-deviation normalization is disabled. Broadcast each response's weight over its valid action tokens. There is no value prediction or value-regression update.

For rewards \([0,0,1]\), sample-standard-deviation normalization gives approximately \([-0.577,-0.577,1.155]\). The sequence-level mean is zero, but the signs are two negative, one positive, not necessarily 50/50. Unequal response lengths can also make the token-weighted logged mean nonzero. Equal rewards within a multi-response group give zero centered reward signal, whether the group all succeeded or all failed.

The returns field is estimator-dependent

The pinned compute_grpo_outcome_advantage returns the same group-relative tensor in both the advantages and returns slots. Thus critic/returns/* in this GRPO path is not a critic target or raw episode-return measurement. The critic/ prefix is a logging namespace, not evidence that a critic exists. Use critic/score/* and critic/rewards/* for sequence outcomes.

3. Actor and optimization metrics

For the pinned PPO loss, with optional entropy and reference-KL terms enabled:

\[ L_{\rm actor}=L_{\rm PG}-c_H H+\beta L_{\rm KL}. \]

Each term uses the configured loss reduction. Entropy and KL coefficients multiply their logged unweighted terms; disabled terms are absent. In this separate-actor/critic path, critic value loss is not part of actor loss. Distillation or other auxiliary objectives require inspecting their own composition. Loss source · Worker aggregation.

Loss terms use global-normalization-aware Metric aggregation. Vanilla clip/KL diagnostics start as local masked means and are then mean-aggregated; with unequal token counts this need not equal a single global token-weighted mean. Do not reconstruct an exact global fraction from an unspecified dashboard average.

Empty valid-token sets produce NaN diagnostics, not evidence of zero loss or successful training.

5. Lengths, masks, and the denominator of a loss

In a simple text response, attention_mask selects non-padding prompt and response tokens. response_mask selects positions that contribute action loss and signal statistics. In multi-turn agent data, tool observations may be attended to but excluded from action loss. Tokens processed, tokens generated, and tokens trained on need not be equal.

MetricDefinition / unitsWhat it does not prove
prompt_length/*
response_length/*		Mean/min/max tokens per sequence. Uses supplied length fields if present; otherwise sums the corresponding attention-mask regions.Response length is not necessarily the number of policy-loss tokens in an agent trajectory. Longer output is not inherently better reasoning.
response_length/clip_ratio

response/aborted_ratioFraction with measured response length zero.Not every failure has zero length. Pair with outcome/error and termination evidence.
response_length_non_aborted/*Mean/min/max and clip_ratio restricted to nonzero-length responses.Excludes aborts by design; use the all-response view alongside it.

The same token losses can produce different scalar losses

For token losses \(\ell_{it}\), mask \(m_{it}\), valid-token count \(T_i\) per sequence, and \(N\) nonempty sequences, the principal reduction modes are:

ModeLogical global objectiveWeighting consequence
token-mean\(\sum_{i,t}m_{it}\ell_{it}/\sum_i T_i\)Equal weight per valid token; a longer response contributes more tokens.
seq-mean-token-mean\(\frac1N\sum_i\frac1{T_i}\sum_t m_{it}\ell_{it}\)Equal weight per response after its own token mean.
seq-mean-token-sum\(\frac1N\sum_{i,t}m_{it}\ell_{it}\)Longer responses contribute more; overall scale grows with average length.
seq-mean-token-sum-normThe previous quantity divided by a normalization length \(C\).Check whether \(C\) is a configured constant or defaults to tensor width; it is not each response's actual length.

These describe the intended global objectives, not unscaled per-rank intermediates. Changing masks or reduction changes weighting and often gradient scale. Do not compare absolute loss magnitudes across such changes as if they were the same experiment.

6. global_seqlen is a load-balancing metric family

In the pinned trainer, global_seqlen is a prefix, not one scalar. When batch balancing is enabled, the trainer sums each row's full attention_mask, then partitions sequences across data-parallel (DP) workers. The logger summarizes sums of those lengths per partition. It does not report the model context limit or the longest individual response. Producer and logger.

KeyExact logged quantity
global_seqlen/min
global_seqlen/max		Minimum/maximum token totals of the original contiguous equal-row-count chunks, before the new assignment.
global_seqlen/minmax_diffOriginal maximum partition total minus original minimum, in tokens. This is the before gap.
global_seqlen/balanced_min
global_seqlen/balanced_max		Minimum/maximum token totals after the computed partition assignment.
global_seqlen/meanTotal non-padding tokens in the batch divided by the number of DP partitions; tokens per partition, not tokens per sequence.

Example: full lengths \([10,10,30,30]\) on two DP partitions initially give totals \([20,60]\). Reassign one short and one long sequence to each partition: \([40,40]\). The logged min/max/difference are \(20/60/40\), balanced min/max are \(40/40\), and mean is \(40\). The batch has \(80\) tokens; average sequence length is \(20\).

To assess the new assignment, compute balanced_max - balanced_min, optionally divided by a positive global_seqlen/mean. These are derived diagnostics, not additional built-in fields in this logger. Smaller token imbalance can reduce stragglers, but the partitioner also uses a workload model and token equality does not guarantee equal runtime (attention lengths, MoE routing, and hardware matter). TP/PP ranks do not each represent another independent DP data partition.

7. Rollout batches, step counters, and speed

Batch units first: \(B\) prompts with \(n\) responses per prompt normally yield \(B n\) sequences before filtering or retries. A rollout batch is collected data; a training minibatch is a subset used for an optimizer update; a microbatch is a memory-sized piece whose gradients can accumulate before that update. Multiple PPO epochs reuse the batch. Configuration fields may count prompts before rollout expansion, so check their actual units.

Timing and throughput source. For example, 80 total batch tokens in 2 seconds on 2 counted GPUs gives 20 tokens/s/GPU, even if only 40 of those tokens were generated responses. No model-quality claim follows from this number.

8. Read a dashboard in this order

  1. Outcome and data validity: held-out task success, raw score, abort rate, termination reasons, and reward-component integrity. Check that the evaluation denominator includes failures.
  2. Learning signal: reward diversity within prompt groups, advantages and masks, and PPO value fit when a critic exists. Mean-zero normalized advantages alone say little.
  3. Update behavior: total loss versus its components, gradient norm, LR, entropy, and which two policies each KL/ratio compares. Loss need not decrease monotonically as the data and targets change.
  4. Cost and scheduling: lengths, partition load, batch units, timers, and throughput denominators. Establish these basics before attributing a change to async policy lag.

There are no implementation-independent healthy loss or length thresholds. Record the algorithm, source revision, reward scale, normalization, masks, loss reduction, batch/step units, and sampling settings alongside the dashboard.
