This page builds on Value Functions (\(V\), \(Q\), and the advantage decomposition) and Monte Carlo Rollouts (sampling a trajectory and why averaging its returns is unbiased — REINFORCE is the same idea applied to a gradient). Section 3 draws on the bias–variance trade-off developed in TD Learning.

1. The Policy Gradient Theorem

Value-based methods (Q-learning, DQN) learn a value function and act greedily on it. Policy gradient methods skip the value function: parameterise the policy \(\pi_\theta(a\mid s)\) directly, define a scalar objective \(J(\theta)\) = expected return, and do gradient ascent on \(\theta\). The policy gradient theorem is the statement of what \(\nabla_\theta J\) actually is, in a form you can estimate from rollouts.

Where \(\theta\) sits in the objective

Write the objective as an expectation over trajectories \(\tau = (s_0, a_0, s_1, a_1, \dots)\) sampled by running the policy:

\[ J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}[R(\tau)] = \sum_\tau \pi_\theta(\tau)\, R(\tau) \]

Compare this to a supervised loss \(\mathbb{E}_{x\sim\text{data}}[\ell_\theta(x)]\). There the distribution is fixed and \(\theta\) is inside the averaged quantity — sample \(x\), backprop through \(\ell_\theta\). Here it is the other way round: the return \(R(\tau)\) is a number handed back by the environment with no \(\theta\) in it (and no gradient through it — the environment is a black box), while all of the \(\theta\) is in \(\pi_\theta(\tau)\), the probability of seeing that trajectory. Sampling \(\tau\) and backpropagating through \(R\) gives exactly zero. The whole theorem is about moving \(\theta\) from "inside the distribution" to "inside the thing being averaged".

Step 1 — Differentiate the sum

\(R(\tau)\) is constant in \(\theta\), so the gradient lands on the probability:

\[ \nabla_\theta J(\theta) = \sum_\tau \big[\nabla_\theta \pi_\theta(\tau)\big]\, R(\tau) \]

True, but not usable. A sum over all trajectories is not something we can compute. The only operation available in practice is to run the policy and look at the trajectories that come out, which computes averages of the form \(\sum_\tau \pi_\theta(\tau)\,[\cdots] = \mathbb{E}_{\tau\sim\pi_\theta}[\cdots]\). The expression above has \(\nabla_\theta\pi_\theta(\tau)\) where it would need a bare \(\pi_\theta(\tau)\), so it is not the average of anything. The next step restores that shape.

Step 2 — The log-derivative trick

The chain rule on \(\log\) gives \(\nabla_\theta \log \pi_\theta(\tau) = \nabla_\theta \pi_\theta(\tau) / \pi_\theta(\tau)\). Rearranged:

\[ \nabla_\theta \pi_\theta(\tau) = \pi_\theta(\tau)\,\nabla_\theta \log \pi_\theta(\tau) \]

Substituting puts a bare \(\pi_\theta(\tau)\) back in front:

\[ \nabla_\theta J(\theta) = \sum_\tau \pi_\theta(\tau)\,\underbrace{\nabla_\theta \log \pi_\theta(\tau)\,R(\tau)}_{\text{averaged quantity}} = \mathbb{E}_{\tau\sim\pi_\theta}\!\big[\nabla_\theta \log \pi_\theta(\tau)\,R(\tau)\big] \]

This is now a sample average: roll out trajectories, compute \(\nabla_\theta \log \pi_\theta(\tau)\,R(\tau)\) for each, take the mean. The estimate is unbiased for the same reason any Monte Carlo average is. The identity is nothing more than multiplying by \(\pi_\theta(\tau)/\pi_\theta(\tau) = 1\), but it changes what gets measured: \(\nabla\log\pi\) is the relative change in a trajectory's probability ("make this one 5% more likely"), and relative changes are what samples can tell you about, because you only ever see trajectories in proportion to their probability.

Step 3 — The environment drops out

\(\pi_\theta(\tau)\) is the probability of a whole trajectory, and it contains dynamics we do not know. Factorise it into the initial state, the policy's choices, and the environment's responses:

\[ \pi_\theta(\tau) = p(s_0)\prod_{t} \pi_\theta(a_t\mid s_t)\, P(s_{t+1}\mid s_t, a_t) \]

The log turns the product into a sum of three kinds of terms:

\[ \log \pi_\theta(\tau) = \log p(s_0) + \sum_t \log \pi_\theta(a_t\mid s_t) + \sum_t \log P(s_{t+1}\mid s_t, a_t) \]

Now take \(\nabla_\theta\). The first and third terms contain no \(\theta\) — the environment does not depend on the agent's weights — so their gradient is identically zero. Only the policy terms survive:

\[ \nabla_\theta \log \pi_\theta(\tau) = \sum_t \nabla_\theta \log \pi_\theta(a_t\mid s_t) \]

This is the payoff of the whole derivation: the transition model \(P\) never has to be known or differentiated. Each remaining term is the log-probability of a single action the network output, which is ordinary backprop.

Putting the three steps together:

Policy Gradient Theorem
\[ \nabla_\theta J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}\!\left[\Big(\sum_t \nabla_\theta \log \pi_\theta(a_t\mid s_t)\Big)\;R(\tau)\right] \]

Read as a recipe: for each trajectory, push up the log-probability of every action taken, scaled by how good the trajectory turned out. A high-return trajectory makes its actions more likely; a low or negative return makes them less likely. The scalar multiplying \(\nabla\log\pi\) is the only place reward enters, and every improvement in the rest of this page (reward-to-go, baselines, advantage, GAE) is a different choice of that scalar — the theorem guarantees the gradient stays unbiased as long as the choice does not depend on the action in a way that biases it.

Two things that routinely confuse people. (1) \(\log\pi_\theta(a_t\mid s_t)\,R\) is not a loss. It is a surrogate whose gradient happens to equal \(\nabla_\theta J\); its value says nothing about how well the policy is doing, so do not plot it as a training curve. (2) Every action in a trajectory is multiplied by the same \(R(\tau)\), including actions that had nothing to do with the reward. That is the source of the variance problem Sections 2–3 address.
Each \(\log\pi_\theta(a_t\mid s_t)\) is one log_softmax gather over the policy's output logits — \(z_{a_t} - \operatorname{logsumexp}(\mathbf{z})\). See computing log-probabilities from logits for the derivation. 
import torch

def reinforce(policy, env, optimizer, gamma=0.99):
    log_probs, rewards = [], []
    obs, done = env.reset(), False
    while not done:
        dist   = policy(torch.tensor(obs, dtype=torch.float32))
        action = dist.sample()
        log_probs.append(dist.log_prob(action))   # tracks gradient through π_θ
        obs, r, done, _ = env.step(action.item())
        rewards.append(r)

    # reward-to-go: G_t = r_t + γ r_{t+1} + γ² r_{t+2} + ...
    G, returns = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        returns.insert(0, G)
    returns = torch.tensor(returns, dtype=torch.float32)
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)  # baseline

    # ∇J(θ) ≈ Σ_t G_t · ∇ log π_θ(a_t | s_t)
    # returns is a plain tensor (no grad); .detach() would be needed if returns
    # came from a learned critic V_ψ(s_t) to stop gradients flowing into it
    loss = -(torch.stack(log_probs) * returns).sum()
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

Each action's score function \(\nabla\log\pi_\theta(a_t\mid s_t)\) points in the direction that makes \(a_t\) more likely; weighting it by the return reinforces actions from good trajectories and suppresses those from bad ones. This is the REINFORCE algorithm (Williams, 1992), and every ingredient in it is Monte Carlo: the trajectory is a rollout, the returns are rollout returns, and the whole sum is a single-sample estimate of \(\nabla_\theta J\). It is unbiased for the same reason MC value estimation is — the expectation of one sample is the mean.

Worked example — why raw REINFORCE is noisy

A single state with two actions, \(A\) and \(B\), and a softmax policy with logits \(\theta = (\theta_A, \theta_B)\); currently \(\pi(A) = 0.6\), \(\pi(B) = 0.4\). For a softmax the score is \(\nabla_\theta \log \pi(a) = e_a - \pi\), with \(e_a\) the one-hot vector for \(a\):

\[ \nabla_\theta \log \pi(A) = (0.4,\; -0.4), \qquad \nabla_\theta \log \pi(B) = (-0.6,\; 0.6). \]

The episode ends after one step, deterministically: \(R = 1.0\) for \(A\) and \(R = 0.2\) for \(B\). Action \(A\) is clearly better, and the true gradient agrees:

\[ \nabla_\theta J = 0.6 \cdot 1.0 \cdot (0.4, -0.4) + 0.4 \cdot 0.2 \cdot (-0.6, 0.6) = (0.192,\; -0.192). \]

Now look at what a single REINFORCE sample does:

Sampled actionProbability\(R\)\(\hat g = R \cdot \nabla_\theta \log \pi(a)\)Direction for \(\theta_A\)
\(A\)0.61.0\((0.40,\; -0.40)\)up ✓
\(B\)0.40.2\((-0.12,\; 0.12)\)down ✗

Forty percent of the time the update moves \(\theta_A\) the wrong way. The average is right — \(0.6 \cdot 0.40 + 0.4 \cdot (-0.12) = 0.192\) — only because the correct pushes are larger than the incorrect ones. The first coordinate of \(\hat g\) has variance

\[ \operatorname{Var}[\hat g_A] = 0.6 \cdot 0.40^2 + 0.4 \cdot 0.12^2 - 0.192^2 \approx 0.0649, \]

a standard deviation of \(0.255\), larger than the gradient being estimated. The culprit is that both returns are positive: REINFORCE increases the probability of whichever action it happened to take, and relies on the better action being taken more often and pushed harder. The next section fixes exactly this.

2. Variance Reduction: From Return to Advantage

REINFORCE is correct but high-variance — every action is credited with the full trajectory return, including outcomes it had nothing to do with. Three reductions bring it to the form used in practice:

Reward-to-go (causality)

Action \(a_t\) cannot affect rewards collected before it, so replace \(R(\tau)\) with the return-to-go \(G_t = \sum_{t'\ge t}\gamma^{t'-t} r_{t'}\). The dropped early rewards are zero in expectation:

\[ \mathbb{E}\!\left[\nabla\log\pi_\theta(a_t\mid s_t)\, r_{t'}\right] = 0 \quad \text{for } t' < t \]

because the policy at step \(t\) has no influence on what happened before it. This alone can halve the variance on long episodes.

Baseline subtraction

Any function \(b(s_t)\) that depends only on the state (not the action) can be subtracted from \(G_t\) without introducing bias:

\[ \hat g_b = \sum_{t} \big(G_t - b(s_t)\big)\, \nabla_\theta \log \pi_\theta(a_t \mid s_t), \qquad \mathbb{E}[\hat g_b] = \nabla_\theta J(\theta). \]
Step 1 — the score has zero mean under its own policy

Fix a state \(s\) and take the expectation of the score \(\nabla_\theta \log \pi_\theta(a\mid s)\) over actions drawn from the policy itself. Write the expectation as a sum, apply the log-derivative identity in reverse, and notice the \(\pi_\theta\) cancels:

\[ \begin{aligned} \mathbb{E}_{a \sim \pi_\theta}\!\big[\nabla_\theta \log \pi_\theta(a \mid s)\big] &= \sum_a \pi_\theta(a \mid s)\, \nabla_\theta \log \pi_\theta(a \mid s) \\ &= \sum_a \pi_\theta(a \mid s)\, \frac{\nabla_\theta \pi_\theta(a \mid s)}{\pi_\theta(a \mid s)} \\ &= \sum_a \nabla_\theta \pi_\theta(a \mid s) . \end{aligned} \]

The sum is over a finite set of actions and the gradient is linear, so the two can be exchanged. The sum of the probabilities is \(1\) for every \(\theta\), and the gradient of a constant is zero:

\[ \sum_a \nabla_\theta \pi_\theta(a \mid s) = \nabla_\theta \sum_a \pi_\theta(a \mid s) = \nabla_\theta 1 = 0 . \]

Check it on the example above: \(0.6 \cdot (0.4, -0.4) + 0.4 \cdot (-0.6, 0.6) = (0, 0)\). Geometrically, the score vectors of the different actions are arranged so that their probability-weighted average cancels — increasing one action's probability must decrease the others'.

Step 2 — a state-only baseline factors out of the action expectation

Take the baseline term at a single timestep, \(\mathbb{E}\big[b(s_t)\, \nabla_\theta \log \pi_\theta(a_t \mid s_t)\big]\), where the expectation is over the whole trajectory. Split it with the law of total expectation: first average over \(a_t\) holding \(s_t\) fixed, then average over \(s_t\):

\[ \mathbb{E}\big[b(s_t)\, \nabla_\theta \log \pi_\theta(a_t \mid s_t)\big] = \mathbb{E}_{s_t}\Big[\; \mathbb{E}_{a_t \sim \pi_\theta(\cdot\mid s_t)}\big[\, b(s_t)\, \nabla_\theta \log \pi_\theta(a_t \mid s_t) \,\big] \;\Big] . \]

Inside the inner expectation \(s_t\) is fixed, so \(b(s_t)\) is a constant and can be pulled out — this is the one place the "state-only" assumption is used:

\[ = \mathbb{E}_{s_t}\Big[\; b(s_t)\, \underbrace{\mathbb{E}_{a_t \sim \pi_\theta(\cdot\mid s_t)}\big[\nabla_\theta \log \pi_\theta(a_t \mid s_t)\big]}_{=\,0 \text{ by Step 1}} \;\Big] = \mathbb{E}_{s_t}\big[\, b(s_t)\cdot 0 \,\big] = 0 . \]

Now apply this to the full estimator. It is linear in the weighting, so it separates into the original REINFORCE term minus a sum of baseline terms, each of which is zero:

\[ \begin{aligned} \mathbb{E}[\hat g_b] &= \mathbb{E}\Big[\sum_t \big(G_t - b(s_t)\big)\, \nabla_\theta \log \pi_\theta(a_t \mid s_t)\Big] \\ &= \underbrace{\mathbb{E}\Big[\sum_t G_t\, \nabla_\theta \log \pi_\theta(a_t \mid s_t)\Big]}_{=\;\nabla_\theta J(\theta)} \;-\; \sum_t \underbrace{\mathbb{E}\big[b(s_t)\, \nabla_\theta \log \pi_\theta(a_t \mid s_t)\big]}_{=\;0} \\ &= \nabla_\theta J(\theta) . \end{aligned} \]

The only requirement was that \(b\) not depend on the action. A baseline that peeks at \(a_t\) cannot be pulled out of the inner expectation, Step 1 no longer applies, and the gradient becomes biased.

Step 3 — which baseline minimises variance

Any state-only \(b\) is unbiased, so choose the one that makes the estimator least noisy. Work at a single state and write \(\psi = \nabla_\theta \log \pi(a)\), a random vector because \(a\) is random, and \(G\) the random return. The estimate is \((G - b)\,\psi\), and its total variance (summed over coordinates) is

\[ \operatorname{Var}\big[(G - b)\,\psi\big] = \mathbb{E}\big[(G-b)^2\, \|\psi\|^2\big] \;-\; \big\|\mathbb{E}\big[(G-b)\,\psi\big]\big\|^2 . \]

The second term is \(\|\nabla_\theta J\|^2\) — by Step 2 it does not depend on \(b\) — so only the first term needs minimising. Expand the square:

\[ \mathbb{E}\big[(G-b)^2\, \|\psi\|^2\big] = \mathbb{E}\big[G^2\|\psi\|^2\big] \;-\; 2b\, \mathbb{E}\big[G\,\|\psi\|^2\big] \;+\; b^2\, \mathbb{E}\big[\|\psi\|^2\big] . \]

This is a convex quadratic in the scalar \(b\). Differentiate and set to zero:

\[ \frac{\partial}{\partial b} = -2\,\mathbb{E}\big[G\,\|\psi\|^2\big] + 2b\, \mathbb{E}\big[\|\psi\|^2\big] = 0 \quad\Longrightarrow\quad b^\ast = \frac{\mathbb{E}\big[G \,\|\psi\|^2\big]}{\mathbb{E}\big[\|\psi\|^2\big]} . \]

So the optimal baseline is a score-weighted average of the return: returns from actions whose score is large (actions whose probability the gradient can move a lot) count more. In practice the weights are dropped and the plain average \(b(s) = V^\pi(s) = \mathbb{E}[G \mid s]\) is used. It is close to \(b^\ast\) whenever \(\|\psi\|^2\) and \(G\) are weakly correlated, it is a quantity we already know how to estimate by sampling or bootstrapping, and it has a clean interpretation — the advantage, below.

Worked example, continued. The value of the state is \(V = 0.6 \cdot 1.0 + 0.4 \cdot 0.2 = 0.68\). Subtract it:

Sampled actionProbability\(R - V\)\(\hat g_b = (R - V)\cdot\nabla_\theta \log \pi(a)\)Direction for \(\theta_A\)
\(A\)0.6+0.32\((0.128,\; -0.128)\)up ✓
\(B\)0.4−0.48\((0.288,\; -0.288)\)up ✓

Now both samples move \(\theta_A\) the right way — sampling the worse action and seeing a below-average return is evidence for the better one. The mean is unchanged, \(0.6 \cdot 0.128 + 0.4 \cdot 0.288 = 0.192\), while the variance of the first coordinate is

\[ \operatorname{Var}[\hat g_{b,A}] = 0.6 \cdot 0.128^2 + 0.4 \cdot 0.288^2 - 0.192^2 \approx 0.0061 . \]
Effect of the baseline on this example

Same expected gradient \((0.192, -0.192)\); variance down from \(0.0649\) to \(0.0061\) — a factor of about \(10\), the equivalent of running ten times as many rollouts.

This table is the whole argument for critics and for group sampling. The catch is that \(V^\pi(s_t)\) is unknown and must be estimated — by a learned network (PPO's critic, §3) or by more rollouts (GRPO's group mean, which is an MC estimate of \(V^\pi(s_0)\)). Even a crude baseline helps: any \(b\) between \(0.2\) and \(1.0\) flips the sign of the \(B\)-sample's push.

Advantage

With the state-value function \(V(s_t) = \mathbb{E}[G_t\mid s_t]\) as the baseline, the weighted quantity becomes the advantage:

\[ A_t = G_t - V(s_t) = Q(s_t, a_t) - V(s_t) \]

The advantage strips out "this state was generically good/bad" and isolates the signal that is actually about the action: how much better did this specific action perform compared to the average from \(s_t\)? Applying all three reductions:

Policy Gradient with Advantage
\[ \nabla_\theta J(\theta) = \mathbb{E}\!\left[ \sum_{t} \hat A_t \, \nabla_\theta \log \pi_\theta(a_t \mid s_t) \right] \]

Push up the log-probability of actions that outperformed expectations (\(\hat A_t > 0\)); suppress those that underperformed. The remaining question is how to estimate \(\hat A_t\) in practice — that is GAE.

3. Advantage Estimation — GAE

We need \(\hat A_t\) but \(V(s_t)\) is unknown and must be approximated by a learned critic \(V_\psi\). The central tension is the bias–variance trade-off: using the full return-to-go \(G_t - V_\psi(s_t)\) is unbiased but accumulates variance over a long episode; bootstrapping from \(V_\psi\) after one step is low-variance but biased by the imperfect critic. TD Learning §6 develops this spectrum in full — one-step TD, \(n\)-step returns, and how each \(n\)-step advantage telescopes into a sum of TD errors.

Define the one-step TD error:

\[ \delta_t = r_t + \gamma\, V_\psi(s_{t+1}) - V_\psi(s_t) \]

The \(n\)-step advantage is a discounted sum of \(n\) consecutive TD errors: \(\hat A_t^{(n)} = \sum_{l=0}^{n-1}\gamma^l\delta_{t+l}\). Generalised Advantage Estimation (GAE) takes an exponentially-weighted average over every \(n\) — which collapses to a single discounted sum:

GAE
\[ \hat A_t^{\text{GAE}(\gamma,\lambda)} = \sum_{l=0}^{\infty} (\gamma\lambda)^l\, \delta_{t+l} \]
\(\lambda = 0\) keeps only the \(l=0\) term, recovering one-step TD \(\hat A_t = \delta_t\) (low variance, higher bias). \(\lambda = 1\) sums all TD errors, which telescopes to the Monte-Carlo return \(G_t - V_\psi(s_t)\) (unbiased, high variance). \(\gamma\) is the reward discount (part of the problem definition); \(\lambda\) is the variance-reduction knob. RLHF typically uses \(\lambda \approx 0.95,\ \gamma \approx 1\).

Computing it efficiently

The infinite sum is never formed directly — it satisfies a one-line recursion run backward from the end of the trajectory, an \(O(T)\) pass:

\[ \hat A_t = \delta_t + \gamma\lambda\,\hat A_{t+1} \]

The same backward pass yields the critic's regression target, the TD(\(\lambda\)) return \(\hat R_t = \hat A_t + V_\psi(s_t)\), so policy and critic train together:

\[ \mathcal{L}_{\text{VF}}(\psi) = \mathbb{E}_t\!\left[ \big(V_\psi(s_t) - \hat R_t\big)^2 \right] \]

Actor-critic structure

GAE requires a critic \(V_\psi\) trained alongside the policy \(\pi_\theta\) — the actor–critic structure that PPO builds on. In LLM RL this is expensive — a second model as large as the policy. GRPO sidesteps it by replacing the learned critic with a group-sampling baseline; see the GRPO page.

4. Summary

PG theorem

\(\mathbb{E}[\sum_t R(\tau)\,\nabla\log\pi_\theta(a_t\mid s_t)]\)

Reward-to-go

Replace \(R(\tau)\) with \(G_t\); past rewards have zero gradient in expectation

Advantage

\(A_t = G_t - V(s_t)\); isolates action quality from state quality

GAE

\(\hat A_t = \sum_l(\gamma\lambda)^l\delta_{t+l}\); computed backward in \(O(T)\)

Policy update

\(\mathbb{E}[\sum_t\hat A_t\,\nabla\log\pi_\theta(a_t\mid s_t)]\)

Critic loss

\(\mathbb{E}_t[(V_\psi(s_t) - \hat R_t)^2]\) where \(\hat R_t = \hat A_t + V_\psi(s_t)\)
