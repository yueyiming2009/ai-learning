RL Foundations

TD Learning

Don't wait for the episode to end. Update the value estimate after every single step, using the Bellman equation as a learning target. Trade a small bias for a large reduction in variance.

🎓
David Silver's Reinforcement Learning Course (DeepMind/UCL)

Covers TD prediction and Q-learning from Lectures 4–5 (model-free prediction and model-free control).

Monte Carlo waits until the episode ends to compute a return and then uses it to update the value estimate. This is unbiased but slow and noisy. Temporal Difference (TD) learning — introduced by Sutton (1988) — makes the update after every single step, using the Bellman equation itself as the learning signal. It is the basis of Q-learning, actor-critic methods, DQN, and the GAE used in PPO.

1. The Core Idea: Learn from Incomplete Episodes

The Bellman equation says that if \(V^\pi\) were perfectly correct, it would satisfy:

\[ V^\pi(s_t) = r_t + \gamma\, V^\pi(s_{t+1}) \]

at every step. TD learning turns this into a learning rule: if the two sides don't match, nudge \(V(s_t)\) toward the right-hand side. The right-hand side — one real reward plus a bootstrapped future value — is the TD target.

The crucial difference from Monte Carlo:

  • MC target: \(G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots\) — wait for the whole episode, use real rewards all the way to the end.
  • TD target: \(r_t + \gamma V(s_{t+1})\) — take one real reward, then substitute the current value estimate for everything after. No need to wait.

2. The TD Error \(\delta_t\)

The gap between the current value estimate and the TD target is the TD error:

TD error
\[ \delta_t = r_t + \gamma\, V(s_{t+1}) - V(s_t) \]

\(\delta_t\) is the "surprise" at step \(t\): how much better or worse things went than the current estimate predicted. Three cases:

  • \(\delta_t > 0\) — reality was better than expected; \(V(s_t)\) was too pessimistic.
  • \(\delta_t = 0\) — the estimate was exactly right; no update needed.
  • \(\delta_t < 0\) — reality was worse than expected; \(V(s_t)\) was too optimistic.
Connection to neuroscience

The TD error closely mirrors the dopamine signal in the brain — a burst of dopamine when outcomes are better than predicted, a dip when they're worse, and silence when they match expectations. Schultz et al. (1997) showed this empirically, providing one of the most striking connections between computational RL and biology.

3. TD(0) — One-Step Bootstrapping

TD(0) is the simplest TD method: after every step, update the value of the current state by a fraction of the TD error.

TD(0) update rule
\[ V(s_t) \;\leftarrow\; V(s_t) + \alpha\, \delta_t \;=\; V(s_t) + \alpha\!\left[\, r_t + \gamma\, V(s_{t+1}) - V(s_t) \,\right] \]
Algorithm — TD(0) for policy evaluation
Require: policy π, learning rate α, discount factor γ
Initialize: V(s) ← 0 for all s ∈ S

repeat
    s ← s₀
    while s is not terminal do
        a     ← π(s)
        r, s' ← env.step(s, a)
        δ     ← r + γ · V(s') − V(s)   ▷ TD error
        V(s)  ← V(s) + α · δ
        s     ← s'
    end while
until V converges

Two things to notice: TD(0) updates online — after every step, not after every episode. And it only ever looks one step into the future, regardless of episode length. Both properties follow from using the TD target instead of the full return.

4. The Bias–Variance Trade-off

MC and TD(0) sit at opposite ends of a spectrum. Understanding the trade-off is the key to understanding every RL method that comes after.

Why TD(0) has lower variance

The TD target \(r_t + \gamma V(s_{t+1})\) depends on only one random reward \(r_t\). The MC return \(G_t\) depends on a sum of \(T-t\) random rewards. Variance accumulates with each additional term, so the TD target is far less noisy — especially for long episodes.

Why TD(0) is biased

The TD target uses \(V(s_{t+1})\) — the current estimate of the value of the next state. That estimate is almost certainly wrong, especially early in training. The error in \(V(s_{t+1})\) propagates into the TD target, which then corrupts the update to \(V(s_t)\). This is bootstrapping bias: using a biased estimate as part of your learning target introduces bias into your new estimate.

Why bootstrapping bias decreases over time

As training continues, \(V\) improves. A better \(V(s_{t+1})\) means a more accurate TD target, which means less biased updates to \(V(s_t)\). The bias is not fixed — it shrinks as the value estimate converges. In the limit (tabular case, appropriate step sizes), TD(0) converges to the true \(V^\pi\). The bias is temporary; the variance reduction is permanent.

5. n-Step TD — Bridging the Gap

Instead of bootstrapping after one step (TD) or never (MC), take \(n\) real rewards then bootstrap. As \(n\) grows, bias decreases and variance increases, smoothly interpolating between the two extremes.

n-step return
\[ G_t^{(n)} = \underbrace{r_t + \gamma r_{t+1} + \cdots + \gamma^{n-1} r_{t+n-1}}_{\text{real rewards}} + \underbrace{\gamma^n V(s_{t+n})}_{\text{bootstrap}} \]

The corresponding update is \(V(s_t) \leftarrow V(s_t) + \alpha\left[G_t^{(n)} - V(s_t)\right]\). The n-step return has a clean equivalence in terms of TD errors — the intermediate value terms telescope:

\[ G_t^{(n)} - V(s_t) = \sum_{l=0}^{n-1} \gamma^l\, \delta_{t+l} \]

The n-step advantage is just a discounted sum of one-step TD errors. This is not a coincidence — it falls directly out of the Bellman recursion and is the algebraic key that makes GAE possible.

6. TD(λ) and GAE

Rather than commit to one value of \(n\), TD(λ) takes a weighted average of all \(n\)-step returns simultaneously. The mixing parameter \(\lambda \in [0,1]\) controls how much weight each horizon receives:

λ-return (TD(λ) target)
\[ G_t^\lambda = (1 - \lambda) \sum_{n=1}^{\infty} \lambda^{n-1}\, G_t^{(n)} \]

The factor \((1-\lambda)\lambda^{n-1}\) is a geometric distribution over \(n\): each extra step gets \(\lambda\) times the weight of the previous one, and the \((1-\lambda)\) normalises the total to 1. Example with \(\lambda = 0.9\):

Horizon \(n\)Weight \((1-\lambda)\lambda^{n-1}\)What the return is
10.1001 real reward, then bootstrap — TD(0)
20.0902 real rewards, then bootstrap
30.0813 real rewards, then bootstrap
100.03910 real rewards, then bootstrap
∞→ 0Full MC return — no bootstrap at all

At the extremes: \(\lambda = 0\) puts all weight on the 1-step return (pure TD(0)); \(\lambda = 1\) gives equal weight to all horizons, which telescopes to the full MC return \(G_t\).

Deriving GAE from the λ-return

We want the advantage form \(\hat A_t = G_t^\lambda - V(s_t)\). The first ingredient: from §5, the n-step advantage is a finite sum of TD errors (the intermediate \(V\) terms telescope away):

\[ G_t^{(n)} - V(s_t) = \delta_t + \gamma\delta_{t+1} + \gamma^2\delta_{t+2} + \cdots + \gamma^{n-1}\delta_{t+n-1} \]

Now substitute this into the λ-return and write out the first few terms, one row per value of \(n\):

\[ \begin{aligned} \hat A_t &= (1{-}\lambda) &&\cdot\; \delta_t &\quad[n=1]\\ &+\ (1{-}\lambda)\lambda &&\cdot\; [\delta_t + \gamma\delta_{t+1}] &\quad[n=2]\\ &+\ (1{-}\lambda)\lambda^2 &&\cdot\; [\delta_t + \gamma\delta_{t+1} + \gamma^2\delta_{t+2}] &\quad[n=3]\\ &+\ (1{-}\lambda)\lambda^3 &&\cdot\; [\delta_t + \gamma\delta_{t+1} + \gamma^2\delta_{t+2} + \gamma^3\delta_{t+3}] &\quad[n=4]\\ &+\ \cdots \end{aligned} \]

Now read down each column and collect the total coefficient for each TD error:

  • \(\delta_t\) appears in every row (all \(n \geq 1\)) with no extra discount. Its coefficient is: \[(1-\lambda)\bigl[1 + \lambda + \lambda^2 + \cdots\bigr] = (1-\lambda)\cdot\frac{1}{1-\lambda} = 1\]
  • \(\gamma\delta_{t+1}\) first appears at \(n=2\) and is present in all rows below. Its coefficient is: \[(1-\lambda)\bigl[\lambda + \lambda^2 + \lambda^3 + \cdots\bigr] = (1-\lambda)\cdot\frac{\lambda}{1-\lambda} = \lambda\] So the total weight on \(\delta_{t+1}\) is \(\gamma \cdot \lambda = \gamma\lambda\).
  • \(\gamma^2\delta_{t+2}\) first appears at \(n=3\). Its coefficient is: \[(1-\lambda)\bigl[\lambda^2 + \lambda^3 + \cdots\bigr] = (1-\lambda)\cdot\frac{\lambda^2}{1-\lambda} = \lambda^2\] So the total weight on \(\delta_{t+2}\) is \(\gamma^2 \cdot \lambda^2 = (\gamma\lambda)^2\).
  • In general, \(\gamma^l\delta_{t+l}\) first appears at row \(n = l+1\). The geometric series starting at \(\lambda^l\) gives coefficient \(\lambda^l\), so the total weight on \(\delta_{t+l}\) is \(\gamma^l \cdot \lambda^l = (\gamma\lambda)^l\).

Putting it all together:

Generalised Advantage Estimation (GAE)
\[ \hat A_t = G_t^\lambda - V(s_t) = \sum_{l=0}^{\infty} (\gamma\lambda)^l\, \delta_{t+l} \]

Every future TD error \(\delta_{t+l}\) contributes, but its influence decays geometrically. A surprise two steps away matters \(\gamma\lambda\) times less than a surprise one step away. \(\lambda\) is the decay knob: small \(\lambda\) means only nearby surprises matter; \(\lambda \to 1\) means all surprises matter equally.

The backward recursion — how GAE is actually computed

The sum \(\sum_{l\geq 0}(\gamma\lambda)^l\delta_{t+l}\) looks forward in time, but in practice you first collect a full rollout and then compute advantages in a single backward pass:

GAE backward recursion
\[ \hat A_T = 0, \qquad \hat A_t = \delta_t + \gamma\lambda\,\hat A_{t+1} \]
Why the recursion equals the forward sum

Unroll from \(t\):

\[ \hat A_t = \delta_t + \gamma\lambda\bigl(\delta_{t+1} + \gamma\lambda\bigl(\delta_{t+2} + \cdots\bigr)\bigr) = \sum_{l=0}^\infty (\gamma\lambda)^l \delta_{t+l} \]

Identical. The recursion is the forward sum written inside-out — and it computes every \(\hat A_t\) in \(O(T)\) with a single backward loop.

GAE backward pass — used in every PPO implementation
Given: stored rollout δ[0..T−1], discount γ, trace parameter λ

A[T] ← 0
for t in reversed(range(T)):
    A[t] ← δ[t] + γ · λ · A[t+1]   ▷ one multiply-add per step

▷ A[t] = Σ_l (γλ)^l δ[t+l] — the full GAE advantage at every position

7. Eligibility Traces — The Backward View

The GAE backward recursion works because you stored the whole rollout first. Eligibility traces achieve the same credit assignment online — updating value estimates after every single step without ever storing the episode. The key idea is to flip the temporal perspective: instead of asking "at time \(t\), how much weight do I put on a future TD error?", ask "when a surprise \(\delta_k\) arrives, how much credit do I give to states I visited in the past?"

The answer to both questions is the same geometric decay \((\gamma\lambda)^l\), where \(l\) is the distance in time. The eligibility trace is the data structure that tracks this decaying credit for every state simultaneously, so that when a TD error arrives the right states get updated immediately.

Step 1 — The tabular case: a decaying visit counter

Start with the simplest setting: a lookup table where each state \(s\) has its own stored value \(V(s)\). The trace for state \(s\) is a scalar that rises by 1 each time \(s\) is visited and decays by \(\gamma\lambda\) on every other step:

Tabular eligibility trace
\[ e_0(s) = 0 \quad \text{for all } s, \qquad e_t(s) = \begin{cases} \gamma\lambda\, e_{t-1}(s) + 1 & \text{if } s_t = s \\ \gamma\lambda\, e_{t-1}(s) & \text{otherwise} \end{cases} \]

Think of \(e_t(s)\) as a fading receipt: it records how recently (and how often) state \(s\) was responsible for a prediction. A state visited 5 steps ago has trace \((\gamma\lambda)^5\); one visited just now has trace 1.

When a TD error \(\delta_t\) occurs at step \(t\), every state gets a value update proportional to its current eligibility:

\[ V(s) \;\leftarrow\; V(s) + \alpha\,\delta_t\, e_t(s) \quad \text{for every state } s \]

States with high eligibility (visited recently) absorb most of the correction. States visited long ago barely change. This is credit assignment happening backward through time, online.

Tabular TD(λ) — eligibility trace version
Initialize: V(s) ← 0 for all s;  e(s) ← 0 for all s

for each episode:
    s ← s₀;  e(s) ← 0 for all s          ▷ reset traces
    while s is not terminal:
        a       ← π(s)
        r, s'   ← env.step(s, a)
        δ       ← r + γ · V(s') − V(s)    ▷ TD error
        e(s)    ← e(s) + 1                 ▷ increment trace for current state
        for all states u:
            V(u) ← V(u) + α · δ · e(u)   ▷ update every state by its eligibility
            e(u) ← γλ · e(u)             ▷ decay every trace
        s ← s'

Step 2 — Why "1" becomes a gradient with function approximation

In the tabular case the update \(V(s) \leftarrow V(s) + \alpha\delta_t e_t(s)\) works because each state owns its own number \(V(s)\) that can be changed independently. The trace just needs to answer: how recently was \(s\) visited? A plain "+1" on each visit is enough.

With a neural network, \(V(s;\mathbf{w})\) is computed from shared weights \(\mathbf{w}\). You cannot update \(V(s)\) directly — you can only move \(\mathbf{w}\), and any change to \(\mathbf{w}\) ripples through all states. The trace needs to answer a harder question: which weights were responsible for the prediction at \(s_t\)?

The answer is the gradient \(\nabla_\mathbf{w} V(s_t;\mathbf{w})\). Each component \(\partial V(s_t)/\partial w_i\) says how much weight \(w_i\) contributed to the prediction at \(s_t\): a large positive value means \(w_i\) had a big influence; zero means it had none. The gradient is the function-approximation analog of the tabular "+1" — it replaces a scalar visit indicator with a vector that identifies which parameters did the visiting.

The analogy made precise
TabularFunction approximation
What can we update? \(V(s)\) — one number per state \(\mathbf{w}\) — shared weights used by all states
What does "visit" mean? \(s_t = s\) → add 1 to \(e(s)\) \(s_t\) activates weights → add \(\nabla_\mathbf{w} V(s_t)\) to \(\mathbf{e}\)
What does the trace track? How recently was state \(s\) visited? How recently did each weight contribute to a prediction?

Step 3 — The general eligibility trace

Replacing the scalar "+1" with the gradient vector gives the general form that works for both tabular (where \(\nabla_\mathbf{w} V(s_t) = \mathbf{e}_{s_t}\), a one-hot indicator) and neural networks:

Eligibility trace (function approximation)
\[ \mathbf{e}_0 = \mathbf{0}, \qquad \mathbf{e}_t = \gamma\lambda\,\mathbf{e}_{t-1} + \nabla_\mathbf{w} V(s_t;\mathbf{w}) \]

\(\mathbf{e}_t\) has the same shape as \(\mathbf{w}\). At each step it decays (older predictions matter less) and gains a new contribution from the current state's gradient (the weights currently responsible for the prediction). When the TD error arrives, every weight moves proportionally to how much it recently contributed:

\[ \mathbf{w} \;\leftarrow\; \mathbf{w} + \alpha\,\delta_t\,\mathbf{e}_t \]
TD(λ) with eligibility traces — function approximation
Initialize: w ← random;  e ← 0 (same shape as w)

for each episode:
    s ← s₀;  e ← 0                              ▷ reset trace each episode
    while s is not terminal:
        a       ← π(s)
        r, s'   ← env.step(s, a)
        δ       ← r + γ · V(s'; w) − V(s; w)    ▷ TD error
        e       ← γλ · e + ∇w V(s; w)         ▷ decay old, add current gradient
        w       ← w + α · δ · e                  ▷ every weight moves by its eligibility
        s       ← s'

Why traces equal the forward view

Consider the total change applied to \(\mathbf{w}\) that can be traced back to state \(s_t\). After step \(t\), the gradient \(\nabla_\mathbf{w} V(s_t)\) sits in the trace with coefficient 1. One step later it has decayed to \(\gamma\lambda\); two steps later to \((\gamma\lambda)^2\); and so on. So every subsequent TD error \(\delta_k\) (\(k \geq t\)) multiplies the gradient by \((\gamma\lambda)^{k-t}\) before applying it to \(\mathbf{w}\). The total update from state \(s_t\) across the whole episode is:

\[ \Delta\mathbf{w}\big|_{s_t} = \alpha \sum_{k \geq t} (\gamma\lambda)^{k-t}\delta_k \cdot \nabla_\mathbf{w} V(s_t) = \alpha\,\hat A_t \cdot \nabla_\mathbf{w} V(s_t) \]

This is the same update the forward view produces: scale the gradient of the value function at \(s_t\) by the GAE advantage \(\hat A_t\). The trace computed it online without ever looking forward.

Modern deep RL for LLMs doesn't use online eligibility traces — maintaining and updating a trace vector over millions of parameters every token step is too expensive. Instead a full rollout is collected and the GAE backward recursion runs as a single \(O(T)\) batch pass. The two approaches are mathematically equivalent; the backward recursion is simply the batch-mode version of the same credit assignment.

Accumulating vs. replacing traces

When a state is revisited within an episode, two conventions exist for the "+1" (tabular) or "+gradient" (parametric) increment:

  • Accumulating: always add. Credit builds up on each revisit. Standard TD(λ) and the GAE backward recursion use this implicitly.
  • Replacing: cap the trace at 1 on revisit (tabular) or reset to the gradient (parametric). Prevents a state in a loop from dominating all updates.
  • Dutch: \(\mathbf{e}_t = (1-\alpha)\gamma\lambda\,\mathbf{e}_{t-1} + \nabla V(s_t)\). Reduces double-counting that arises with function approximation when the same weight is adjusted twice for the same prediction.

8. Q-Learning — Off-Policy TD for Q*

TD(0) evaluates a fixed policy \(\pi\) — it estimates \(V^\pi\). Q-learning (Watkins, 1989) uses TD to directly learn the optimal Q-function \(Q^*\), without needing to know or follow the optimal policy during data collection.

The key change: replace the one-step bootstrap with a greedy maximum over next actions.

Q-learning update
\[ Q(s_t, a_t) \;\leftarrow\; Q(s_t, a_t) + \alpha \underbrace{\!\left[\, r_t + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t) \,\right]}_{\delta_t^Q \;\text{(Q-learning TD error)}} \]
Algorithm — Q-learning (Watkins, 1989)
Require: learning rate α, discount factor γ, exploration rate ε
Initialize: Q(s, a) ← 0 for all s ∈ S, a ∈ A

repeat
    s ← s₀
    while s is not terminal do
        a     ← ε-greedy(Q(s, ·))                       ▷ explore or exploit
        r, s' ← env.step(s, a)
        δ     ← r + γ · maxa' Q(s', a') − Q(s, a)   ▷ Bellman target
        Q(s, a) ← Q(s, a) + α · δ
        s ← s'
    end while
until Q converges to Q*

Why Q-learning is off-policy

Q-learning separates two policies:

  • Behavior policy \(\pi_b\): what the agent actually does to collect data. Typically ε-greedy — mostly greedy but sometimes random, to ensure exploration.
  • Target policy \(\pi_t\): what Q-learning is implicitly optimizing toward. Always greedy: \(\arg\max_a Q(s,a)\).

The update uses \(\max_{a'} Q(s', a')\) — the greedy action at the next state — regardless of what action the behavior policy actually took. This means the data collected under \(\pi_b\) can be used to improve a different policy \(\pi_t\). That is the defining property of an off-policy method.

Q-learning converges to \(Q^*\) in the tabular case (Watkins & Dayan, 1992) under standard step-size conditions. With function approximation (neural networks), convergence is not guaranteed — the combination of off-policy data, bootstrapping, and function approximation is the "deadly triad" (Sutton & Barto) that can cause divergence. Deep Q-Networks (DQN) work around this with experience replay and a frozen target network.

SARSA — the on-policy alternative

SARSA is the on-policy sibling of Q-learning. Instead of taking the max over next actions, it uses the action the policy actually takes:

\[ Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha\left[r_t + \gamma\, Q(s_{t+1}, a_{t+1}) - Q(s_t, a_t)\right] \]

The name comes from the tuple \((s_t, a_t, r_t, s_{t+1}, a_{t+1})\) it uses. Because it evaluates the policy that's actually being followed, SARSA is safer in environments where exploration mistakes are costly — the policy it learns accounts for the fact that it sometimes takes random actions.

When does TD actually converge?

Tabular TD converges; the picture gets subtle once you add function approximation and off-policy data. David Silver's Lecture 6 tabulates the full story for prediction (evaluating a fixed policy):

9. TD Learning in LLM RL

LLM RL doesn't use tabular TD — the state space is too large. But the TD error \(\delta_t\) and the TD(λ)/GAE framework are central to PPO.

TD conceptIn PPO for LLMs
Value function \(V(s_t)\) Learned critic \(V_\psi(s_t)\): a neural network (often a separate head on the policy model) that predicts expected return from the current token context
TD error \(\delta_t\) \(\delta_t = R_t + \gamma V_\psi(s_{t+1}) - V_\psi(s_t)\), where \(R_t\) is the per-token reward (terminal RM score + KL penalty)
TD(λ) / GAE \(\hat A_t = \sum_{l \ge 0}(\gamma\lambda)^l \delta_{t+l}\) — computed in a single backward pass after each rollout. This is the advantage used in the PPO policy gradient.
Critic training \(\mathcal{L}_\text{VF}(\psi) = \mathbb{E}_t[(V_\psi(s_t) - \hat R_t)^2]\) where \(\hat R_t = \hat A_t + V_\psi(s_t)\) is the TD(λ) return. The critic is regressing toward its own bootstrapped target.
Why GRPO avoids TD entirely

Training the critic \(V_\psi\) is expensive and unstable — it requires a second forward pass on all rollout tokens, regresses toward noisy targets, and can diverge. GRPO sidesteps this by using the group-average reward as a Monte Carlo estimate of \(V(s_0)\), assigning a uniform advantage across all tokens in a response. It trades the per-token credit assignment that TD enables for simplicity and stability. See the GRPO page.
