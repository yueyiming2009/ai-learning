Sequence Parallelism — Megatron-SP, Ring Attention, and Ulysses

When sequence length fills GPU memory before model parameters do, shard the token axis. Three approaches with different communication primitives, memory profiles, and scaling limits — derived from the same sharding cost model.

Prerequisites: Tensor Parallelism → (column/row-parallel layers, the AllReduce that Megatron-SP replaces) and Sharding & Collectives → (AlltoAll for Ulysses; ring P2P for ring attention).

1 · Why sequence length is a memory problem

The three parallelism axes covered so far — TP, DP, PP — each attack a different memory bottleneck: parameter memory (TP, PP) or batch size (DP). None of them shard the sequence axis. At long context, the sequence axis is where the memory goes.

Where activation memory lives in a transformer layer

For a standard transformer layer with \(B\) sequences of length \(T\), hidden dimension \(D\), and \(N\) attention heads of dimension \(H\) (so \(NH = D\)), the dominant activation tensors stored for the backward pass are:

TensorShapebf16 bytesScales with
Input to each sub-layer\([B, T, D]\)\(2BTD\)T
QKV projections\(3 \times [B, T, D]\)\(6BTD\)T
Attention scores (per head)\([B, N, T, T]\)\(2BNT^2\)T²
Attention output\([B, T, D]\)\(2BTD\)T
FFN intermediate\([B, T, 4D]\)\(8BTD\)T

The attention score term \(2BNT^2\) is the canonical quadratic memory cost — FlashAttention eliminates it by recomputing scores in tiles. But even without it, the linear terms sum to roughly \(20BTD\) bytes per layer. At \(T = 128{,}000,\ B = 1,\ D = 8192\): one layer costs about 21 GB of activation memory — more than a full A100 80 GB for just two layers, before weights and optimizer state.

The long-context problem
Even with FlashAttention removing the \(T^2\) term, activation memory grows as \(O(BTD)\) per layer — linear in sequence length. At 128k tokens it dominates everything else.

TP shards the weights but replicates the sequence: every TP rank holds all \(T\) tokens of the activation. The activation memory per TP rank is unchanged. Sequence parallelism shards the token axis too, so each SP rank holds only \(T / \text{SP}\) tokens.

2 · Megatron-SP — free activation savings on the TP axis

Megatron-LM's sequence parallelism is the simplest of the three: it reuses the existing TP process group and replaces the TP AllReduce with a ReduceScatter+AllGather pair. The communication volume is identical; the benefit is that between the two collectives, each rank holds only \(T/|X|\) tokens.

How the standard TP block works

Recall from Tensor Parallelism: each MLP or attention block ends with a row-parallel projection that produces an unreduced output, followed by an AllReduce. The output \(Y[B, T, D]\) is replicated on all TP ranks before entering the next layer's layer norm.

The Megatron-SP modification

Instead of the AllReduce (which produces a full replicated tensor), use a ReduceScatter: it sums the partial outputs and shards the result along the sequence axis at the same time. Each rank now holds \(Y[B, T/|X|, D]\). The layer norm and dropout that follow operate locally on this \(T/|X|\)-token slice. Before the next attention or MLP block, an AllGather restores the full \(T\)-length sequence.

Modified block boundary

Row-parallel projection → ReduceScatter (produces \(Y[B, T/|X|, D]\) on each rank)
LayerNorm, Dropout (local, on \(T/|X|\) tokens)
AllGather (restores \(Y[B, T, D]\)) → Column-parallel of next block

Standard TP vs. Megatron-SP — communication
Standard TP (AllReduce)

Volume per AllReduce: \(2BTD\) bytes.
Two AllReduces per layer (fwd) = \(4BTD\) bytes moved.
Tensor between layers: \(Y[B, T, D]\) — replicated, full sequence on every rank.

Megatron-SP (ReduceScatter + AllGather)

ReduceScatter: \(2BTD \cdot (|X|-1)/|X|\) bytes moved.
AllGather: same. Total ≈ \(4BTD\) bytes — identical total volume.
Tensor between collectives: \(Y[B, T/|X|, D]\) — \(1/|X|\) of the sequence.

Megatron-SP memory saving
No extra communication. Activation memory between blocks is reduced by \(1/|X|\) — the same factor as the weight sharding. On a TP=8 group, each GPU holds \(T/8\) tokens between layers.
Megatron-SP requires the same TP group as the model-parallel sharding — it does not add a new axis. It is effectively free: the ReduceScatter+AllGather pair has the same latency and bandwidth as the AllReduce it replaces (both are \(\Theta(2V(|X|-1)/|X|)\) on a ring), but the intermediate state is sharded.

3 · Ring Attention — context parallelism beyond one node

Megatron-SP reuses the TP group, so it is bounded by the NVLink node limit (\(|X| \le 8\)). For truly long sequences — 128k, 1M tokens — you need a separate context-parallel (CP) axis that can span across nodes. Ring Attention is the dominant approach.

The core idea

Partition the \(T\) tokens across \(CP\) ranks: rank \(r\) holds tokens \([rT/CP,\ (r+1)T/CP)\) for both queries and keys/values. Computing attention for rank \(r\)'s query chunk requires the keys and values from all \(CP\) ranks — but instead of an AllGather (which would bring all K,V to every rank), ranks pass K,V chunks around a ring while computing locally.

Ring Attention — one layer, CP ranks
  1. Each rank starts with its local Q, K, V chunk: shapes \([B, T/CP, N, H]\).
  2. In step \(s\) of \(CP\) steps: rank \(r\) computes \(\text{Attn}(Q_r, K_{(r-s)\%CP}, V_{(r-s)\%CP})\) and simultaneously sends its current K,V to rank \((r+1)\%CP\), receiving from rank \((r-1)\%CP\).
  3. After \(CP\) steps, each rank has accumulated the full attention output for its query chunk by running a numerically stable online softmax across all \(CP\) key chunks.

The ring topology means each rank sends its K,V chunk exactly \(CP - 1\) times. The total bytes sent per rank is \((CP-1) \times 2 \times (B \times T/CP \times D)\) (K and V together, in bf16). Summing over the ring:

\[ \text{Ring Attention comm per layer} = 2(CP-1) \cdot \frac{B \cdot T \cdot D}{CP} \cdot \frac{1}{\text{rank}} \approx 2BTD \text{ bytes/rank for large } CP \]

This is comparable in volume to one TP AllReduce (\(2BTD\) bytes), but the ring is pipelined: the P2P sends overlap with the local attention computation, hiding most of the latency if the attention GEMM is long enough.

Causal masking

For causal (autoregressive) attention, rank \(r\) only attends to positions \(\le r \cdot T/CP\) from ranks that precede it in sequence order. When rank \(r\) receives a K,V chunk from a rank with a higher sequence index, it applies a zero mask to those positions. This roughly halves the effective compute for the upper triangle — implementations like FlashAttention-Ring handle this by tracking which chunks are causal vs. non-causal and skipping the masked upper half.

▸ Ring Attention — CP=4, one step Each rank computes attention against one K,V chunk per step while passing its chunk to the right.
Step 0/4: each rank holds its own K,V chunk.

4 · DeepSpeed Ulysses — AlltoAll on the head axis

Ulysses takes a completely different approach: instead of routing K,V chunks around a ring, it uses two AlltoAll operations to redistribute which ranks are responsible for which heads.

Step 1 — AlltoAll before attention

Input: \(Q[B, T/SP, N, H]\) on each rank (each rank holds all heads, a T/SP slice).
AlltoAll across SP ranks: transpose the sequence and head axes across the group.
Output: \(Q[B, T, N/SP, H]\) on each rank — each rank now sees all \(T\) tokens but only \(N/SP\) heads.

Step 2 — Local attention

Each rank runs standard attention (FlashAttention compatible) on its \(N/SP\) heads over the full sequence. The computation is fully local — no further communication.

Step 3 — AlltoAll after attention

Output: \(O[B, T, N/SP, H]\) on each rank. AlltoAll reverses the redistribution.
Result: \(O[B, T/SP, N, H]\) — back to the sequence-sharded layout.

Ulysses communication per attention layer
Two AlltoAll operations. Volume per AlltoAll: \(B \times T \times D\) bytes (same as one AllReduce). Both can be pipelined with Q, K, V projections on the forward pass and fused with the output projection on the backward.

Ulysses limitation

The AlltoAll transposes \(N\) heads across \(SP\) ranks, so each rank must end up with at least one head: \(SP \le N\). For GQA (grouped-query attention) models with few KV heads, the limit is \(SP \le N_\text{KV}\). A 128-head model can support up to \(SP = 128\), but a GQA model with 8 KV heads is capped at \(SP = 8\).

Megatron-SP and ring attention / Ulysses are not mutually exclusive. Production runs often combine Megatron-SP (on the TP axis, within one node) with ring attention or Ulysses (on a separate CP axis, across nodes) — getting \(1/|X|\) savings from the former and the cross-node sharding from the latter.

6 · Composing with TP, PP, and DP

All three sequence-parallel approaches live on a separate mesh axis from TP, PP, and DP. The typical nesting order from innermost (fastest fabric) to outermost (slowest, most overlappable):

Axis nesting (innermost → outermost)
TP (NVLink, AllReduce on critical path) → SP/CP (NVLink or IB, overlappable P2P or AlltoAll) → PP (IB, P2P at stage boundaries) → DP (IB, one AllReduce per step, overlappable)

In practice:

  • Megatron-SP reuses the TP process group — no new group needed. It's zero overhead and always worth enabling alongside TP.
  • Ring attention / Ulysses use a separate CP group, typically sized to fit within one node (using NVLink) before going cross-node. A CP=4 within a node plus CP=2 across nodes is a common two-tier setup.
  • DP is orthogonal: each DP replica independently runs its own TP+SP+PP configuration. Gradient sync happens across DP replicas after the full forward+backward of a micro-batch.
from torch.distributed.device_mesh import init_device_mesh

# 64 GPUs: 2-way DP × 2-way CP × 8-way TP
mesh = init_device_mesh("cuda", (2, 2, 8), mesh_dim_names=("dp", "cp", "tp"))

dp_group = mesh["dp"].get_group()    # gradient sync (ReduceScatter / AllGather)
cp_group = mesh["cp"].get_group()    # ring attention or Ulysses AlltoAll
tp_group = mesh["tp"].get_group()    # Megatron TP AllReduce (+ Megatron-SP ReduceScatter/AllGather)

7 · Summary

The problem

Activation memory grows as \(O(BTD)\) per layer. At T=128k it dominates weights and optimizer state. TP/PP/DP don't shard the token axis.

Megatron-SP

Replaces TP AllReduce with ReduceScatter+AllGather. Same comm volume, \(1/|X|\) activation memory between blocks. Zero extra overhead — always enable.

Ring Attention

K,V chunks rotate around a CP ring while queries compute locally. Pipelined with attention compute. Unlimited CP degree; needs ring-aware FlashAttention and causal-mask handling.

Ulysses

Two AlltoAll ops transpose heads and sequence axes. Standard FlashAttention runs per-rank on all T tokens. Hard cap at SP ≤ N (or KV head count for GQA).

When to use each

Megatron-SP: always. Ulysses: T ≤ 64k, high head count. Ring: T > 128k, cross-node. Combine: Megatron-SP on TP axis + ring or Ulysses on CP axis.

Composing

SP is orthogonal to DP. Megatron-SP reuses TP group. CP group is separate. Axis nesting: TP inner → CP → PP → DP outer.
