Tensor Parallelism — The Collective Math

Megatron-style tensor parallelism, derived from the sharding cost model: split each weight matrix across devices so that a transformer block costs exactly one AllReduce on the forward pass and one on the backward — and see precisely why that pins tensor parallelism to a single high-bandwidth node.

This page applies the machinery from Sharding & Collectives →. If the notation A[I, JX], the marker {UX}, or the three matmul cases aren’t familiar, read that first — everything below is an application of it.

Data parallelism replicates the model and splits the batch; it breaks the moment one copy of the model no longer fits on one device. Tensor parallelism attacks that directly: it splits the operators themselves — the weight matrices and the matmuls that use them — across a group of devices, so that no single device ever holds a whole layer. The whole design is an exercise in choosing shardings that keep the big matmuls in Case 1 (free) and pay for the unavoidable reduction exactly once.

1 · The problem: split the operator, not the data

A single transformer layer is dominated by four big matmuls — the two MLP projections and the QKV/output projections of attention. Each multiplies an activation against a weight matrix of size \(O(D^2)\) to \(O(DF)\). For a large model those weights, and the activations flowing through them, exceed one device’s HBM.

Tensor parallelism puts \(|X|\) devices in a group (the tensor-parallel group, mesh axis \(X\)) and gives each one a slice of every weight matrix. They compute their slices in parallel and exchange the minimum data needed to reconstruct the correct output. The question the collectives cost model answers is: which slicing makes that exchange cheapest?

2 · Two ways to split one linear layer

A linear layer \(Y = X\,W\) contracts the hidden axis \(D\): \(X[B, D]\cdot W[D, M] \to Y[B, M]\). There are exactly two interesting ways to shard \(W\) across the TP axis, and they differ in which axis of \(W\) you cut.

Column-parallel vs row-parallel
Column-parallel — split the output axis \(M\)

X[B, D] · W[D, MX] → Y[B, MX]

Contraction \(D\) is not sharded → Case 1, no communication. The output comes out split along \(M\); each device holds whole columns of \(Y\).

Row-parallel — split the input/contraction axis \(D\)

X[B, DX] · W[DX, M] → Y[B, M] {UX}

Both operands are split on the contraction \(D\) → Case 3. The output is born unreduced and needs an AllReduce (or ReduceScatter) to finish.

Column-parallel is free but leaves its output sharded; row-parallel costs a reduction but consumes a sharded input. The Megatron insight is to chain them: a column-parallel layer feeds its sharded output straight into a row-parallel layer, so the split in the middle is never re-gathered — and the entire pair of matmuls costs a single reduction at the very end.

3 · The MLP block — one AllReduce

The transformer MLP is \( Y = \big(\sigma(X W_\text{in})\big)\,W_\text{out}\), with \(W_\text{in}[D, F]\) expanding to the intermediate width \(F\) and \(W_\text{out}[F, D]\) projecting back. Shard \(W_\text{in}\) column-parallel and \(W_\text{out}\) row-parallel, both on the \(F\) axis.

Step 1 — up-projection (column-parallel, free)

X[B, D] · Win[D, FX] → Z[B, FX]
Contraction \(D\) is replicated → Case 1. Each device produces the columns of \(Z\) belonging to its slice of the \(F\) neurons. No communication.

Step 2 — nonlinearity (elementwise, free)

σ(Z[B, FX]) → A[B, FX]
GeLU/SwiGLU act per element. An elementwise op on a sharded array needs no communication — and crucially, because each neuron’s activation depends only on its own pre-activation, splitting \(F\) does not change the result. This is why we split the intermediate axis: the nonlinearity sits entirely inside the shard.

Step 3 — down-projection (row-parallel, Case 3)

A[B, FX] · Wout[FX, D] → Y[B, D] {UX}
Now the contraction \(F\) is sharded, and so is \(A\). Local products are partial sums → the output is unreduced.

Step 4 — finish the sum (AllReduce)

AllReduceX: Y[B, D] {UX} → Y[B, D]
One AllReduce produces the correct, replicated block output, ready for the residual add and the next layer.

Megatron MLP — forward
Two big matmuls, one nonlinearity, exactly one AllReduce — the intermediate split on \(F\) is never gathered. 
import torch, torch.distributed as dist

def col_parallel_linear(x, W_col):
    # x: [B, D] replicated; W_col: [D, F/tp] local shard
    # Contraction axis D is not sharded → Case 1, no communication
    return x @ W_col                           # [B, F/tp], sharded

def row_parallel_linear(z, W_row, tp_group):
    # z: [B, F/tp] sharded; W_row: [F/tp, D] local shard
    # Contraction axis F is sharded → Case 3, local result is a partial sum
    y = z @ W_row                              # [B, D], {U_X} unreduced
    dist.all_reduce(y, group=tp_group)         # sum across TP group
    return y                                   # [B, D], replicated

def tp_mlp(x, W_in, W_out, tp_group):
    z = col_parallel_linear(x, W_in)          # free: no comm
    a = torch.nn.functional.gelu(z)           # free: elementwise, stays sharded
    return row_parallel_linear(a, W_out, tp_group)  # 1 AllReduce total

What the backward pass costs

By the forward/backward duality, we don’t re-derive the comm — we read it off. The forward AllReduce sits where activations are reduced; its adjoint is again an AllReduce, now of the input gradient \(\partial \mathcal{L}/\partial X\) as it flows back through the column-parallel layer:

Megatron MLP — the conjugate operators
forward: identity \(\to\) (matmuls) \(\to\) AllReduce
backward: AllReduce \(\to\) (matmuls) \(\to\) identity

These are the famous \(f\) and \(g\) operators of the Megatron-LM paper: \(g\) is an AllReduce in the forward pass and identity in the backward; \(f\) is identity forward and AllReduce backward. Net for the MLP block: 1 AllReduce forward + 1 AllReduce backward.

4 · Attention — split across heads

Multi-head attention parallelizes even more naturally, because the heads are already independent: head \(h\) only ever mixes its own \(Q_h, K_h, V_h\). So we shard the heads across \(X\) — each device owns a subset of heads end to end — and the per-head softmax-attention stays entirely local.

Step 1 — QKV projection (column-parallel over heads)

X[B, T, D] · WQ[D, NX, H] → Q[B, T, NX, H]  (and likewise \(K, V\))
Splitting the head axis \(N\) is a column split of the output → Case 1, free. Each device materializes the \(Q,K,V\) of its own heads only.

Step 2 — attention per head (local)

softmax(Q K⊤ / √H) V → O[B, T, NX, H]
Each head’s scores, softmax, and value-mix touch only data that device holds. No communication — this is the whole reason head-splitting is the right cut for attention.

Step 3 — output projection (row-parallel, Case 3)

O[B, T, NX, H] · WO[NX, H, D] → Y[B, T, D] {UX}
\(W_O\) contracts over the (now sharded) head axis, so its rows are split to match \(O\). Local products are partial sums → unreduced.

Step 4 — AllReduce

AllReduceX: Y[B, T, D] {UX} → Y[B, T, D]

Attention block
Same shape as the MLP: column-parallel in, row-parallel out, one AllReduce forward + one backward. The head count \(N\) must be divisible by \(|X|\).

5 · The per-layer communication bill

Each transformer layer is one attention block plus one MLP block, so per layer:

Communication per transformer layer
2 AllReduce forward + 2 AllReduce backward.

Each AllReduce moves the block activation \(Y[B, T, D]\). In bf16 that is \(V = 2BTD\) bytes, and from the cost model an AllReduce costs \(\approx 2V/W\). So the forward comm time of a layer is

\[ T^\text{layer}_\text{comm,\,fwd} \;\approx\; 2 \times \frac{2\,(2BTD)}{W}\cdot\frac{|X|-1}{|X|} \;\xrightarrow[|X|\ \text{large}]{}\; \frac{8\,BTD}{W}. \]

Two things to read off this:

  • Comm scales with activations \(BTD\), not with parameters. Bigger weight matrices (\(F\), \(D^2\)) cost more compute but the AllReduce payload only grows with the activation size. That is what makes TP viable at all.
  • It is on the critical path. Unlike data-parallel gradient AllReduce (which overlaps with the backward compute), these reductions sit between the two matmuls of a block — the next op cannot start until the sum lands. They are exposed latency, not hidden.

6 · Why tensor parallelism stops at one node

Put the compute and the comm side by side. A block does \(O(BTD\cdot F)\) FLOPs of matmul but only moves \(O(BTD)\) bytes per AllReduce — a compute-to-comm ratio of \(O(F)\). The reduction is small relative to the math, so as long as the link bandwidth \(W\) is high, the exposed AllReduce hides under the matmul.

But \(W\) falls off a cliff at the node boundary. Inside a server, GPUs share NVLink/NVSwitch at hundreds of GB/s to ~TB/s. Across servers, you drop to InfiniBand/Ethernet an order of magnitude slower. Because the TP AllReduce is on the critical path and runs twice per block, crossing that boundary turns a hidden cost into a dominant one.

The rule of thumb
Keep the tensor-parallel degree \(\le\) the number of GPUs on one NVLink island — typically \(|X| = 8\). Scale further with other axes (data, pipeline, expert parallelism) that tolerate the slower inter-node fabric.

This is the “TP↔PP transition point”: tensor parallelism buys you per-device memory relief up to one node, and beyond that you switch to pipeline or data parallelism, whose communication is either rarer (point-to-point activations between stages) or overlappable (gradient AllReduce). The whole 3-D parallelism layout is organized around keeping each collective on a fabric fast enough to hide it.

7 · The embedding and the parallel cross-entropy

The token embedding / unembedding matrix \(E[V, D]\) is huge — vocabularies run to \(10^5\) and beyond — so it is sharded along the vocabulary axis: E[VX, D]. Each device owns the rows (and output logits) of a slice of the vocabulary. The logit projection is therefore column-parallel:

h[B, T, D] · E⊤[D, VX] → logits[B, T, VX]

A naive cross-entropy would AllGather the full \(V\)-wide logits to every device — a payload of size \(BTV\), far larger than the \(BTD\) activations. The vocab-parallel cross-entropy avoids it by pushing the two reductions of the softmax through the shard:

  1. Max: each device takes the max over its local vocab slice → one AllReduce (max) of a single scalar per token. (Payload \(BT\), negligible.)
  2. Sum of exponentials: each device sums \(e^{z - z_\max}\) over its slice → one AllReduce (sum) of one scalar per token.
  3. The numerator \(e^{z_y - z_\max}\) for the true label \(y\) lives on whichever device owns that vocab row; the loss \(-\log p_y = z_\max + \log\!\sum e^{\cdot} - z_y\) is then a local computation.
Parallel cross-entropy
Two tiny scalar AllReduces per token instead of gathering the whole \(BTV\) logit tensor — comm drops from \(O(BTV)\) to \(O(BT)\).

8 · Worked example — one block at \(|X| = 8\)

Take a model with \(D = 8192\), \(F = 4D = 32768\), \(N = 64\) heads, \(H = 128\), trained at \(B = 4\), \(T = 8192\), bf16, on a tensor-parallel group of \(|X| = 8\) GPUs.

Each GPU stores \(1/8\) of every weight matrix and computes on \(1/8\) of the neurons / heads. The only data crossing the wire is the AllReduce of \(Y\): \(V = 2BTD = 2\cdot 4\cdot 8192\cdot 8192 \approx 537\) MB per block per direction. At an NVLink bandwidth of, say, \(W = 400\) GB/s, one AllReduce is roughly \(2V/W \approx 2.7\) ms — and there are two per layer per pass. That is the number that has to stay hidden under the matmul compute, and the number that explodes if the group spans two nodes.

9 · Summary

The split

Weights cut column-parallel (split output) then row-parallel (split contraction), chained so the middle split is never gathered.

MLP & attention

Each is one Case-1 matmul → local nonlinearity/attention → one Case-3 matmul → 1 AllReduce fwd, 1 bwd.

The bill

2 AllReduce fwd + 2 bwd per layer, payload \(2BTD\) bytes — scales with activations, on the critical path.

The cap

AllReduce is exposed and frequent ⇒ needs NVLink ⇒ keep \(|X|\le 8\) (one node). Scale out with other axes.

Vocabulary

Embedding split on \(V\); parallel cross-entropy reduces two scalars/token instead of gathering \(BTV\) logits.

In one line

TP shards the operators so big matmuls stay local and the only bill is a small, NVLink-speed AllReduce per block.
